# MicroCleaningVision 文档总导航

文档只按“谁来读、什么时候读”分类。新成员不需要在 `architecture / research / future_hardware` 之间猜入口。

## 1. 六个清晰入口

```text
docs/
├── README.md                 # 你正在看的总导航
├── 成员A/                   # 数据、U500、标注、模型路线
├── 成员B/                   # 视觉识别、Mask、面积和中心
├── 成员C/                   # 路径、动作申请、控制仿真和电脑端协议
├── 硬件组/                  # 接线、STM32协议、联调和固件上传
├── 总流程说明/              # 所有人共同理解的架构、分工、环境和Git
└── 未来计划/                # 真实实验、长期路线、Episode和失败复盘
```

这六个入口之外不再维护第二套文档分类。

## 2. 第一次进入项目，按这个顺序读

1. [项目共同上下文](../AGENTS.md)：项目目标和不能混淆的证据边界。
2. [当前事实](../project_state.yaml)：什么已经运行，什么仍未验证。
3. [团队总流程与输入输出](总流程说明/团队总流程与输入输出.md)：A、B、C、硬件组怎样接力。
4. [系统架构说明](总流程说明/系统架构说明.md)：为什么代码这样分。
5. 打开自己的入口：成员 A、B、C 或硬件组。
6. [团队任务看板](总流程说明/团队任务看板.md)：本轮实际要做什么。

## 3. 按角色进入

### 成员 A：数据与模型

- [长期任务手册](成员A/成员A_数据与模型任务手册.md)
- [工作流程与命令百科](成员A/成员A_工作流程与命令百科.md)
- [U500 USB 数码显微镜接入指南](成员A/U500_USB数码显微镜接入指南.md)

输入：U500/手机/来源明确的图片和采集事实。

输出：原图、metadata、人工 Mask、质量报告和对 B 算法的评价。

### 成员 B：视觉识别与测量

- [长期任务手册](成员B/成员B_视觉识别与测量任务手册.md)
- [工作流程与命令百科](成员B/成员B_工作流程与命令百科.md)

输入：A 的图片和人工 Mask。

输出：算法 Mask、面积、中心、置信度和失败样本。

### 成员 C：目标规划与控制仿真

- [长期任务手册](成员C/成员C_目标规划与控制仿真任务手册.md)
- [工作流程与命令百科](成员C/成员C_工作流程与命令百科.md)

输入：B 的算法 Mask、面积和中心。

输出：像素路线、ActionRequest、FakeSerial 回执，以及未来交给 STM32 的结构化消息。

### 硬件组：NUCLEO、接线和机械

从 [硬件组说明](硬件组/README.md) 开始，只需继续阅读：

- [NUCLEO-F401RE 接线与待确认信息](硬件组/NUCLEO-F401RE接线与待确认信息.md)

## 6. 文档可信度

- `project_state.yaml`：当前事实；
- `总流程说明/团队任务看板.md`：当前行动；
- `未来计划/长期分阶段研发规划.md`：满足条件后才开始的路线；
- `硬件组/STM32最小串口协议_v0.1.md`：双方共同维护的接口；
- 文件存在、测试通过、模拟成功都不自动等于实机完成。
