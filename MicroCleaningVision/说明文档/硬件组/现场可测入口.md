## 2. 实物单入口的参数模板

填入实际设备和标定文件后，用同一命令、同一进程：

只移动步进、不喷水。路径占位用 `firmware/path_placeholders.json`，喷头偏移仍只来自 nozzle-offset，占位里的 `nozzle_offset_mm` 是 0。确认词不区分大小写。旧 `demo.demo_pipeline --live` 不发送步进。

```text
python -m demo.closed_loop_station --real --camera-index 1 --camera-backend 1400 --serial-port COM8 --stage2-calibration firmware/mm_per_px.json --path-placeholders firmware/path_placeholders.json --nozzle-offset firmware/gate5_scope_nozzle_offset.json --arm-stage2-xy --max-cycles 1
```

要连短喷和复检一起走，再加 `--arm-pump --confirm-pump`。两个喷水参数必须同时有或同时没有。短喷默认 500 ms，主机许可 100–500 ms。第一次画面标注几块污渍，就处理几块；`--max-cycles` 只是上限，不会为了凑轮数把同一块再洗一遍。确认、空格抓图和显微镜画面在同一个窗口，不用回到 Cursor 终端。人要在旁边，杯子里有没有水要自己看。ACK、DONE 和步数都不是清洗有效。

```text
python -m demo.closed_loop_station --real --camera-index 1 --camera-backend 1400 --serial-port COM8 --stage2-calibration firmware/mm_per_px.json --path-placeholders firmware/path_placeholders.json --nozzle-offset firmware/gate5_scope_nozzle_offset.json --arm-stage2-xy --arm-pump --confirm-pump
```

缺 COM/相机索引/三个配置文件时直接拒绝启动，不扫描设备、不退回 Mock。`--confirm-pump` 只是启用确认流程，不能代替这个窗口里的确认。

过程：先打开同一个窗口，左边是实时显微镜 → 人确认当前位置与位置账本相符（未知或 `--stage2-set-zero` 时先人工对位记零）→ **空格冻结前图** → 窗口写出目标、去程、偏移、回程，并保留第一次画面的标注。没有喷水武装时，一次确认只批准去程和回程，不喷水，也不复检。

同时有 `--arm-pump --confirm-pump` 时，每一次转换单独停在这个窗口：

1. 确认只开始去程，不喷水。
2. 步进过程中，窗口正中黄色十字是显微镜中心；右下角小图 S 是显微镜观察位，N 是这一块的针头目标，圆点是当前台面计数。针头在视野外，不画在样品画面中间。右边保留第一次画面的标注。
3. 去程结束后，人确认污渍和针头中心重合，再确认才喷默认 500 ms，许可范围 100–500 ms。不确认就不喷水。
4. 确认才回到原观察位。回到后，再确认才抓后图。在这个窗口按空格之后，还要确认前后图是同一视野，窗口才给出匹配、残留、去除率和规则结论。0.80 不是已验收洁净标准。
5. 清洗顺序就是第一次画面的编号：S0001，然后 S0002，再往后。不按离画面中心的远近重排。规则认为这一块可以结束时，再确认才把它记完成并开始下一块。复检对不上、或原因是 PRE_POST_NOT_COMPARABLE 时，确认也会结束这一块并按编号继续下一块，并写明这一块没有被规则记成洗净；不确认才停止。还有下一块、而且轮数没用完时，窗口写“第一个污渍已清洗完成，现在进行第二个”。规则认为还有残留时，确认只是再试这一块。后面新分出来的区域不新开清洗。

Q 取消抓图。图像质量提示不中断规划。画面刷新失败不中断已经开始的步进。

运动 ALLOW 前不开 COM。喷水令牌在重合确认之后才签发；回程令牌过期则不喷。移动失败、计数不足、泵失败或回程失败均停止任务；不自动恢复。

## 3. H2 要提供的有符号偏移接口

载物台/样品移动；显微镜和喷头固定。`scope_to_nozzle_delta_steps=[dx,dy]` 的意义是：**样品已在显微镜中心时，载物台再走多少有符号步，能把同一位置送到喷头中心**。正负是电机/载物台坐标，不是直接抄图像 x/y。

未标定模板如下，程序会拒绝用于实物；unknown 不填 0：

```json
{
  "version": "scope-nozzle-v1",
  "setup_id": "填写实际装配编号",
  "coordinate_frame": "stage2_signed_steps_scope_to_nozzle",
  "scope_to_nozzle_delta_steps": null,
  "axes_confirmed": false,
  "calibration_source": null,
  "uncertainty_steps": null,
  "motor_calibration_sha256": null,
  "mock_only": false
}
```

实测后：步数填整数二元数组；axes_confirmed 为 true；calibration_source 指实测记录；uncertainty_steps 填非负二元数组并说明测法；motor_calibration_sha256 绑定此次实际加载的电机标定文件。只有实测共轴才能写 `[0,0]`。Mock 的偏移和零不确定性是替身声明，不能用于实物。

工作坐标 JSON 的 `work` 配置需确认旋转/轴翻转；标定的正尺度不自动证明方向正确。因移动样品会使图像特征反向移动，先实测两轴正向脉冲对应的像素位移，再让工作坐标变换与此一致，不盲目把像素误差直接当正向电机步数。V1 不支持 homography。旧 `nozzle_px` 或非零 `nozzle_offset_mm` 与新接口冲突时拒绝，防止加两次偏移。

记第一帧观察位 `q_obs`，本轮目标位移 `d_target`，偏移 `d_offset`：

```text
q_exec = q_obs + d_target + d_offset
RETURN = -(d_target + d_offset)
```

例如 `d_target=(120,-40)`、`d_offset=(200,80)`，执行位为 `q_obs+(320,40)`，回程为 `(-320,-40)`。只退 `(-200,-80)` 仍然换了视野，不能拿整图污渍编号当作原目标。

## 4. 现在仍然不能直接上机的条件

| 负责人 | 输入/操作 | 必须交付的证据 |
|---|---|---|
| H2 + C | 逐轴小范围正反位移、人工参考点、同次装配偏移 | 标定 JSON + 上述偏移 JSON、方向/误差记录、回程误差；全程留在人工零点 ±10000 步内 |
| H1 + H2 | 同一块 F103、联合固件、PB0/PB2/PB3 实际接线 | 构建/烧录身份、两协议原文、停止/急停与短喷起止记录；STATUS 不是电气联锁验收 |
| A + B | 固定倍率、夹具、光照、同一视野的前后图 | 原图/条件/质量、人工可比性与污渍标注、复检失败说明；0.80 是现有规则阈值，损伤未自动检测 |
| C | 配置准备齐后一次受限新入口运行 | 完整运行目录、串口收发、执行/回程回执与 Episode；禁止把不同固件、不同任务的记录拼成一次成功 |

主机不再另设单次步数上限。位置账本记住当前步数，人工零点两侧各 10000 步。这一步会越出边界时，窗口和终端用中文写明当前位置、两边剩余和超出多少，然后拦住。固件一条报文最多 20000 步。V1 只执行 CENTER_POINT，RASTER_SCAN 交 HUMAN。

## 5. 怎样查本轮到底做了什么

`output/closed_loop/station_*/`：run_config.json 锁定分割参数/哈希及标定引用；progress.json、summary.json 记路由/目标/累计步数/位置；serial.json 留原文收发；失败有 failure.json。

每轮 cycle_*/ 有 pre/post.png 及质量元数据、掩膜、selected_target_mask.png、sequence.json、path_preview.json、path_overlay.png、geometry.json、cycle.json、execution.json、verification.json 和 episodes/。尚未到达某阶段时对应文件可以缺失，不能补造。S0001 是任务稳定编号，T1 是当帧连通块；重编号不重置重试次数。

READXY 已发脉冲只证明固件计数，不证明台面无丢步；MCV1 DONE 只证明输出流程结束，不证明喷液到点。新入口先保存真实回执，后图中断也会留下失败 Episode。
