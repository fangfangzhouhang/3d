# MicroCleaningVision 长期分阶段研发规划

## 1. 先理解这份规划是什么

它不是“第几周一定上 YOLO、双目和 3D”的功能日历，而是一套证据关卡。只有上一阶段的出口证据真实存在，下一阶段才开始。

长期目标是积累机器处理微观表面的能力：

```text
观察 → 测量 → 判断 → 受限动作 → 执行回执 → 复检 → 记录 → 从失败中改进
```

当前第一场景是 PLA 表面彩色水溶性模拟污染；手机只用于验证文件链路，USB 显微镜才是当前计划中的主要成像设备。

## 2. 证据等级

| 等级 | 可以说什么 | 最低证据 |
|---|---|---|
| E0 | 设计或代码框架存在 | 文档、接口、未验证实现 |
| E1 | 单个软件或硬件组件可重复 | 明确输入、输出、测试或真实组件记录 |
| E2 | 多个真实模块正确交接 | 真实数据穿过两个以上模块，失败能被处理 |
| E3 | 真实最小闭环存在 | 真实观测、批准动作、真实回执、动作后复检和 Episode |
| E4 | 形成可研究结论 | 重复实验、对照组、误差和局限分析 |

软件组件可以到E1/E2，而整体硬件仍保持E0。两个等级不能混写。

## 3. 阶段总览

| 阶段 | 要回答的问题 | 主要成果 |
|---|---|---|
| P0 当前事实与共同接口 | 大家是否在做同一个项目 | 三模块目录、接口、测试、共同文档 |
| P1 真实数据与简单视觉 | 真实像素能否稳定变成污染测量 | USB图像、标注、HSV基线、失败样本 |
| P2 软件回放闭环 | 前后图、状态、动作和回执能否完整连接 | 真实图片回放 Episode |
| P3 定位与控制仿真 | 污渍位置能否变成可信目标和路线 | 标定工具、目标规划、FakeSTM32 |
| P4 真实最小硬件闭环 | 一次受限动作能否真实执行并复检 | E3硬件回合，必须经过人工关卡 |
| P5 证据驱动模型升级 | 简单方法在哪些稳定失败上需要学习模型 | HSV与模型A/B、独立测试集 |
| P6 自适应研究系统 | 状态和动作能否预测结果 | State–Action–Outcome 数据和简单预测 |
| P7 平台化 | 同一能力能否迁移到另一材料或任务 | 跨材料/设备复现实验 |

## 4. P0：当前事实、目录和接口统一

### 目的

消除“文件很多但没人知道谁负责”的问题，让三名新手能够在不修改同一文件的情况下并行工作。

### A并行任务

- 运行真实图片检查工具；
- 准备USB显微镜拍摄条件；
- 学会数据编号和小规模标注。

### B并行任务

- 用合成色块读懂污染测量接口；
- 明确面积、中心、mask和置信度；
- 不等待A就能编写算法测试。

### C并行任务

- 用合成黑白区域理解目标点和动作申请；
- 运行FakeSerial成功、超时和拒绝测试；
- 不等待B就能准备控制仿真测试输入。

### 集成任务

三个人互相运行一次相邻模块测试，并能画出 `A → B → C` 数据流。

### 出口标准

- 三个顶层业务模块和镜像测试目录清晰；
- 全部当前回归测试通过；
- 每个人有核心、扩展、备用任务；
- 目录迁移不被描述为新算法或硬件证据。

## 5. P1：建立最小真实图像数据与 HSV 基线

### 要解决的问题

当前最大失败不是模型不够高级，而是没有真实USB显微镜图片进入识别算法。

### A的独立任务

1. 固定样本、倍率、距离、光照和方向。
2. 分至少三个采集批次保存图片，不能只拍连续帧。
3. 建立图片清单，记录设备、样本、批次、前后阶段和质量状态。
4. 标注第一批15～20张图片。
5. 保存失败图：失焦、反光、阴影、过曝也属于数据资产。

### B的独立任务

1. 用合成色块实现HSV分割测试。
2. 输出mask、面积、中心和可视化边界。
3. 实现无污渍、单污渍、多污渍和噪点测试。
4. 拿到A数据后只调整显式参数，不为单张图无限调参。
5. 与人工标注比较，记录假阳性和假阴性。

### C的独立任务

1. 用合成mask选择处理目标点。
2. 在图片坐标中生成目标点顺序和路线图。
3. 明确当前只是像素坐标，禁止伪造毫米比例。
4. 为无目标、多个目标和越界输入编写测试。

### 集成任务

```text
A真实图片和标注 → B分割与测量 → C像素级目标预览
```

### 出口证据

- 至少一个固定USB显微镜采集协议；
- 至少30张链路数据，来自多个采集批次；
- 至少15张人工参考标注；
- HSV基线在独立样本上的量化结果和失败清单；
- C能在B输出上画目标点，但不发送真实动作。

### 停止条件

如果标记物会永久染色、扩散或破坏PLA，先更换实验载体；不要用算法掩盖工艺失败。

## 6. P2：真实图片的软件回放闭环

### 要解决的问题

证明真实动作前后图片能够穿过完整软件链，而不是证明真实清洗已经完成。

### A任务

- 采集可对应的前后图片；
- 保持视角、倍率和光照可比较；
- 记录图片哈希和采集条件。

当前没有清洗硬件时，可以用人工擦除制作“软件回放对”，但必须标记为 `manual_change`，不能写成自动清洗结果。

### B任务

- 实现最小前后图配准；
- 分别测量前后污染面积；
- 图片不可比时返回人工处理，而不是计算虚假去除率。

### C任务

- 把测量结果转为结构化动作申请；
- 让FakeSerial返回成功、失败或超时；
- 保存完整Episode；
- 证明缺失后图或回执时不会宣布成功。

### 出口证据

- 至少5组真实像素前后图完成软件回放；
- 成功和失败路径都留下Episode；
- 软件多模块达到E2；整体硬件仍为E0。

## 7. P3：像素定位、标定和控制仿真

### 要解决的问题

把“图上第300列”转换成“工作台应到达的位置”，并明确误差。

### A任务

- 拍摄标定板或毫米刻度参考图；
- 固定相机与样本相对位置；
- 记录重新安装后的漂移。

### B任务

- 输出污染中心的像素误差；
- 检查分割误差怎样传播到目标位置；
- 提供难定位样本。

### C任务

- 实现像素到工作坐标的标定工具；
- 生成多个目标点和移动顺序；
- 在二维仿真中显示喷头路线；
- 实现FakeSTM32命令编码、ACK、超时和错误码；
- 真实协议未知时只使用明确标记的模拟协议。

### 出口证据

- 独立验证点上的坐标误差报告；
- 相机重新安装后的标定失效规则；
- 合成和真实mask都能生成有界路线；
- FakeSTM32合同测试通过；仍不打开真实COM口。

## 8. P4：真实最小硬件闭环

这一阶段依赖机械、STM32固件和实验安全信息，不由当前视觉三人组单方面宣布开始。

### 入口关卡

- 真实固件协议、单位、ACK和停止命令已确认；
- 工作空间、限位、急停和联锁有真实证据；
- 标定有效；
- 样本和液体风险已经人工批准；
- 第一次动作使用固定低风险参数并有人在场。

### 三人贡献

- A：真实动作前后采集和成像稳定性；
- B：目标测量和动作后复检；
- C：受限串口适配器、动作回执和软件状态机。

### 出口证据

至少一次真实受限动作完成：前图、状态、批准、真实回执、后图、复检和Episode。一次成功只能说明E3演示存在，不能说明稳定。

## 9. P5：证据驱动的模型升级

### 什么时候允许训练模型

必须同时满足：

1. HSV在固定条件下出现稳定、可复现失败；
2. 有人工标注和按样本/批次隔离的独立测试集；
3. 能说清模型要解决哪一种失败；
4. 本地CPU先跑通数据加载和最小训练；
5. 预先定义与HSV的A/B指标和停止条件。

### A任务

- 管理数据版本、划分、训练配置和AutoDL实验；
- 固定代码提交、依赖、随机种子和预算；
- 保存模型及模型卡。

### B任务

- 定义视觉指标和任务指标；
- 比较HSV与模型在独立测试集上的错误；
- 把模型输出转换成相同测量接口。

### C任务

- 测模型推理延迟和失败处理；
- 证明替换识别方法不会绕过动作边界；
- 在同一回放集上比较端到端结果。

### 删除条件

如果模型没有在预登记失败上显著改善，或复杂度、延迟和维护成本超过收益，就保留HSV为主线，模型退回实验分支。

## 10. P6：State–Action–Outcome 与简单适应

只有积累足够真实Episode后，才研究：

```text
当前状态 + 采取的动作 + 环境条件 → 下一状态/处理结果
```

先从表格统计、线性模型或树模型开始，不直接上世界模型或强化学习。研究问题可以是：不同污染面积下，哪一档固定动作更可能达到目标且不损伤表面。

出口标准是独立测试中的结果预测或参数选择优于固定规则，并包含失败和局限分析。

## 11. P7：平台化与高级视觉

只有一个场景E4后，才考虑迁移到另一材料、污染、执行器或视角。双视角、3D、Transformer、PINN和World Model都只是候选假设：

- 第二视角只在遮挡或几何误差成为主要失败时实验；
- 3D只在高度变化确实影响定位或处理时实验；
- Transformer只在时序或多模态关系确实需要长程建模时实验；
- PINN只在可靠物理方程能约束数据不足的预测问题时实验；
- World Model只在真实State–Action–Outcome数据足够后研究。

## 12. 每轮都使用的任务结构

每个人都有：

- 核心任务：产生本轮最小可验收成果；
- 扩展任务：核心完成后继续；
- 备用任务：上游未到位时独立推进；
- 集成任务：使用一次真实上游输出；
- 退出证据：文件、测试、图片、标注、运行结果或实验记录。

不再提前锁死工时。每项完成后记录实际专注时段，两轮后再校准任务大小。
