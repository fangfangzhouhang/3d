## 1. 这个项目在干什么

MicroCleaningVision 是大创：让机器在显微镜下看见微观表面的污渍，量出位置和面积，再做**受限动作**（现在是人确认后的定点短喷），以后还要复检有没有变干净。

整条链：

```text
A 图片/数据
→ B 污渍 Mask、面积、中心
→ C 目标点、像素路线、动作申请
→ Safety Governor → Human Gate
→ FakeSerial 或 STM32（默认不发泵）
→ 喷后视觉复检（真后图仍缺）
→ Episode 记录
```

三人分工：A 数据与标注；B 识别与测量；C 路径与串口协议。正式板是 NUCLEO-F401RE。同学机已报 STM32F103 短喷，证据未入库。看见污渍**不会**自动喷。

识别只是其中一环。识别变好 ≠ 清洗有效 ≠ 对准污渍中心。没有标定就没有毫米坐标，没有 XY 就不能跟着路径喷。

当前第一场景：PLA 试片 + 水溶性彩色模拟污染 + **U500 USB 显微镜**固定俯视。

## 2. 污渍识别算法现在是什么

### 2.1 一句话

现在跑在真链路上的，是 **OpenCV 邻域差异 `local`（版本 `local-contrast-v0.1`）**，不是神经网络。仓库里的「训练入口」也只是**自动调这几个阈值**，不是深度学习。

### 2.2 电脑现在怎么找污渍

默认算法大白话：

1. 把彩图转到 Lab（亮度和颜色拆开）。
2. 每个像素看「它和周围一圈差多少」。
3. 差得够大的涂白（候选污渍），再用 Otsu 切一刀。
4. 丢掉碎点、细长条（像电路铜线）、以及几乎整张图那么大的块。
5. 留下的白块算面积和中心，交给 C 画路线。

污渍**不规定必须是红色**。这就是为什么 HSV（按高饱和红抠）已经不当主算法。

对照算法还在，只用来比，不进默认 Demo：

| 名字 | 假设 | 现在的角色 |
|---|---|---|
| `local` | 污渍和旁边不一样 | **主算法**，Demo / `run_baseline` 默认 |
| `otsu` | 污渍比背景暗 | 对照 |
| `hsv` | 高饱和红色标记物 | 失败对照；`public_001` IoU=0.0739，已证明不够 |
| `exg` / `exr` | 绿/红色指数 | 可选对照，不接硬件 |

代码：

```text
microcleaning/vision/local_contrast_baseline.py   # 主算法
microcleaning/vision/run_baseline.py              # B 自己跑 Mask
microcleaning/vision/hsv_baseline.py
microcleaning/vision/otsu_baseline.py
demo/demo_pipeline.py                             # 默认 local；实时窗 O=Otsu，H=HSV
```

`LocalContrastPolicy` 代码内默认（不要默默改这些数，改了要升版本号）：

```text
min_residual = 8.0              # 和周围差多少才算污渍
min_component_area_px = 20      # 太小的点丢掉
max_aspect_ratio = 6.0          # 太细长的条丢掉
max_area_ratio = 0.20           # 单块不能占画面太大
blur_kernel_px = 0              # 0 = 按图自适应
lightness_weight = 0.55
color_weight = 1.0
morphology_kernel_px = 3
```

调参结果若要生效，写 `data/models/local_contrast_policy.json`，不直接改 Python 默认。`--no-tuned-policy` 回到 v0.1。当前**没有**把调参结果写成全局生效文件。

### 2.3 输出长什么样

B 交给后面的只有像素结果，单位 `image_px`：

```text
mask.png                    白=污渍，黑=背景
contamination_overlay.png   叠加图，给人看
area_px / centroid_px / component_count / confidence
algorithm_version
```

不输出毫米、不写串口、不发泵。C 用 Mask 做像素路线预览；真喷仍是原地 `PUMP_IN_PLACE`。

## 4. 我们现在的想法（最后确认）

负责人最新方向（2026-09-16 晚）：

> **之后的计划是：先凑够足够大、条件固定、带人工 Mask 的数据集，再训练污渍算法。**

和仓库里一直写的顺序合在一起，完整想法是：

```text
1. 最小闭环已经在同学机发生：看见 → 人确认 → 短喷
2. 识别还没有尺子：13 张网图不能当过关，OpenCV 在这批图上卡在 ~0.44
3. 下一阶段的真正工作是数据，不是再拧旧图旋钮，也不是先买 XY / GPU
4. 数据必须是自己工位上的 U500 实拍（固定支架、倍率、灯、标记物）
5. 数据够了之后，再用学习方法训练分割模型，替换或补强现在的 local
6. 新模型必须输出同一套东西：Mask + 面积 + 中心，仍不发泵
```

「足够大」在作战总表里的最低讨论门槛（讨论学习模型之前）是：

- 成像条件锁死，写进 metadata
- 大约 **≥50 张原图、≥30 张 labeled**，来自 **至少 2 个采集批次**
- 开发 / 留出按批次切，不要按「哪张分好看」切
- 干净表面负样本大约 **10%**
- 最好先让 OpenCV 在新留出上暴露**稳定失败类型**（漏检、反光、铜线、整图涂白……），再决定模型要解决哪一种失败

这 50/30 是「允许开始讨论训练」的下限，不是「明天就能发表」的规模。用户说的「足够大」是这个方向：先把数据集立住，再训；不是用现有 13 张开训。

若做模型，项目里已否决和已倾向：

| 做 | 不做 |
|---|---|
| 语义分割（每个像素污渍/背景），输出二值 Mask | AGPL YOLO、框检测当分割、`legacy` 回流 |
| 和 `local` 在同一套 U500 留出上 A/B | 用网图或开发集宣布过关 |
| 失败了能退回 OpenCV | 看见污渍就喷、视觉写串口 |
| 本地先跑通数据加载和最小训练 | 无标注就上 AutoDL、无失败类型就上 Transformer |

创新点我们对外讲的是：**带证据的微观表面处理闭环**，不是模型名词。没有本机数据就训练，老师一问相机/倍率/批次会穿帮。
