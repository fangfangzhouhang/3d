## 2. 实物单入口的参数模板（未执行）

填入实际设备和标定文件后，用同一命令、同一进程：

```text
python -m demo.closed_loop_station --real --camera-index <设备索引> --serial-port <人确认的COM> --stage2-calibration <电机标定JSON> --path-placeholders <工作坐标JSON> --nozzle-offset <偏移JSON> --arm-stage2-xy --arm-pump --confirm-pump --max-cycles 1
```

首次实物验收只做一轮，默认不重试。缺 COM/相机索引/三个配置文件时直接拒绝启动，不扫描设备、不退回 Mock。`--confirm-pump` 只是启用确认流程，不能代替终端 YES。

过程：人确认当前位置与位置账本相符（未知或 `--stage2-set-zero` 时先人工对位记零）→ 开同一相机预览 → **空格冻结前图，仅分析** → 打印目标、去程、偏移、短喷、回程和预算 → **大写 YES 批准本轮** → 去程完成且计数足够 → 100–300 ms 定点短喷 → 回原观察位 → 同一相机空格冻结新后图 → 人核对前后可比并输入 YES → 单目标复检。Q 取消。继续下一块或重试时再次抓新前图、规划和确认，不重放上一条命令。

运动 ALLOW 前不开 COM；随后同会话 PING/STATUS 取得泵联锁事实，再评估泵审批。一次 YES 只绑定本轮确定的去程、短喷和回程，各自令牌独立且有有效期。移动失败、计数不足、审批过期、泵失败或回程失败均停止任务；不自动恢复。

## 3. H2 要提供的有符号偏移接口

载物台/样品移动；显微镜和喷头固定。`scope_to_nozzle_delta_steps=[dx,dy]` 的意义是：**样品已在显微镜中心时，载物台再走多少有符号步，能把同一位置送到喷头中心**。正负是电机/载物台坐标，不是直接抄图像 x/y。

未标定模板如下，程序会拒绝用于实物；unknown 不填 0：

```json
{
  "version": "scope-nozzle-v1",
  "setup_id": "填写实际装配编号",
  "coordinate_frame": "stage2_signed_steps_scope_to_nozzle",
  "scope_to_nozzle_delta_steps": null,
  "axes_confirmed": false,
  "calibration_source": null,
  "uncertainty_steps": null,
  "motor_calibration_sha256": null,
  "mock_only": false
}
```

实测后：步数填整数二元数组；axes_confirmed 为 true；calibration_source 指实测记录；uncertainty_steps 填非负二元数组并说明测法；motor_calibration_sha256 绑定此次实际加载的电机标定文件。只有实测共轴才能写 `[0,0]`。Mock 的偏移和零不确定性是替身声明，不能用于实物。

工作坐标 JSON 的 `work` 配置需确认旋转/轴翻转；标定的正尺度不自动证明方向正确。因移动样品会使图像特征反向移动，先实测两轴正向脉冲对应的像素位移，再让工作坐标变换与此一致，不盲目把像素误差直接当正向电机步数。V1 不支持 homography。旧 `nozzle_px` 或非零 `nozzle_offset_mm` 与新接口冲突时拒绝，防止加两次偏移。

记第一帧观察位 `q_obs`，本轮目标位移 `d_target`，偏移 `d_offset`：

```text
q_exec = q_obs + d_target + d_offset
RETURN = -(d_target + d_offset)
```

例如 `d_target=(120,-40)`、`d_offset=(200,80)`，执行位为 `q_obs+(320,40)`，回程为 `(-320,-40)`。只退 `(-200,-80)` 仍然换了视野，不能拿整图污渍编号当作原目标。

## 5. 怎样查本轮到底做了什么

`output/closed_loop/station_*/`：run_config.json 锁定分割参数/哈希及标定引用；progress.json、summary.json 记路由/目标/累计步数/位置；serial.json 留原文收发；失败有 failure.json。

每轮 cycle_*/ 有 pre/post.png 及质量元数据、掩膜、selected_target_mask.png、sequence.json、path_preview.json、path_overlay.png、geometry.json、cycle.json、execution.json、verification.json 和 episodes/。尚未到达某阶段时对应文件可以缺失，不能补造。S0001 是任务稳定编号，T1 是当帧连通块；重编号不重置重试次数。

READXY 已发脉冲只证明固件计数，不证明台面无丢步；MCV1 DONE 只证明输出流程结束，不证明喷液到点。新入口先保存真实回执，后图中断也会留下失败 Episode。

| 旧入口 | 范围 |

| `demo.demo_pipeline --from-camera --live --mode analyze --camera-index <N>` | 空格单帧分析，默认无动作；live 不能加 stage2-xy |
