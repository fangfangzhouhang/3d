# 实验数据与回合（Episode）规范 v0

## 别把数据理解成“存几张图片”

一张图片只能告诉我们“当时看到了什么”；研究平台真正需要记住的是：**当时相信什么、申请了什么动作、设备实际做了什么、之后发生了什么。** 这才是未来做参数预测、适应性选择和 Robot Memory 的可靠地基。

## 原则

科学价值的单位不是 `image -> label`；而是一条不可变、相互链接的链：

```text
State_t -> Action_t -> actual ExecutionReceipt_t -> Outcome_t+1
```

`microcleaning/contracts.py` 是可执行的 v0 模式。`write_episode()` 写入 JSON 并附 SHA-256 旁车文件；这对模拟契约证据已足够，但尚未成为完整的真实数据存档。

## 真实闭环前必须留下的字段

| 实体 | 必需字段 |
|---|---|
| Task/Episode | task ID、sample ID、操作员、协议版本、UTC 时间、硬件/软件/控制器/模型/标定版本 |
| Raw artifact | 不可变相对路径或对象 ID、SHA-256、采集设置、源设备 |
| Observation | image/frame ID、原始制品引用、对焦/照度评分、质量标志、图像/模型版本 |
| State | target/mask/area/centroid、`work_mm`、单位、不确定性、设备状态、标定有效性/版本、先前动作 |
| ActionRequest | action/state ID、原语白名单、target/frame、剂量/参数、策略/规则版本、预期效果 |
| SafetyDecision | 结果、原因、策略版本、签发/过期、请求摘要、决策令牌 ID |
| Receipt | 实际 target/dose/时间、控制器/联锁状态、ACK/测量引用、错误码 |
| Verification | 动作前/后制品 ID、配准结果、残留/移除、损伤评估、路径/原因 |
| FailureRecord | 阶段、症状、疑似原因、严重度、恢复、可复现性、关联证据 |

## 真实证据怎样放（硬件数据开始时再创建）

```text
evidence/
  episodes/<episode_id>.json + .sha256
  raw/<image_id>.<format>
  derived/<mask_or_metric_id>.<format>
  calibration/<calibration_id>/
  manifests/<protocol_version>.json
```

原始和派生制品不得被覆盖。运行滚动日志不是科学存档。当前遗留 logger 的行为不得成为实验的唯一记录。

## 数据不合格时怎么办

不要删除“脏数据”。把它标为不能进入结果统计，同时保留原件与失败原因；否则以后无法知道系统是在变好，还是只是把失败样本藏起来了。

将一个回合从结果分析中拒绝，但保留其记录，条件是：ID/版本/单位缺失；动作前/后图像未配准；质量低于阈值；回执状态未知；标定已过期；或需要人工标注但缺失。该拒绝本身成为一个 `FailureRecord`。
