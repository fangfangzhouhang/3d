## 1. 怎么升级识别算法

### 1.1 现状

Demo 与 `run_baseline` 默认是邻域差异 `local`（`local-contrast-v0.1`）：Lab 里看一块和周围差多少，再丢掉细长块。对照：`otsu`、`exg`、`exr`；`hsv` 只作红色标记物失败对照（`public_001` IoU=0.0739）。

升级对象必须是 **U500 固定条件下的实拍**，不是 `data/raw_images/public/` 那 13 张来源 unknown 的图。冻结留出 `public_002` / `public_011` / `M9` / `M12` **不准改**。

### 1.2 升级顺序（先数据，后参数，最后才谈模型）

```text
锁死成像
→ U500 批次实拍 + metadata
→ 新开发/留出（按批次切，不碰旧留出）
→ 失败分类（漏检 / 反光 / 失焦 / 铜线 / 整图涂白）
→ 一次只改 LocalContrastPolicy 一个字段并升版本号
→ 同一套 U500 留出上看 local vs otsu
→ 连续两版达不到门槛才允许讨论分割模型
```

**第 0 步：成像 SOP（成员 A + 支架）**

固定并写入 metadata：工作距、倍率旋钮刻度、LED、曝光/增益（若可设）、样品材质、标记物配方。条件变了算新批次。对焦差的帧作废，不拿去调参。

**第 1 步：先 1 张，再两批次**

```powershell
cd "D:\大创\3d\MicroCleaningVision"
.\.venv\Scripts\python.exe scripts\probe_usb_camera.py
.\.venv\Scripts\python.exe scripts\probe_usb_camera.py --capture-test --device-index <显微镜编号>
.\.venv\Scripts\python.exe -m demo.demo_pipeline --input <该PNG> --mode analyze
```

probe 证据（index、分辨率、FPS、PNG、SHA-256、质量）进仓后，才能把 `physical_capture_verified` 改为 true。这与「同学机喷过水」不是同一件事。

**第 2 步：标注与切分**

- 只标 U500 新图；Polygon 转 `{0,255}` Mask。
- 开发 / 留出按**采集批次**切，不要按「哪张 IoU 好看」。
- 负样本（干净表面）至少约 10%，否则 local 容易整图涂白却没人发现。
- 旧 13 张继续当软件回归，不当 U500 过关集。

**第 3 步：失败分类（成员 B，调参前先记）**

每张开发图只贴一类主因：漏检、误检（反光/铜线/阴影）、中心偏、面积爆、失焦。没有稳定失败类型就不要改算法。

**第 4 步：OpenCV 调参规则**

| 允许 | 禁止 |
|---|---|
| 一次改 `LocalContrastPolicy` 一个字段 | 同时改一堆阈值「看起来更好」 |
| 升版本号，例如 `local-contrast-v0.2` | 默默覆盖 v0.1 使旧评价对不上 |
| 升降只看 **U500 留出** 的 IoU / P / R / FP / FN | 用开发图或单张 live 帧宣布过关 |
| Otsu 作对照 | 用未验收图上 Otsu IoU>0.6 当过关 |
| 保留 HSV 文件 | 删 HSV、引入 YOLO/`legacy` |

建议先动的字段（一次一个）：`min_component_area_px`（碎点）、`max_aspect_ratio`（铜线）、`min_residual`（弱污渍 vs 噪声）、`max_area_ratio`（整图涂白）。

评价命令（目录换成 U500 批次后同结构）：

```powershell
.\.venv\Scripts\python.exe -m microcleaning.vision.run_baseline --algorithm local --input-dir "data\raw_images\<u500批次>"
.\.venv\Scripts\python.exe -m microcleaning.vision.run_baseline --algorithm otsu --input-dir "data\raw_images\<u500批次>"
.\.venv\Scripts\python.exe scripts\evaluate_vision_baselines.py
```

看 `output/data_learning/evaluations/comparison_summary.json` 里的 `holdout_by_algorithm`，不要看混在一起的总分。

**第 5 步：什么时候可以停在 OpenCV**

作战总表第 8 节：U500 labeled 留出 n≥10、跨 2 批次，连续 2 个算法版本达到 mean IoU≥0.50、灾难率≤10%、P/R≥0.50、整图涂白 0 张。

**第 6 步：什么时候才允许谈训练**

必须同时：成像固定、≥50 张原图、≥30 张 labeled、2 批次切分、OpenCV 留出有**稳定失败类型**、调参后仍达不到第 5 步、负样本≥10%。缺一条继续 OpenCV。若做模型：语义分割，禁止 AGPL YOLO。

仓库里的 `train_entry` 目前只做 OpenCV 自动调参（开发集搜参、留出集闸门），**不是**第 6 步的语义分割训练。`--backend semantic-seg/torch/yolo` 会拒绝。

视觉模块始终不得 `serial.write`。看见污渍仍不自动喷。

## 2. 路径规划要加什么、现在缺什么

### 2.1 已经有的（像素预览）

[`cleaning_plan.py`](../../microcleaning/control_system/cleaning_plan.py)：

- 无污渍 → `NO_TARGET`（不申请泵，这是正确行为）
- 面积占比小 → 每块一个 `CENTER_POINT`
- 面积占比大 → mask 内 `RASTER_SCAN`（步长默认 16 px）
- 多连通块分段，段起点记在 `segment_start_indices`

Demo 把路线画在 `path_overlay.png`。`arm-pump` **不读** `path_px`，只发原地 `PUMP_IN_PLACE`。

### 2.2 功能升级分四档（后一档依赖前一档）

**档 0 — 把现有预览看懂（不接电机，可立刻做）**

- overlay：点编号、段与段之间用虚线/不画喷线，避免看起来像连续喷射。
- 记录：策略名、点数、是否 `NO_TARGET`。
- 验收：C 能指着一张 U500 图说出「先喷哪一块、为什么是中心点还是光栅」。

**档 1 — 喷斑约束下的像素步长（仍不驱动 XY）**

需要数据：试纸上一次 100–200 ms 定点喷的湿斑直径（像素 + 毫米尺或测微尺）。  
用湿斑直径改 `raster_step_px`，使点间距大约覆盖喷斑，而不是固定 16 px。  
验收：步长来自测量记录，不是拍脑袋；单位仍写 `image_px`。

**档 2 — 块间顺序（仍是像素）**

多污渍时用最近邻排块序（先于 TSP）。不引入 OMPL。  
验收：两块不相邻时，段间不喷；顺序可复述。

**档 3 — 毫米路径 / 对准喷射（必须先有尺度 + 喷头偏移）**

前置：第 3 节的测微尺 JSON、喷斑相对光学中心的偏移、托盘行程数字。  
才允许新契约讨论 `path_mm` 和单点 `SPRAY_AT_POINT`。无标定继续 DENY 毫米动作。  
MCV2 `HOME`/`MOVE`、步进脉冲当量是再后面；未 HOME 禁止 MOVE。

禁止：把 `path_px` 直接 `serial.write`；用 `simulate` 的虚拟 100×100 mm 冒充真机坐标。

## 3. 需要买什么、需要哪些数据

### 3.1 采购（缺则补；已有的不要再买一台）

已声明拥有、不要重复采购：U500、NUCLEO-F401RE、现有 12V 泵、现有 MOSFET 或继电器。F103 是走通板，不是再买一块替代 F401。

| 优先级 | 项 | 用途 | 依赖哪一步 |
|---|---|---|---|
| 必买（无则算法/尺度做不了） | 物镜测微尺 1 mm / 100 格（10 μm） | 离线 mm/px | 路径档 3、对准喷射 |
| 必买（无则成像不稳） | 刚性支架、常亮灯、PLA 试片、水溶标记 | U500 批次可复拍 | 算法第 0–1 步 |
| 必买（无则尺度/喷斑对不上） | 卡尺（若无） | 湿斑、工作距、托盘 | 路径档 1、行程 |
| 必买（安全，接 12V 前） | 万用表、泵支路保险、急停、续流管（模块没有才买）、废物盘 | 短喷可停、不干转 | 重复短喷、喷斑数据 |
| 先量再买 | 入门 XY + 限位 | MOVE | **托盘有效行程数字写下来之前不买** |
| 现在不要买 | 工业相机、本机 GPU、YOLO 权重、龙门、第二套 MCU、树莓派 | 无失败证据、无 MCV2 | — |

12V 电源：读泵铭牌，额定电流 ×1.5；不要反灌 MCU。

### 3.2 数据清单（没有这些不要升级下一档）

**识别（A/B）**

- U500 probe 包：可读设备、PNG、SHA-256、质量
- ≥2 个成像批次；目标往 50 张原图、30 张 labeled 走，但**第一张 analyze 通了再加**
- 开发集失败分类表
- 干净表面负样本
- 旧 13 张不动留出

**复检（闭环，代码未冻结前先手工也能做）**

- 同一次：喷前图、喷后图、样品未挪、对焦都过
- 对应 `summary.json` 的 ALLOW / 回执；失败回合也留

**路径 / 标定（C + 硬件）**

- 测微尺与样品同高的尺度图 → `scripts/measure_scale_mm_per_px.py`，JSON 里必须 `feeds_action_request=false`，留出段误差 ≤ max(5%, 0.05 mm)
- 定点喷湿斑：直径 px、直径 mm、时长、喷嘴是否在画面里
- 光学中心 vs 湿斑中心（喷头偏移）
- 托盘长宽、拟用行程、原点打算在哪一侧（没数字不买模组）

**硬件证据（同学机，拷回仓库，不改本机当官方固件）**

- 固件路径 `firmware/stm32f103/f103-stage1/` 的 git、人认 COM、camera-index
- `PING→PONG`、`STATUS ESTOP=0` 原文
- 一次成功 Episode 目录；对照：无目标不发泵、缺 `--confirm-pump`/`--arm-pump` 无 `MCV1|PUMP`
- 工位：12V、MOSFET、PB0、PB2、人在场

## 4. 具体怎么进行（建议四周内，一次一张卡）

不要并行「改算法 + 买 XY + 改固件」。成功代码入库前，本机只做数据和预览，不把 Demo 锁成实喷发行版。

### 第 1 周：证据拷回 + 成像锁死（全员 / A / 硬件）

1. 从同学机拷贝：成功 `output/demo/<run_id>/`、probe/ping 原文、所用命令（COM、camera-index）。放进约定目录，**不要**在没 diff 的情况下覆盖本仓 `demo/`。
2. 本机 U500：`probe_usb_camera.py` + `--capture-test`，固定支架。
3. 硬件：量托盘外廓；急停/保险事实填表。仍不买 XY。

验收：有一份别人能复跑的命令记录；本机有一张 U500 PNG + SHA。

### 第 2 周：算法只在 U500 上比（A 标，B 评）

1. 导入第 1 张 U500 → `analyze`（不发泵）。
2. 补同一条件下的开发图并标 Mask；另留一个未看过的小留出。
3. B 跑 local / otsu，只改一个 `LocalContrastPolicy` 字段。
4. 记下 3 类真实失败。达不到第 5 步门槛就继续补图，不开训练。

验收：`comparison_summary.json` 出现 **U500 留出** 分表，而不是只评 public。

### 第 3 周：路径预览可用 + 喷斑数据（C / 硬件）

1. 档 0：overlay 让人能读。
2. 在试纸上做 1–3 次 200 ms 定点喷（人在场、三道闸），量湿斑。
3. 有湿斑直径后再谈改 `raster_step_px`（档 1）。
4. 有测微尺则拍尺度图，写出 mm/px JSON，**不**写入 ActionRequest。

验收：一张图上能解释路线；一份湿斑记录；可选一份 `feeds_action_request=false` 的 JSON。

### 第 4 周及以后：才讨论对准和 XY

同时具备：U500 留出评价、mm/px、喷头偏移、托盘行程数字，才开 MCV2 / 步进采购讨论。  
复检软件（喷后自动收 `observation_post`）等成功代码合并后再做，避免在过期副本上改 Demo。
