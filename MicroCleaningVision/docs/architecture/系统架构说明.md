# 系统架构：视觉软件先闭环，硬件以后换适配器

## 核心数据流

```text
ReplayCamera / 未来真实相机
  → Observation
  → ContaminationMeasurement
  → StateEstimate
  → ActionRequest
  → SafetyDecision
  → FakeSerial / 未来 STM32 Adapter
  → ExecutionReceipt
  → VerificationResult
  → Episode
```

适配器（`Adapter`，把外部设备转换成统一接口）隔离硬件差异。A/B 的视觉代码不应该知道 COM 口或 STM32 型号；未来控制器也不应该接收原始图片。

## 模块和所有者

| 模块 | 输入 | 输出 | 所有者 |
|---|---|---|---|
| `perception/image_quality.py` | 图片引用和质量分数 | Observation | A |
| `adapters/replay_camera.py` | 回放图清单 | Observation | A |
| `perception/contamination.py` | 合格图片 | 污染测量 | B |
| `state/estimator.py` | Observation + 测量 | StateEstimate | B |
| `verification/area_change.py` | 前后观测与面积 | VerificationResult | B |
| `decision/fixed_rule.py` | StateEstimate | ActionRequest | C |
| `safety/governor.py` | 状态 + 动作申请 | SafetyDecision | C |
| `execution/fake_serial.py` | 已批准动作 | 模拟 ExecutionReceipt | C |
| `app/replay_mcl.py` | A/B/C 的上述对象 | Episode | C |

## 失效安全默认值

新状态默认标定无效、控制器未连接、联锁未闭合。必须显式提供回放条件才能获得 FakeSerial 的 ALLOW。这是 fail-safe（失效安全，缺少事实时宁可停止）的设计。

## 旧代码的位置

旧相机、检测、规划、通信等代码集中在 `legacy/`，供选择性迁移，但当前入口不导入它们。旧文档位于 `docs/archive/legacy_docs/`。迁移规则是：先写符合新合同的测试，再提取最小可用逻辑；不整体复制旧模块。

## 当前证据边界

通过的测试只证明对象能连接、安全拒绝生效、FakeSerial 能返回模拟回执。尚未证明真实图像质量、HSV 分割、配准、相机、STM32 或清洗。
