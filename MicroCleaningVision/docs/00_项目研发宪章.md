# 项目研发宪章：先做成一条真实闭环，再让它越来越聪明

这不是宣传页，而是团队在“想加一个看起来很厉害的功能”时拿来刹车的共同准则。任何人都可以提出新想法；但想法必须先说明它要解决哪一种已经出现、可复现的失败。

## 不可协商的使命

构建一个能力逐步增强的**微表面智能平台**，从一个真实、安全、可重复的清洁闭环开始。首个场景是 3D 打印后处理；它是一项能力的证据，而非对每种微观表面都可处理的声明。

## 工作顺序

```text
真实问题 → 可被推翻的假设 → 最简单的基线 → 实验
      → 证据 / 失败分析 → 有理由时才增加复杂度
```

不会仅仅因为流行就让 YOLO、3D、第二视图、Transformer、PINN、agent 或世界模型进入主路径。

## 必须守住的控制边界

```text
Observation -> StateEstimate -> ActionRequest -> SafetyDecision
                                      |                  |
                               proposal only       ALLOW/DENY/HUMAN
                                                         |
                                              deterministic controller
                                                         |
                                              ExecutionReceipt -> Verification
```

AI、规则引擎、Agent 和 LLM 可以提出结构化的 `ActionRequest`（动作申请）；但任何一方都无权直接控制泵、阀、电机、XYZ 平台或喷嘴。真实硬件需要人工关卡（Human Gate）、独立的安全治理器和确定性控制器。

## 证据词汇表

| 等级 | 允许的声明 | 最低证据 |
|---|---|---|
| E0 | 设计存在 | 需求、契约、图示 |
| E1 | 某个组件可重复 | 可复现的模块流程与证据 |
| E2 | 多组件集成 | 真实接口交换加错误处理 |
| E3 | 最小闭环存在 | 真实检测 -> 安全动作 -> 回执 -> 验证 -> 路径 |
| E4 | 研究结论 | 重复的 A/B，误差/局限分析 |

文件和生成的代码永远不是物理系统证据。

## 完成定义

一个任务只有在具备可执行/已测试的变更、契约状态、证据产物、可复现说明、文档以及 `project_state.yaml` 更新时才算完成。模拟测试可以关闭一个软件契约任务，但不能将硬件平台推进到 E1 以上。
