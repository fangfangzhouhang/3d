## 一、Trae 界面快速认识

> **重要**：我们使用 **Trae** 作为主要开发工具，所有操作都在 Trae 中完成。

### 1.1 三个核心面板

| 面板 | 图标 | 位置 | 用途 |
|------|------|------|------|
| **资源管理器** | 📁 | 左侧第一个 | 查看项目文件结构，创建/删除/重命名文件 |
| **源代码管理** | 🪵 | 左侧第二个 | Git操作：提交、推送、拉取、分支管理 |
| **终端** | ⬛ | 底部 | 执行命令（激活虚拟环境等） |

### 1.2 Trae AI 辅助功能（核心优势）

Trae 内置强大的 AI 助手，可以帮助你：

1. **代码生成**：选中文件后，点击右侧 AI 对话框，描述你想要的功能，AI 会帮你生成代码
2. **代码解释**：选中代码，让 AI 解释这段代码的作用
3. **代码优化**：让 AI 帮你优化代码结构和性能
4. **错误修复**：遇到报错时，让 AI 帮你分析原因并提供修复方案

> **使用提示**：遇到问题先问 AI，它能帮你快速解决大部分编码问题！

## 二、基础概念通俗讲

### 1.1 用生活类比理解Git

想象我们的项目是一个**共享的草稿本**，团队每个人都有一本复印件，GitHub就是存放正本的**保险柜**。

| Git概念 | 生活类比 | 说明 |
|---------|----------|------|
| **main主干** | 草稿本的**正本** | 最终稳定版本，所有人共享 |
| **功能分支** | 在草稿纸**另起一页**写草稿 | 你自己的开发区域，不影响正本 |
| **远程origin** | 保险柜的**地址** | GitHub仓库的地址，大家都连同一个 |
| **分离HEAD** | 把草稿纸**撕下来**单独写 | 危险！不要这么做 |
| **提交(commit)** | 在草稿纸**写一句话总结** | 保存你的修改，方便追溯 |
| **PR(Pull Request)** | 申请把你的草稿**贴到正本上** | 请求组长审核你的代码 |
| **代码冲突** | 两个人**同时改了草稿本同一页** | 需要商量后决定保留谁的版本 |

### 2.2 核心原则

> **就像家里的钥匙，每个人都有一把，但开门前要先确认门锁状态**。

- **不要直接改main**：就像不要在正本上直接涂画，要先拿草稿纸
- **先同步再开发**：开门前先看看家里有没有新变化
- **小步提交**：写一点总结一点，不要整篇写完才总结

## 三、硬性禁止红线（必须遵守）

> **违反以下任何一条，都可能导致项目崩溃！**

### ❌ 禁止直接修改 main 主干

```
错误做法：直接在 main 分支上写代码、提交、推送
正确做法：从 main 创建功能分支，在分支上开发
```

**为什么？** main是最终稳定版本，直接修改会影响所有人，就像在大家共用的正本上乱涂。

### ❌ 禁止分离 HEAD 模式开发

```
错误做法：git checkout <commit-id> 后直接修改提交
正确做法：git checkout -b <分支名> 创建分支后再开发
```

**为什么？** 分离HEAD就像把草稿纸撕下来，你的修改无法安全地合并回去。

### ❌ 禁止多远程别名指向同一个仓库

```
错误做法：git remote add upstream <同一个仓库地址>
正确做法：只使用默认的 origin 远程
```

**为什么？** 多个远程指向同一仓库会造成混乱，就像家里有两把钥匙开同一扇门，容易搞混。

### ❌ 禁止大批量一次性提交代码

```
错误做法：一次提交100个文件，注释写"修改了很多东西"
正确做法：每次提交不超过10个相关文件，注释清晰说明做了什么
```

**为什么？** 大批量提交难以审查，出问题时无法定位。

### ❌ 禁止不更新主干就合并

```
错误做法：直接把自己的分支合并到main，不管main有没有新更新
正确做法：先拉取main的最新代码，处理完冲突再合并
```

**为什么？** 就像你修改的草稿是基于旧版本的正本，必须先更新到最新版。

### ❌ 禁止裸推代码到主干

```
错误做法：git push origin main
正确做法：通过PR流程合并到main
```

**为什么？** 必须经过组长审核，确保代码质量。

## 四、标准化全流程操作步骤

### 4.1 初次克隆仓库

**目的**：把远程仓库的代码下载到你的电脑

#### Trae 可视化操作：
1. 打开 **Trae**
2. 左侧点击 **源代码管理** 图标（🪵，第二个图标）
3. 点击 **克隆仓库**
4. 粘贴仓库地址：`https://github.com/fangfangzhouhang/3d.git`
5. 选择本地保存路径（建议放在桌面或文档目录）

> **提示**：克隆完成后，Trae会自动打开项目，左侧资源管理器会显示项目文件结构。

---

#### 可选：终端命令（了解即可）
```bash
# 克隆仓库到本地
git clone https://github.com/fangfangzhouhang/3d.git

# 进入项目目录
cd MicroCleaningVision
```
---

### 4.2 新建规范命名分支

**目的**：创建你自己的开发区域

#### Trae 可视化操作：
1. 左下角显示当前分支名（如 `main`），点击它
2. 在弹出的菜单中选择 **创建新分支**
3. 输入分支名称（如 `feat/camera-connect`）
4. 按 Enter 确认

> **提示**：创建成功后，左下角会显示新分支名称。

---

#### 可选：终端命令（了解即可）
```bash
# 创建并切换到新分支
git checkout -b feat/camera-connect
```

**分支命名规则**：见第五章

---

### 4.3 每日开发前同步主干

**目的**：确保你的分支基于最新的main版本

#### Trae 可视化操作：
1. 左下角点击当前分支名 → 选择 `main` 切换到主干
2. 点击 **同步更改**（蓝色箭头图标），拉取最新代码
3. 切回你的分支（左下角点击分支名选择你的分支）
4. 在源代码管理面板点击 **合并**，选择 `main`

> **重要**：如果出现冲突，请参考第七章处理。

---

#### 可选：终端命令（了解即可）
```bash
# 切换到main分支
git checkout main

# 拉取最新代码
git pull origin main

# 切回你的分支
git checkout feat/camera-connect

# 合并main的更新到你的分支
git merge main
```

---

### 4.4 本地写代码分次提交

**目的**：保存你的修改，方便追溯

#### 步骤1：查看修改了哪些文件

#### Trae 可视化操作：
1. 左侧点击 **源代码管理** 图标（🪵，第二个图标）
2. 可以看到所有修改过的文件（红色显示）

#### 步骤2：暂存文件

#### Trae 可视化操作：
1. 每个文件右侧有 `+` 号，点击暂存（变绿色）
2. 或点击顶部的 **暂存所有更改**

#### 步骤3：提交（写总结）

#### Trae 可视化操作：
1. 在源代码管理面板顶部的输入框中写提交注释
2. 点击 **√** 图标提交

> **提示**：提交成功后，文件列表会清空。

**提交注释规则**：见第六章

---

#### 可选：终端命令（了解即可）
```bash
# 查看状态
git status

# 暂存所有修改
git add .

# 提交，写注释
git commit -m "feat(camera): 实现顶部相机连接功能"
```

---

### 4.5 推送远程分支

**目的**：把你的代码上传到GitHub，备份并供他人查看

#### Trae 可视化操作：
1. 在源代码管理面板点击 **同步更改**（蓝色箭头）
2. 第一次推送会提示设置上游分支，点击确定

> **提示**：推送成功后，你的代码就上传到GitHub了，队友可以看到你的修改。

---

#### 可选：终端命令（了解即可）
```bash
# 推送到远程，设置上游分支
git push -u origin feat/camera-connect

# 后续推送直接用
git push
```

---

### 4.6 发起 PR 合并主干

**目的**：请求组长审核你的代码，合并到main

#### 网页操作（GitHub）：
1. 打开仓库页面：`https://github.com/fangfangzhouhang/3d.git`
2. 点击 **Pull requests** → **New pull request**
3. 选择 **compare** 为你的分支（如 `feat/camera-connect`）
4. 选择 **base** 为 `main`
5. 填写标题和描述，点击 **Create pull request**

**标题格式**：`feat(camera): 实现顶部相机连接功能`

> **提示**：PR创建后，通知组长审核。审核通过后，组长会合并到main。

---

### 4.7 冲突本地解决

**目的**：处理多人修改同一文件的情况

#### Trae 可视化操作：
1. Trae会自动检测冲突，显示红色提示
2. 点击 **解决冲突** 按钮
3. 选择保留你的更改（**接受当前更改**）或对方的更改（**接受传入更改**）
4. 解决完所有冲突后，点击 **标记为已解决**
5. 重新提交

详细教程见第七章。

---

#### 可选：终端命令（了解即可）
```bash
# 查看冲突文件
git status

# 编辑文件解决冲突后，标记为已解决
git add camera/camera.py

# 继续合并
git commit -m "fix: 解决相机模块冲突"
```

---

### 4.8 合并后清理临时分支

**目的**：保持仓库整洁

#### Trae 可视化操作：
1. PR合并后，左下角点击分支名
2. 选择 `main` 切换到主干
3. 右键你的临时分支，选择 **删除分支**

> **提示**：删除分支后，本地和远程的临时分支都会被清理。

---

#### 可选：终端命令（了解即可）
```bash
# 切换到main
git checkout main

# 更新main
git pull origin main

# 删除本地分支
git branch -d feat/camera-connect

# 删除远程分支
git push origin --delete feat/camera-connect
```

```bash
git checkout -b docs/development-plan
```

## 六、提交注释规范

### 提交注释格式

```
类型(模块): 简短描述（不超过50字）
```

### 类型说明

| 类型 | 含义 | 示例 |
|------|------|------|
| `feat` | 新增功能 | `feat(camera): 实现单相机图像采集` |
| `fix` | bug修复 | `fix(comm): 修复串口连接超时` |
| `optimize` | 性能优化 | `optimize(detect): 减少内存占用` |
| `docs` | 文档修改 | `docs: 更新开发计划文档` |
| `refactor` | 代码重构 | `refactor(config): 统一配置类命名` |
| `test` | 测试代码 | `test(camera): 添加相机连接测试` |
| `chore` | 杂项修改 | `chore: 更新.gitignore` |

### 正确示例

```bash
# ✅ 正确：类型+模块+简短描述
git commit -m "feat(camera): 实现顶部相机连接功能"
git commit -m "fix(comm): 修复串口发送失败问题"
git commit -m "docs: 更新开发计划文档"
git commit -m "test(camera): 添加相机采集测试用例"

# ❌ 错误：太笼统
git commit -m "修改了代码"
git commit -m "完成任务"
git commit -m "更新文件"
```

## 七、冲突处理教程

### 7.1 提前预防冲突习惯

1. **每天开发前同步main**：就像开门前先看看家里有没有变化
2. **小步提交**：写一点提交一点，减少冲突范围
3. **避免修改同一文件的同一部分**：提前和队友沟通分工
4. **定期推送**：每天至少推送一次，让队友知道你的进度

### 7.2 本地Trae可视化解决冲突

当你执行合并操作时，如果出现冲突：

#### 步骤1：Trae会提示冲突
```
自动合并 camera/camera.py
冲突（内容）：合并冲突于 camera/camera.py
自动合并失败；修复冲突然后提交结果。
```

#### 步骤2：打开冲突文件
Trae会在冲突位置显示：
```python
<<<<<<< HEAD
    def connect(self):
        # 你的代码
        return True
=======
    def connect(self, camera_id=0):
        # 队友的代码
        return True
>>>>>>> main
```

#### 步骤3：选择保留哪部分
- **接受当前更改**：保留你的代码（HEAD）
- **接受传入更改**：保留队友的代码（main）
- **接受两者**：都保留（需要手动编辑）

#### 步骤4：标记为已解决
点击顶部的 **标记为已解决** 按钮

#### 步骤5：重新提交
在源代码管理面板中提交即可。

### 7.3 网页PR冲突处理

如果在GitHub上创建PR时提示冲突：

1. **回到本地**，按照7.2的步骤解决冲突
2. 推送更新后的分支（Trae中点击同步更改）
3. PR会自动更新

### 7.4 多人修改同一块代码的沟通规则

1. **提前沟通**：修改前在群里说一声"我要改camera.py的connect方法"
2. **及时同步**：修改后立即推送，让队友知道
3. **互相review**：修改重要代码时，@队友帮忙看一下
4. **保留最好的**：冲突时，不是谁先写的就用谁的，而是保留更好的实现

## 八、远程仓库使用规则

### 8.1 仅允许使用默认origin远程

```bash
# 查看当前远程配置
git remote -v

# 正确输出：只有一个origin
origin  https://github.com/用户名/MicroCleaningVision.git (fetch)
origin  https://github.com/用户名/MicroCleaningVision.git (push)
```

### 8.2 禁止新增同名仓库远程别名

```bash
# ❌ 错误：不要这样做
git remote add upstream https://github.com/xxx/MicroCleaningVision.git

# ✅ 正确：只用origin
```

### 7.3 多余远程清理命令

```bash
# 查看所有远程
git remote -v

# 删除多余的远程（如upstream）
git remote remove upstream
```

## 九、虚拟环境使用规则

> **重要**：项目使用虚拟环境管理依赖，**每次编码前必须先激活虚拟环境！**

### 9.1 虚拟环境是什么？

就像给项目准备了一个**专属房间**，所有依赖包都安装在这个房间里，不会影响电脑上的其他项目。

| 概念 | 生活类比 | 说明 |
|------|----------|------|
| **虚拟环境** | 项目的**专属房间** | 隔离依赖，避免冲突 |
| **激活虚拟环境** | 进入房间开始工作 | 使用房间里的工具（Python、依赖包） |
| **依赖包** | 房间里的**工具** | OpenCV、PyTorch等库 |

### 9.2 每次编码前必须激活虚拟环境

#### Windows系统 - 终端命令：

```bash
# 进入项目目录（根据自己的文件位置来）
cd MicroCleaningVision

# 激活虚拟环境
.\venv\Scripts\Activate.ps1
```

激活成功后，终端提示符会显示 `(venv)`：
```
(venv) D:\大创\opencv\MicroCleaningVision>
```

#### Windows系统 - PowerShell命令：

```powershell
# 进入项目目录
cd MicroCleaningVision

# 激活虚拟环境
.\venv\Scripts\Activate.ps1
```

> **注意**：如果PowerShell提示权限问题，以管理员身份运行PowerShell并执行：
> ```powershell
> Set-ExecutionPolicy RemoteSigned
> ```

#### VSCode自动激活：

1. 打开VSCode → 左下角显示Python解释器版本
2. 点击版本号 → 选择 `Python 3.x.x .\venv\Scripts\python.exe`
3. 打开终端，VSCode会自动激活虚拟环境

### 8.3 如何确认虚拟环境已激活？

```bash
# 查看Python解释器路径
which python    # Linux/Mac
where python    # Windows

# 输出应该包含 venv 路径
# Windows示例：D:\大创\opencv\MicroCleaningVision\venv\Scripts\python.exe
```

### 8.4 退出虚拟环境

```bash
# 退出虚拟环境
deactivate
```

### 9.5 安装依赖包（仅组长或环境配置者操作）

```bash
# 确保已激活虚拟环境
# 安装项目依赖
pip install -r requirements.txt

# 安装新的依赖包
pip install opencv-python

# 更新依赖列表（安装新包后必须执行）
pip freeze > requirements.txt
```

### ❌ 禁止在未激活虚拟环境时安装依赖

```
错误做法：在系统Python环境中安装依赖
正确做法：必须先激活venv虚拟环境再安装
```

**为什么？** 未激活虚拟环境时安装的依赖不会被项目使用，就像把工具放在了房间外面。

## 十、文件/文件夹操作指南

> **重要**：所有文件操作都在 Trae 的 **资源管理器**（📁，左侧第一个图标）中完成。

### 10.1 文件/文件夹树结构

左侧资源管理器显示项目的文件树结构：
- 文件夹显示为 📁 图标，可以展开/折叠
- 文件显示为不同图标，根据类型区分（.py、.md、.txt等）
- 文件名前面有状态标记：
  - **U**：未跟踪（新建的文件）
  - **M**：已修改（修改过的文件）
  - **A**：已暂存（已添加到暂存区）

### 10.2 创建文件/文件夹

#### Trae 可视化操作：

**创建文件**：
1. 在资源管理器中，右键点击目标文件夹
2. 选择 **新建文件**
3. 输入文件名（如 `camera.py`）
4. 按 Enter 确认

**创建文件夹**：
1. 在资源管理器中，右键点击目标位置
2. 选择 **新建文件夹**
3. 输入文件夹名（如 `detection`）
4. 按 Enter 确认

#### 快捷键：
| 操作 | 快捷键 |
|------|--------|
| 新建文件 | `Ctrl+N` |
| 新建文件到指定位置 | 右键菜单 |

### 10.3 删除文件/文件夹

#### Trae 可视化操作：

1. 在资源管理器中，右键点击要删除的文件/文件夹
2. 选择 **删除**
3. 确认删除（会提示确认对话框）

#### 快捷键：
| 操作 | 快捷键 |
|------|--------|
| 删除选中项 | `Delete` |

> **注意**：删除后可以在 Git 中恢复（参考第十一章），但最好先确认是否真的需要删除。

### 10.4 重命名文件/文件夹

#### Trae 可视化操作：

1. 在资源管理器中，右键点击要重命名的文件/文件夹
2. 选择 **重命名**
3. 输入新名称
4. 按 Enter 确认

#### 快捷键：
| 操作 | 快捷键 |
|------|--------|
| 重命名 | `F2` |

### 10.5 移动文件/文件夹

#### Trae 可视化操作：

**方法1：拖拽移动（推荐）**
1. 在资源管理器中，选中要移动的文件/文件夹
2. 按住鼠标左键拖拽到目标文件夹
3. 松开鼠标，文件就会移动过去

**方法2：剪切粘贴**
1. 选中文件/文件夹
2. 按 `Ctrl+X` 剪切
3. 选中目标文件夹
4. 按 `Ctrl+V` 粘贴

#### 快捷键：
| 操作 | 快捷键 |
|------|--------|
| 剪切 | `Ctrl+X` |
| 复制 | `Ctrl+C` |
| 粘贴 | `Ctrl+V` |

### 10.6 上下文菜单说明

右键点击文件/文件夹时，会显示上下文菜单：

| 菜单项 | 功能 |
|--------|------|
| **打开** | 在编辑器中打开文件 |
| **新建文件** | 在当前文件夹下创建新文件 |
| **新建文件夹** | 在当前位置创建新文件夹 |
| **重命名** | 修改文件/文件夹名称 |
| **删除** | 删除文件/文件夹 |
| **复制路径** | 复制文件的完整路径 |
| **在资源管理器中显示** | 打开系统文件管理器定位到该文件 |

### 10.7 文件搜索

#### Trae 可视化操作：

1. 按 `Ctrl+P` 打开快速搜索
2. 输入文件名或关键词
3. 上下箭头选择，按 Enter 打开

#### 快捷键：
| 操作 | 快捷键 |
|------|--------|
| 快速打开文件 | `Ctrl+P` |
| 在文件中搜索 | `Ctrl+F` |
| 在项目中搜索 | `Ctrl+Shift+F` |

## 十一、常见问题解决

### 11.1 推送代理报错

**错误信息**：
```
fatal: unable to access 'https://github.com/...': Failed to connect to github.com port 443: Timed out
```

**解决方法**：

#### 方法1：设置代理（校园网用户）
```bash
# 设置代理
git config --global http.proxy http://proxy.xxx.com:8080
git config --global https.proxy http://proxy.xxx.com:8080

# 取消代理
git config --global --unset http.proxy
git config --global --unset https.proxy
```

#### 方法2：使用SSH方式（推荐）
```bash
# 检查SSH密钥
ls ~/.ssh

# 如果没有密钥，生成一个
ssh-keygen -t ed25519 -C "你的邮箱"

# 复制公钥到GitHub
cat ~/.ssh/id_ed25519.pub
```
然后在GitHub设置中添加SSH密钥。

### 11.2 SSL证书报错

**错误信息**：
```
fatal: unable to access 'https://github.com/...': SSL certificate problem: unable to get local issuer certificate
```

**解决方法**：
```bash
# 临时忽略SSL验证（不推荐长期使用）
git config --global http.sslVerify false

# 永久解决：安装证书
# Windows用户：下载GitHub证书并安装
```

### 11.3 代码丢失

**情况**：误删了文件，或者提交错了

**解决方法**：

#### 恢复未提交的修改
```bash
# 恢复单个文件
git checkout -- camera/camera.py

# 恢复所有未提交的修改
git checkout -- .
```

#### 撤销最近一次提交
```bash
# 撤销提交，但保留修改（可以重新提交）
git reset HEAD~1

# 撤销提交并丢弃修改（慎用！）
git reset --hard HEAD~1
```

#### 恢复已删除的文件
```bash
# 找到删除该文件的提交
git log --oneline -- camera/camera.py

# 恢复该文件到某个版本
git checkout <commit-id> -- camera/camera.py
```

### 11.4 PR合并失败

**情况**：组长告诉你PR无法合并

**解决方法**：

```bash
# 1. 切换到你的分支
git checkout feat/your-feature

# 2. 拉取main最新代码
git pull origin main

# 3. 解决冲突（参考第七章）
#    Trae会提示冲突，手动解决

# 4. 提交解决后的代码
git add .
git commit -m "fix: 解决合并冲突"

# 5. 推送更新
git push

# 6. PR会自动更新，通知组长重新审核
```

## 十二、常用命令速查

| 命令 | 用途 |
|------|------|
| `git clone <地址>` | 克隆仓库 |
| `git checkout main` | 切换到main分支 |

| `git add <文件>` | 暂存文件 |
| `git commit -m "<注释>"` | 提交修改 |
| `git push` | 推送到远程 |
| `git merge main` | 合并main到当前分支 |
| `git branch` | 查看所有分支 |
| `git branch -d <分支名>` | 删除本地分支 |

## 十三、团队协作流程总结

> **所有操作都在 Trae 中完成！**

```
0. 每次开始编码前：打开Trae → 选择项目 → 激活虚拟环境（底部终端执行 venv\Scripts\activate）
1. 每天早上：左下角切换到main → 同步更改 → 切换到你的分支 → 合并main
2. 开发中：源代码管理中暂存 → 写注释提交 → 同步更改推送
3. 功能完成：在GitHub创建PR → 等待审核 → Trae中解决冲突 → 合并
4. 合并后：切换到main → 同步更改 → 删除临时分支
```
