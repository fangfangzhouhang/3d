# MicroCleaningVision 开发梯度计划

## 一、开发梯度概述

根据项目实际情况，我们采用**四阶段梯度开发**策略，每个阶段都基于前一阶段的成果进行增量升级，确保代码结构稳定、功能逐步完善：

| 阶段 | 名称 | 核心技术 | 难度 | 预期时间 |
|------|------|----------|------|----------|
| **Phase 1** | 基础视觉检测 | 顶部相机 + OpenCV传统视觉 | ⭐ | 1-2周 |
| **Phase 2** | AI视觉检测 | YOLO目标检测替代传统检测 | ⭐⭐ | 2-3周 |
| **Phase 3** | 双目立体视觉 | 加入45°相机 + 双目标定 | ⭐⭐⭐ | 2-3周 |
| **Phase 4** | 三维重建 | 深度图 + 点云处理 | ⭐⭐⭐⭐ | 3-4周 |

## 二、各阶段详细计划

### Phase 1：基础视觉检测（单相机 + OpenCV）

**目标**：实现最基本的视觉检测闭环——顶部相机采集图像 → OpenCV颜色检测 → 串口发送喷水指令

**核心功能**：
1. 顶部相机连接和图像采集
2. OpenCV HSV颜色空间检测污渍
3. 串口通信发送喷水指令
4. 清洗效果评估（简单的面积对比）

**涉及模块**：
- `camera/camera.py` - 相机连接和采集
- `detection/detector.py` - OpenCV检测实现
- `communication/stm32_comm.py` - 串口通信
- `planning/planner.py` - 简单的坐标计算和决策

**入口标准**：
- Python环境配置完成（已完成）
- 顶部显微镜相机可用
- STM32串口通信可用

**出口标准**：
- 能稳定采集顶部相机画面
- 能识别红色污渍并标记位置
- 能通过串口发送喷水指令
- 能判断清洗是否有效

**无需修改的模块**：
- `models/` - 本阶段不使用AI模型
- `reconstruction/` - 本阶段不使用三维重建
- `dataset/` - 本阶段不使用数据集管理

---

### Phase 2：AI视觉检测（YOLO替代OpenCV）

**目标**：用YOLO模型替代OpenCV传统检测，支持多类别污渍识别

**核心功能**：
1. YOLO模型加载和推理
2. 多类别污渍识别（灰尘、油污、划痕、残渣、纤维）
3. 检测结果后处理（过滤、排序）
4. 置信度阈值可调

**涉及模块**：
- `models/yolo_model.py` - YOLO模型封装
- `detection/detector.py` - 切换到YOLO检测
- `detection/preprocessing.py` - 图像预处理
- `detection/postprocessing.py` - 检测结果后处理

**入口标准**：
- Phase 1功能完整运行
- PyTorch和YOLO环境配置完成（已完成）
- 标注好的数据集准备就绪

**出口标准**：
- 能加载YOLO模型并进行推理
- 能识别5种污渍类型
- 检测结果包含置信度和类别信息
- 能过滤低置信度检测结果

**无需修改的模块**：
- `reconstruction/` - 本阶段不使用三维重建
- `camera/stereo.py` - 本阶段不使用双目视觉

---

### Phase 3：双目立体视觉（加入45°相机）

**目标**：加入45°相机，实现双目图像采集和坐标计算

**核心功能**：
1. 45°相机连接和图像采集
2. 双目标定（获取内外参）
3. 坐标计算（像素坐标转物理坐标）
4. 双目图像融合

**涉及模块**：
- `camera/camera.py` - 添加45°相机支持
- `camera/calibration.py` - 双目标定
- `camera/stereo.py` - 立体视觉
- `planning/coordinate_calculator.py` - 坐标转换

**入口标准**：
- Phase 2功能完整运行
- 45°显微镜相机可用
- 标定板准备就绪

**出口标准**：
- 能同时采集顶部和45°相机画面
- 能完成双目标定
- 能将像素坐标转换为物理坐标
- 能计算目标的三维位置

**无需修改的模块**：
- `reconstruction/` - 本阶段不使用三维重建

---

### Phase 4：三维重建

**目标**：从双目图像生成深度图和点云，实现三维重建

**核心功能**：
1. 深度图生成
2. 点云处理（去噪、下采样）
3. 三维可视化
4. 清洗路径优化

**涉及模块**：
- `reconstruction/depth_map.py` - 深度图生成
- `reconstruction/point_cloud.py` - 点云处理
- `reconstruction/three_d_reconstructor.py` - 重建管理器
- `planning/planner.py` - 基于三维信息的路径规划

**入口标准**：
- Phase 3功能完整运行
- 双目图像质量满足重建要求

**出口标准**：
- 能从双目图像生成深度图
- 能处理和优化点云
- 能进行三维可视化
- 能基于三维信息规划清洗路径

## 三、三人分工方案

### 分工原则

按**功能管线**进行纵向切分，每人负责一个完整的功能链条，便于独立开发和测试：

| 成员 | 代号 | 负责模块 | 角色定位 |
|------|------|----------|----------|
| **你（组长）** | A | camera + detection | 视觉采集与识别 |
| **成员B** | B | planning + communication | 控制决策与通信 |
| **成员C** | C | dataset + training | 数据与模型训练 |

## 四、新人入门引导流程

### 第一步：环境配置（第1天）

**由你负责指导**

1. **安装Python环境**
   - 安装Python 3.8+
   - 创建虚拟环境 `python -m venv venv`
   - 激活虚拟环境

2. **安装依赖**
   - 安装项目依赖 `pip install -r requirements.txt`
   - 验证OpenCV安装 `python -c "import cv2; print(cv2.__version__)"`

3. **配置VS Code**
   - 安装Python插件
   - 设置Python解释器为虚拟环境中的Python

4. **测试运行**
   - 运行 `test_env.py` 验证环境配置
   - 运行相机测试脚本验证相机连接

**沟通话术参考**：
> "先跟着我配置环境，这是基础。打开命令行，按步骤创建虚拟环境，然后安装依赖。有任何报错随时问我，这一步一定要确保成功，后面开发才不会出问题。"

## 五、与现有代码架构的兼容性说明

### 为什么这个梯度计划不需要大改结构？

1. **模块化设计**：项目采用高度解耦的模块化设计，每个模块独立封装，替换或添加功能只需修改对应模块

2. **统一接口**：所有模块都有统一的接口设计，例如：
   - `Detector` 类的 `detect()` 方法可以切换OpenCV/YOLO实现
   - `CameraManager` 可以控制是否启用 `angle_camera`
   - `Planner` 的方法接口保持稳定

3. **预留扩展能力**：
   - `models/` 目录预留了多模型支持
   - `reconstruction/` 目录预留了三维重建能力
   - `dataset/` 目录预留了数据集管理能力

4. **配置驱动**：所有关键参数都在 `config.py` 中配置，通过配置可以控制功能开关

## 七、风险管理

### 常见风险及应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 相机连接失败 | 无法采集图像 | 准备备用摄像头，测试多种后端 |
| 串口通信不稳定 | 无法控制STM32 | 添加错误处理和重试机制 |
| 模型训练效果差 | 检测准确率低 | 增加标注数据，调整训练参数 |
| 标定精度不足 | 坐标计算误差大 | 使用高精度标定板，多次标定取平均 |
| 新人进度慢 | 整体进度滞后 | 提供详细文档，定期一对一辅导 |
