# 串口协议与参数

电脑与固件共同使用这一份约定。修改句子、单位或引脚前，提供者与消费者一起核对。

核对：2026-10-05，main 341224f（PR #24 后）加 feat/single-entry-cleaning-v1 未提交主机改动；本次未改固件或线上协议。当前工程是 firmware/common/keil/stage2-stepmotor.uvprojx，单一 main.c 同时编译运动、泵、已有安全状态机和 MCV1 协议。旧喷水工程保留在 common/compat/stage1/，工程为 common/keil/f103-stage1.uvprojx；不是当前移动/喷水必须轮流烧录。

## 1. 串口与证据边界

| 项目 | 约定 |
|---|---|
| 实验板 | STM32F103C8；不是 F401 |
| 串口 | USART2：PA2 TX，PA3 RX |
| 参数 | 115200、8N1、ASCII；按行发送 |
| 换行 | 固件接受 CR 或 LF；STEP 电脑端使用 CRLF，MCV1 编码器使用 LF |
| 端口 | 人从设备管理器确认的 USB-TTL；不扫描 COM |
| 当前主入口行容量 | 数组 64 字节，最多 63 个内容字节；超长整行丢弃并停止 |
| MCV1 旧实现容量 | 128 字节；目前合法短命令含 32 字符动作编号可放入当前主入口 |

同一 v0.3 握手无法唯一识别本轮固件，必须记录源码版本、工作区差异和实际烧录文件。编译产物不是烧录证据。

PB2 接线是本次新增明确条件，未实机确认。输入断开时动作会被阻止；不要短接或绕过来追求 Demo 运行。默认 FW_REQUIRE_ARM_BUTTON=0 保留旧配置，不宣称默认要求物理 ARM。设 1 的原始 ARM/PUMP ON 路径已有离线测试，MCV1 物理按钮握手仍需专项确认。

旧兼容入口的 PB2 配置未重写，不自动具有当前入口的接线条件。轮询停止不是独立硬件断电方案。

### 机械名义参数

当前移动的是样本托盘，两台 DM542 的共阳极接法和细分/导程来自原约定；不是本次测量结果。

| 项目 | 名义值 / 限制 |
|---|---|
| 细分、导程 | 1600 步/圈，5 mm/圈 |
| 步距 | 320 步/mm；电脑 microstep=1，不能再乘 16 |
| 画面比例 | 0.01 mm/px 仍是占位，未标定 |
| 默认脉冲频率 | 500 Hz；一个脉冲两个半周期，更新中断 1000 Hz |
| SPEED 可设置范围 | 10–20000 Hz；当前正式发送器不发 SPEED |
| MCU 单命令上限 | 各轴 20000 步 |
| 正式主机运动关卡 | 不再另设单次步数上限；能否移动只看位置账本，人工零点两侧各 10000 步。固件一条报文最多 20000 步 |
| 名义显微镜/针头偏移 | Y 7680 步 = 24 mm × 320；未验方向、距离或行程 |

两轴同频，短轴先停，不是比例直线插补。READXY 是已发脉冲，不是台面位置反馈。DM542 的具体端子、电平要求和实际装配仍须以手头器件核对，不能凭文档替代检查。

## 3. STEP 兼容运动与辅助句子

| 发送 | 回复 | 说明 |
|---|---|---|
| HELLO | STEP_OK v0.3 | 不动作，旧 v0.2 被正式主机拒绝 |
| MOVEXY Nx FWD或REV Ny FWD或REV | STEP2_START X=Nx 方向 Y=Ny 方向 | 双轴开始；任一轴可 0 |
| READXY | STEP2 X=已发 BX=0或1 Y=已发 BY=0或1 | 查询计数和忙闲 |
| STOP | STEP_STOPPED | 两轴停止、关泵；若 MCV1 动作被中止，还会有该动作的 ERR |
| PUMP ON | PUMP_ON | 兼容短喷，固定 300 ms 自停；重复 ON 不延期 |
| PUMP OFF | PUMP_OFF | 关闭泵；正在运行 MCV1 动作则中止，不伪造 DONE |
| TO_NEEDLE | STEP2_START X=0 FWD Y=7680 FWD | 同一 XY 驱动的相对名义偏移 |
| TO_SCOPE | STEP2_START X=0 FWD Y=7680 REV | 反向名义偏移，不是回零 |
| CLEAR | CLEARED 或 ERR: CLEAR_REJECTED | 输入恢复后清急停锁存，不自动续跑 |
| ARM | ARMED / ARM_PENDING / ERR: ARM_REJECTED | 由配置/按钮决定是否完成 ARM |
| PULSE N 可选方向 | STEP_START N=N 方向 | 旧单 X 命令，正式路径不用 |
| READ | STEP_SENT=已发 BUSY=0或1 | 旧 X 查询 |
| SPEED Hz | SPEED=<实际值>Hz OK | 按范围夹取 |
| MOVE N | STEP_MOVE N=N | 旧 X 正向入口，正式路径不用 |

拒绝：ESTOP/FAULT、忙时覆盖、非法/负数/溢出数字、非法方向、多余字段、过长行尾部。必须按回复决定是否继续，不能将错误当运动已执行。

电脑侧 `Stage2SerialLink` 仍只发 `HELLO` / `MOVEXY` / `READXY` / `STOP`，不发 `PUMP`、`MCV1` 或 `TO_NEEDLE`。喷水仍由 `STM32SerialController` 发 `MCV1|PUMP|action_id|毫秒`。两套编码器没有合并。

2026-10-05 起，主机增加 `microcleaning/control_system/serial/f103_session.py` 的 `F103SerialSession`。它让这两套逻辑协议按时间顺序共用同一个人指定的 COM：先走完步进，步进成功、并且喷水关卡仍是 ALLOW、控制器已武装，才调用喷水。同一时刻只有一个命令流占用这条串口。切换前先读完已经到达的回复；清接收缓存时留下另一协议还没读完的回复。运动失败、未武装或不是 ALLOW 时，喷水字节数为 0。`ACK` 只表示固件接受，`DONE` 只表示输出流程结束，都不是清洗成功。`F103SerialSession` 不发送 `TO_NEEDLE` / `TO_SCOPE`。主机不再另设单次步数上限。能否移动只看位置账本，人工零点两侧各 10000 步。固件一条报文最多 20000 步。

新 `demo.closed_loop_station` 已调用该会话，以 close_after=False 在成功后保持连接；失败关闭/锁定。同一进程包括原图分割、稳定目标、顺序、单目标规划、逐轮 YES、去程/短喷/回程和新后图复检；默认 Mock 验证三目标成功。旧 demo_pipeline 单帧模式继续各自运行，真实 COM 本轮未打开。Stage2SerialLink 现在要求 READXY 各非零轴已发计数等于申请；零轴可保留上段计数。泵审批在移动前预检，发送前复检；完整运动结果/错误保留供账本与档案使用。

analyze --stage2-xy 只保存文本，不开串口；stage2-move 仍需已有运动关卡、人输入 YES 和 --arm-stage2-xy。名义偏移大于现有主机预算，后续必须先提出标定、预算和单一偏移来源方案，不绕过关卡发送原始命令。

## 4. MCV1 限时喷水：旧/新入口共用

MCV1 主机实现：microcleaning/control_system/serial/stm32_protocol.py。协议处理：firmware/common/serial/mcv1_protocol.c。该文件与安全核心内容沿用旧工程，只整理位置，并由当前 main.c 实际调用。

| 发送 | 回复 | 意义 |
|---|---|---|
| `MCV1\|PING` | `MCV1\|PONG` | 在线，不表示可以喷水 |
| `MCV1\|STATUS` | `MCV1\|STATUS\|ESTOP=<0或1>\|PUMP=<0或1>` | 输入/泵逻辑状态 |
| `MCV1\|PUMP\|<action_id>\|<毫秒>` | `MCV1\|ACK\|<action_id>`，结束时 `MCV1\|DONE\|<action_id>` | 有界限时输出 |
| `MCV1\|STOP` | 中止动作的 ERR（如有），然后 `MCV1\|ACK\|STOP` / `MCV1\|DONE\|STOP` | 停两轴、关泵；被中止动作不写成功 |
| 拒绝/故障 | ERR 编号 错误码 | 未执行或中止 |

字段之间用字符 | 分隔。完整文本示例：

~~~text
MCV1|PING
MCV1|PONG
MCV1|PUMP|A001|300
MCV1|ACK|A001
MCV1|DONE|A001
~~~

电脑编码器默认 100–500 ms；STM32SerialController 与新闭环 PUMP_IN_PLACE 许可为 100–500 ms，闭环默认 500 ms。固件 `PUMP ON` 仍是固定 300 ms，不随这次主机许可改变。MCU 沿用旧核心范围 100–2000 ms，不把固件上限当作用户可以直接申请的上限。动作编号为 1–32 字符的字母、数字、下划线或连字符，电脑持续使用唯一编号；固件只缓存最近 8 个，不能保证无限历史去重。

ACK 是接受，DONE 是输出流程结束，不是液体到达或清洗率。急停、STOP 和 FAULT 会中止，解除后不自动续跑。错误包括 BAD_FORMAT、BAD_VERSION、BAD_DURATION、ESTOP、BUSY、WATCHDOG、INTERNAL、STOPPED；以实际源码为准。

默认无串口探测命令：

~~~powershell
.\.venv\Scripts\python.exe scripts\probe_stm32_link.py
~~~

实机端口和人工关卡看 [总流程](../总流程说明/团队总流程与输入输出.md)。线上句子没有改。电脑端新增持续会话与闭环编排，见上面的 `F103SerialSession`。本轮没有打开真实 COM。

## 5. 明确保留的主机缺口

scripts/center_object.py 与标定脚本仍直接写串口，未接入统一运动关卡；居中尝试耗尽后可能喷水，回复丢失后的补关流程也未修。它们并未自动调用 TO_NEEDLE/TO_SCOPE，标定/相机索引还有现场耦合。

`F103SerialSession.run_step_then_pump` 已经做到：同一条已打开的连接上，步进失败就不喷，异常后可以 STOP。它已接到新闭环入口；`scripts/center_object.py` 仍未收进同一关卡。名义 7680 步仍不是实测偏移，正式路径不发 `TO_NEEDLE`。当前可称 Mock 软件闭环，不能称真实清洗有效。STOP 现在有界读取被中止动作 ERR 后，要求 STOP 自身 ACK/DONE，并保留原文；排空 I/O 失败会关闭并释放会话占用。
