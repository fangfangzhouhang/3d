# 团队入门指南：两小时看懂项目并完成第一次运行

## 1. 一句话认识项目

我们在做一套显微表面智能软件：先拍清楚，再找污渍，再决定处理哪里，最后重新拍摄判断是否真的变好。

当前三人只负责视觉和上位机软件；机械、STM32固件和真实喷洗不在当前交付范围。软件保留接口，但不能假装硬件已经完成。

## 2. 用“医院检查—治疗—复查”理解系统

- A像检验科：准备可信样本和数据，未来还负责训练模型。
- B像影像科：从图片判断异常在哪里、有多大。
- C像治疗计划软件：选择处理点、安排路线，并让模拟控制器演练。
- 动作后复检像复诊：设备回应了不等于问题解决，必须重新观察。

```text
A 数据与模型 → B 视觉测量 → C 目标与控制仿真 → 前后复检和记录
```

## 3. 第一个小时：建立共同理解

### 0～15分钟：阅读四份文件

1. `AGENTS.md`；
2. `project_state.yaml`；
3. `docs/README.md`；
4. `docs/team/三人分工与文件所有权.md`。

读完后必须能回答：当前软件证据和硬件证据分别是什么等级？

### 15～30分钟：看目录

```text
data_learning/      A
vision/             B
control_system/     C
contracts.py        共享
ports.py            共享
```

每个人打开自己的目录和测试目录，找到当前存在的文件。不要从 `legacy/` 开始学习。

### 30～45分钟：理解八个核心对象

在术语词典中查：Observation、StateEstimate、ActionRequest、SafetyDecision、ExecutionReceipt、VerificationResult、Episode、FailureRecord。

记忆口诀：

> 看见不等于知道，申请不等于允许，收到不等于完成，执行不等于成功。

### 45～60分钟：画流程

不看文档，手画：

```text
图片 → 质量 → mask/面积/中心 → 状态 → 目标/动作 → 回执 → 后图 → 结果
```

在每个箭头上写出负责成员。画不出来就回到系统架构说明。

## 4. 第二个小时：在自己电脑运行

### 0～15分钟：检查Git和环境

```powershell
cd D:\大创\3d\MicroCleaningVision
git status
.\.venv\Scripts\python.exe scripts\check_environment.py --profile mock
```

没有 `.venv` 时按开发环境教程重建，不要从Git或别人电脑复制虚拟环境。

### 15～30分钟：运行全部软件测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s test -p "test*.py" -v
```

测试通过只说明软件回归正常，不说明相机、STM32或清洗成功。

### 30～45分钟：运行入口

```powershell
.\.venv\Scripts\python.exe main.py
```

入口只生成Mock回合，并明确打印没有访问真实硬件。

### 45～60分钟：运行自己的测试

## 5. 三个人当前分别做什么

### A

第一批USB显微镜图片、采集清单、少量人工标注。设备暂时不可用时，先练习质量工具、标注和清单。

### B

不等A，先用合成色块实现HSV、mask、面积和中心。A数据到位后再做真实评价。

### C

不等B，先用合成mask实现目标点、路线和像素级Dry Run。真实STM32协议到位前只使用FakeSerial。

完整步骤见团队任务看板和个人手册。

| 概念 | A | B | C |

## 7. 每个人必须能回答的十个问题

1. 项目最终要形成什么闭环？
2. 当前为什么还不是硬件闭环？
3. A、B、C各自交付什么？
4. Image为什么不等于State？
5. 像素坐标为什么不能直接当毫米？
6. ACK为什么不等于清洗成功？
7. 没有上游数据时怎样继续？
8. 为什么不马上训练YOLO？
9. `.venv`为什么不能提交Git？
10. 自己的核心、扩展和备用任务分别是什么？

## 8. 第一次任务完成标准

- 能独立运行自己的测试；
- 只修改自己的顶层目录；
- PR中写清输入、输出、证据和未验证内容；
- 能向另外两个人演示自己的输出；
- 不使用“应该可以”“基本完成”代替运行证据。
