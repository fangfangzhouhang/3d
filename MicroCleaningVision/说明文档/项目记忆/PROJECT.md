## 2. 项目目标与第一个实验

MicroCleaningVision 研究机器怎样观察微观表面、找到待处理区域、执行受限动作，再用真实图像检查处理效果。当前先把显微成像、污染识别、路径和清洗接成一条可重复的链。长期积累的是 `当前状态 → 采取的动作 → 后续结果`，而不只是图片和标签。

第一验证场景**计划**采用 PLA 平面试片和可清除的模拟污染。材料、污染配方与清洗液是否稳定适用，尚未有完整实验记录；不能写成已经验证。设备已知是 U500 USB 数码显微镜，团队没有工业相机。板子当前为 STM32F103C8 系列实验板，不再以 F401 为当前主线。

第一条合格闭环的输入是有来源、条件和版本的动作前图像；输出是污染测量、批准动作、真实控制回执、动作后图像、结果判断和完整 Episode（一次任务的档案）。首次目标允许固定样本、固定喷头、固定参数、人工批准；先证明一次完整处理，再扩大载物台运动范围并讨论复杂模型。

## 6. 怎样积累有竞争力的成果

我们要形成可展示且可复查的“发现目标—采取动作—证明效果”能力。对大创和竞赛，优先积累四类资产：明确的真实问题；可重复现场 Demo；与简单对照比较的结果及失败；换成员、换电脑仍能解释和复现的证据包。

“微观表面闭环”“按局部污染处理”“结果复检与追溯”目前是研究/创新候选表达。是否新颖、是否比人工或固定全域处理有优势，仍需实验和文献/现有方案核对。不要把 OpenCV、模型或 Agent 的名称当成已证明创新。

“国创赛”的具体赛事全称、年份、组别、时间与规则尚未确认。这里不声称符合某个正式评分条款，也不承诺获奖。最有把握的推进方向是把端到端证据做扎实，具体赛事要求确认后再映射材料。

## 7. 记忆如何保持可信

- 事实以本次查到的代码、原始实验文件和 Git 为证；计划单独标记。软件实现证据与物理效果证据各回答自己的问题。
- 冲突先查证，不因文档更新时间较新就覆盖实测，不因提交标题写“成功”就升级证据。
- 日常命令看[当前总流程](../总流程说明/团队总流程与输入输出.md)与 A/B/C 命令百科；线上协议参数的唯一正文看[串口协议与参数](../硬件组/串口协议与参数.md)。记忆保存边界、理由、证据索引和下一步，不复制整本教程。
- `EXPERIMENTS`、`DECISIONS` 保留历史，失效条目标记“已替代”并链接新条目，不静默改掉失败。
- 一次提交里由指定成员整合公共记忆；其他人提供事实和证据，避免多人同时改同一文件。未经提交/共享的本机输出不能当其他电脑已拥有。
