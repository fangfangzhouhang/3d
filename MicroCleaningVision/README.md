# 显微智能自清洗科研平台（MicroCleaningVision）

这是一个要逐步长成“微观表面智能能力”的科研平台；眼下它还不是一台已经能清洗的机器。团队现在只做一件最重要的事：把一条**小、完整、真实且安全**的闭环跑出来。

> 先让机器在一个固定样品上，安全地“看见—提出动作—执行—复查—留下证据”；再让它逐步变聪明。

## 新同学先看这里

你不需要一上来理解 YOLO、3D、Transformer 或 Agent。先掌握这一条流水线：

```text
拍一张图
  → 判断这张图是否可信
  → 估计污渍在哪里、自己有多确定
  → 提出一个受限动作
  → 安全系统批准或拒绝
  → 控制器报告实际发生了什么
  → 再拍一张图复查
  → 把成功和失败都保存成一条实验回合（Episode）
```

代码中的英文对象名是它们的“程序身份证”，不要随意改名；文档会同时给出中文含义：

| 代码名 | 你可以把它理解成 |
|---|---|
| `Observation` | 机器这一次实际看到了什么 |
| `StateEstimate` | 机器据此判断“现在能不能、安全不安全地做什么” |
| `ActionRequest` | 一份动作申请单，而不是可执行命令 |
| `SafetyDecision` | 安全审批：允许、拒绝或请人判断 |
| `ExecutionReceipt` | 设备实际做了什么的回执 |
| `VerificationResult` | 前后对比后，是否真的达到预期 |

## 当前事实：请不要夸大

- **真实硬件能力：E0。** 仓库中没有已验证的相机、标定、STM32、泵/喷头或真实清洗实验。
- **软件能力：E1（仅模拟）。** 默认程序只跑一个无依赖的模拟闭环，绝不会打开相机、串口、泵、电机或喷头。

换句话说，当前 JSON 是“软件流程演练记录”，不是“清洗成功证明”。这条边界是科研诚信，也是安全底线。

## 可以放心运行的模拟闭环

```powershell
python main.py
python -m unittest discover -s test\mcl -p "test_*.py" -v
```

运行后会在 `output/mock_episodes/` 生成模拟回合记录。它用于检查接口、拒绝路径与日志是否连通；不产生任何真实硬件动作。

## 目录速览

```text

docs/               团队共识、实验规程、任务和科研记录规范
skills/             可反复执行的协作方法
```

写代码前，先读 `project_state.yaml` 与 `docs/10_团队任务看板.md`。任何真实硬件接入都必须经过人工关卡（Human Gate）和单独评审的确定性适配器；没有例外。
