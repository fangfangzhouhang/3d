## 1. 启动与完整操作

在项目目录运行：

```powershell
cd D:\大创\3d\MicroCleaningVision
.\.venv\Scripts\python.exe -m demo.closed_loop_station --mock --workbench --mock-scenario workbench-mixed
```

基础依赖仍为 Tkinter、NumPy、OpenCV；真实串口还需 pyserial。HTML/CSV 和浏览器打印不需要 ReportLab。旧 `--mock` 不加 `--workbench` 时仍是自动确认的纯命令行验收入口；自动确认仅适用于合成测试。

| 页面 | 用户操作 | 系统实际处理 |
|---|---|---|
| 封面 | 填样品、操作员，点击开始检测 | 新建独立运行目录，启动相机线程；封面阶段不打开 COM |
| 实时检测 | 看实时显微图，空格/采集按钮 | 保存新前图，运行原分割和候选提取；按钮不是喷洗授权 |
| 目标审核 | 点击图像或列表，确认/排除/待复核，补框 | 保留稳定 S 编号、原因和操作日志；排除及待复核不会进入队列 |
| 锁定与开始 | 查看每块去程/回程、时长及定位限制，再锁定 | 原子保存全候选与冻结快照，核对总预算；开始只启动原执行流程 |
| 清洗监控 | 每次确认移动、重合/喷洗、回程、复检、下一块 | 实际 MOVE 阶段自动跳转；首次参考与实时图并排，金色标明当前 S；中文解释日志和进度由实际阶段驱动 |
| 结果与报告 | 选目标、看前后图/Mask/放大、人工复核，选导出/打印 | 原记录自动保存；HTML、CSV 或打印由用户明确选择，结束不自动关闭窗口 |

示范：确认 S0001/S0002，排除 S0003，锁定，再开始。按每次确认卡批准当前请求；遇到前图/后图等待时按空格。合成混合场景只产生 2 次 PUMP，完整名单仍为 3 行；S0001 未检出前景但需核对，S0002 有残留，S0003 排除，最终质量 FAIL。不是实物清洗证明。

导航只改变当前查看页面，不重新发令。锁定后回看目标列表只读；返回封面时“返回当前任务”继续同一任务。重新采集仅在 DRAFT 可用：旧草稿以 SUPERSEDED 原因取消并留档，再建立新 task_id。S 身份是 `(task_id, S编号)`。

## 2. 人工补框与定位

在审核页打开“人工补框”，只在首次冻结图上拖拽非空区域。画布按原图等比居中缩放；留白不产生目标。框、处理点和编号保留原图像素坐标，再复用已有规划和标定转换，不能把鼠标坐标直接当步数。

人工区域若超界、与已有目标重叠、缺少有效规划/标定、或只能生成扫描动作，不能确认执行。可执行名单仅含 CENTER_POINT。框面积标记为人工处理区域面积；不会充当真实污渍基线或自动生成“去除率”。执行多个人工区域时还要求当前视野/处理点确认。

下一算法目标执行前重新抓前图；必须唯一匹配首次目标，质心漂移不得超过工作台策略的 2 px。该门槛是软件保护，不是已测定位精度；不满足时 HUMAN 停止，保留冻结坐标，不自行追着新位置发令。运行中出现的新区域不加入锁定名单。

## 3. 停止、异常与进度

顶部“停止 / 取消任务”、非文本输入中的 Q、Esc、运行中关窗均设置同一个取消信号。STOPPING 表示正在收尾，不等于设备已经停止。UI 不开第二个串口；现有设备所有者处理 STEP STOP / MCV1 STOP，并保存回执。运动完成性未知时原位置账本标为未知，禁止继续使用。

串口读取采用 50 ms 可取消片段，保持原总超时，收到完整行才交给协议解析；不完整回复保存为 `rx_partial`，不记成 DONE。STOP 事务本身有界收尾，不被同一次取消中断。驱动的打开/写入/相机 read 仍受驱动和原超时限制；软件按钮不能替代物理急停。没有 STOP 回执时必须按现场停机规程处理，不能把按钮点击作为停止证据。

上方目标进度是“已处理/锁定目标数”，不等于合格比例。阶段动画只表示当前操作正在等待/执行，不伪造百分比。拒绝确认不会默认为 YES。回复绑定当前请求，旧回复或重复点击不生效；同一时刻只允许一个设备任务。

已有 PUMP DONE 在取消回程/拍照/后续失败后仍保留；报告显示输出完成但任务中止/质量待定。关窗等待设备线程留档；报告导出失败不会改变硬件结果，可重新导出。

## 4. 质量与报告

流程状态、发送尝试、ACK、DONE、回程、可比较性和质量分别记录。质量优先级：INCOMPLETE → FAIL → REVIEW_REQUIRED → PASS。至少一个获确认目标且所有要求目标有可靠合格证据才能 PASS；全部排除、无候选、待审核或缺证据都不能凭流程 SUCCESS 通过。

原视觉规则的 0.80 是回放阈值，未验收为实物洁净标准。匹配要求 20% 重叠；很少的残留可能无法匹配。空 ROI 的原算法去除率仍保存，证据层不会把“未检出”自动当“已洗净”。表面损伤未评估。receipt 中时长/压力当前复制请求值，报告写请求时长、实测未记录，压力不臆定为 bar。

人工复核须填写操作员、结论、依据，并引用实际前后图。保存追加 `quality_review`，原 verification 不改写；REVOKED 追加撤销记录。人工说明不能补造缺图、缺回执或未完成动作。新的导出会读取最新有效复核并创建新的报告版本，已有报告不覆盖。

结果页可选：HTML（默认浏览器查看）、CSV（UTF-8 BOM，适用于中文 Excel）、HTML+CSV、打印/另存 PDF。打印按钮先生成可打印 HTML，再打开浏览器打印对话框；用户选择打印机或 PDF 保存目的地。基础界面无需 PDF 包。本版不提供 ReportLab 直接 PDF 导出。

```text
output/closed_loop/station_时间_随机ID/
  run_config.json               # 原配置 + 操作员/样品/源码身份/判据
  task_manifest.json            # 全候选、决定、锁定名单/几何与哈希、目标状态
  review_log.jsonl              # 编辑与质量复核历史，追加不覆盖
  cycle_NNN/                   # 原 pre/post、Mask、geometry、execution、verification、Episode
  serial.json / progress.json / summary.json / failure.json
  reports/report_时间_随机ID/    # 仅用户选择后创建
    index.html / task.csv / targets.csv / attempts.csv / assets/
    report_manifest.json        # 导出格式、统计、判据、产物哈希
    report_error.json           # 若此版本导出失败
```

历史入口选择包含 summary.json 的任务目录，只读查看和导出。支持新侧文件、旧 closed_loop、旧单帧 summary/Episode、部分损坏或中止目录。未知审批/操作员/统计写未记录，不补造成已确认。图片只允许本任务内引用；迁移后的旧绝对路径须用原哈希验证。Episode 兼容原 Windows 文本换行哈希与字节哈希。

## 5. 真实设备入口

以下是模板；路径、相机编号、COM 和固件/接线身份须由现场确认。运行软件开发测试不构成实物动作授权。

```powershell
.\.venv\Scripts\python.exe -m demo.closed_loop_station --real `
  --camera-index <已确认编号> --serial-port <已确认COM> `
  --stage2-calibration <实测电机标定JSON> --nozzle-offset <有符号偏移JSON> `
  --path-placeholders <已复核配置JSON> --arm-stage2-xy `
  --arm-pump --confirm-pump --max-cycles 1
```

去掉两个泵武装参数则仅作去程/回程调试，不做清洁复检。真实入口默认使用新工作台，必须先人工审核和锁定。原运动软边界 ±10000 步、报文每轴 20000 步、短喷 100–500 ms、一次性授权令牌、MCV1 预检、有符号偏移只补一次全部保留。当前 `firmware/common/main.c` 急停读 PB12，旧材料 PB2 只保留为历史；软件不能确认当前板子已经烧录这一源码。

## 6. 模块分工与验收

| 负责人 | 负责的具体输入/输出 |
|---|---|
| 软件集成 / C | runtime 的唯一设备线程、任务冻结、事件、取消、报告读取/导出，维护本手册与 Mock 回归 |
| 操作员 / 项目负责人 | 样品、操作者、候选决定和当步授权，试用导航/报告，保存现场完整证据目录 |
| B 视觉 | 提供同条件前后图和人工真值，验证匹配失配/无前景/面积规则，决定科学质量判据；本次未改 B 算法 |
| H1 | 提供同次固件/接线、实际短喷、STOP 和急停证据，测量输出时长/覆盖；不以 DONE 替代测量 |
| H2 | 实测方向、步距、有符号偏移、回程误差与行程；C 消费版本化标定，UI 不自行改参数 |

`demo/station_window.py` 管理主窗口和主线程事件；`workbench_views.py` 管理五页/像素画布；`workbench_runtime.py` 管理相机、设备线程和报告后台作业。`task_model.py` 管理决定和冻结；`cleaning_loop.py` 复用原编排；`hardware_executor.py`/原 serial 保持动作授权与回执。`result_evidence.py` 是 UI/报告统一判定来源；reporting 从原档案读取，不重新执行硬件。

验收测试覆盖候选锁定/空名单/磁盘失败、稳定编号与原像素映射、原闭环兼容、取消发生于去程/短喷/回程等待或 DONE 后、主事件循环心跳、3→2→3 贯通、残留/失配/排除/人工复核/缺图/坏 JSON/迁移/导出失败。完整测试日志和截图在本机 `D:\大创\tmp\workbench-*.log` 与 `output/workbench_qa/`，输出未入 Git；结果数字以最新回归记录为准。

后续真实验收仍需 H1/H2/A/B 的同任务证据。当前交付是 E2 软件集成，不升级为 E3 硬件闭环或 E4 清洗效果对照。
