# 串口协议与参数

电脑和固件只认这一份。改步数、引脚或串口句子时，先改这里，再改代码。

同一块 STM32 同一时刻只能烧一份程序。喷水用 `firmware/keil/f103-stage1.uvprojx`，步进用 `firmware/keil/stage2-stepmotor.uvprojx`。两条协议不能写在同一次串口会话里。

`firmware/stage2-stepmotor/README.md` 里仍有只发 X、`STEP_OK v0.2`、共阴极的旧句子，以本文件为准。

## 1. 两边相同的串口参数

| 项目 | 值 |
|---|---|
| 当前实验板 | STM32F103C8 |
| 串口 | USART2，PA2 = TX，PA3 = RX |
| 波特率 | 115200 8N1，ASCII |
| 行结束 | 固件认 `\r` 或 `\n`。电脑发送 `\r\n` |
| 日常连线 | USB 转 TTL。不要扫描 COM 口，填设备管理器里看到的那一个 |

烧录用 ST-Link。只有一个 USB 口时，ST-Link 和 USB 转 TTL 互换。烧录前断开 12V 和 24V。烧完拔掉 ST-Link，再给驱动器或泵上电。

## 2. 步进 Stage 2

实现：`microcleaning/control_system/serial/stage2_protocol.py`、`stage2_link.py`、`planning/stage2_axes.py`，固件 `firmware/stage2-stepmotor/common/main.c` 和 `driver/stepmotor.c`。

### 机械和电

| 项目 | 值 |
|---|---|
| 驱动器 | 两台 DM542，共阳极 |
| 阳极 | 两台的 PUL+、DIR+ 接到 STM32 的 3.3V，不要接 5V |
| 地 | STM32 GND、两台 DM542 GND、24V 地接在一起 |
| 电机电源 | 24V 只进 DM542 的 +V |
| 使能 | ENA+、ENA- 不接 |
| 细分 | 1600 步/圈（SW5 开，SW6/SW7/SW8 关） |
| 导程 | X、Y 都按 5 mm/圈 |
| 步距 | 320 步/mm。电脑端 `microstep` 填 1，不要再乘 16 |
| 画面比例 | 0.01 mm/像素，占位值，还没有标定 |
| 默认脉冲频率 | 500 脉冲/秒。一个完整脉冲是拉低再拉高，定时器中断频率是 1000 Hz |
| 频率范围 | `SPEED` 允许 10–20000 Hz。路径发送程序不发 `SPEED`，按 500 Hz 等待 |
| 单条命令最大步数 | 20000 |
| 一帧发送上限 | X、Y 各自最多 1600 步。超出的段整段留下，不跳段 |
| 一行上限 | 64 字节 |

方向电平（阳极是 3.3V）：DIR 脚低 = `FWD`，DIR 脚高 = `REV`。脉冲脚空闲为高，光耦关断。

| 轴 | 脉冲 | 方向 | 定时器 | 对应画面 |
|---|---|---|---|---|
| X | PA6 → PUL- | PA7 → DIR- | TIM3 | 画面左右 |
| Y | PA0 → PUL- | PA1 → DIR- | TIM2 | 画面上下 |

只发 X 步时，动的应是画面左右那台，接在 PA6、PA7。PA0、PA1 是 Y。两台不要并到同一组 PUL/DIR。

### 句子

电脑先发 `HELLO`。回复必须是 `STEP_OK v0.3`。`STEP_OK v0.2` 会被拒绝，并且不会发运动命令。

| 电脑发送 | 固件回复 | 谁动 |
|---|---|---|
| `HELLO` | `STEP_OK v0.3` | 不动 |
| `MOVEXY <Nx> <FWD\|REV> <Ny> <FWD\|REV>` | `STEP2_START X=<Nx> <方向> Y=<Ny> <方向>` | 两轴按各自步数同时开始 |
| `READXY` | `STEP2 X=<已发> BX=<0\|1> Y=<已发> BY=<0\|1>` | 只查询 |
| `PULSE <N> <FWD\|REV>` | `STEP_START N=<N> <方向>` | 只动 X。路径程序不发这句 |
| `READ` | `STEP_SENT=<已发> BUSY=<0\|1>` | 只查询 X。路径程序不发这句 |
| `STOP` | `STEP_STOPPED` | 两轴立刻停 |
| `SPEED <Hz>` | `SPEED=<Hz>Hz OK` | 只改频率 |
| `MOVE <N>` | `STEP_MOVE N=<N>` | 只让 X 正转。禁止使用 |

某一轴步数可以是 0，例如 `MOVEXY 320 REV 0 FWD`。0 步的那一轴不启动。

两轴都以 500 脉冲/秒走。步数少的那一轴先停，另一轴继续走完。这不是先走完 X 再走 Y，也不是按比例插补的斜线。电脑在 `max(Nx, Ny) / 500 + 0.5` 秒内轮询 `READXY`，两轴都空闲才发下一条。超时发 `STOP`。

路径程序发出的每一行都是 `MOVEXY <数字> FWD|REV <数字> FWD|REV`。线上不能出现 `MCV1` 或 `PUMP`。

```text
.\.venv\Scripts\python.exe -m demo.demo_pipeline --from-camera --mode analyze --stage2-xy --arm-stage2-xy --serial-port COMx --camera-index 0
```

`--live` 不能和步进发送写在一起。这条命令不喷水。

## 3. 喷水 Stage 1

实现：`microcleaning/control_system/serial/stm32_protocol.py`。固件是 `firmware/stm32f103/f103-stage1`。字段用竖线 `|` 分隔，前缀 `MCV1`。一行最长 128 字节。

当前 F103 实验引脚：泵 PB0，急停 PB2，蜂鸣器 PB1，指示灯 PA5，ARM 按钮 PB3。这不是 NUCLEO-F401RE 的 PB5 / PB12。

电脑编码水泵时长为 100–500 ms。固件自己还有上限，不能只相信电脑发来的数字。

| 电脑发送 | 固件回复 | 含义 |
|---|---|---|
| `MCV1\|PING` | `MCV1\|PONG` | 通信在线，不表示泵可用 |
| `MCV1\|STATUS` | `MCV1\|STATUS\|ESTOP=<0\|1>\|PUMP=<0\|1>` | 急停和泵输出 |
| `MCV1\|STOP` | `MCV1\|ACK\|STOP` 然后结束回执 | 关闭当前输出 |
| `MCV1\|PUMP\|<action_id>\|<毫秒>` | `MCV1\|ACK\|<action_id>` 然后 `MCV1\|DONE\|<action_id>` | 一次限时脉冲 |
| 拒绝时 | `MCV1\|ERR\|<action_id>\|<错误码>` | 未执行或已中止，泵关闭 |

`action_id` 是 1–32 个字母、数字、下划线或连字符。同一次上电里不要重复执行同一个编号。

`ACK` 只表示收到并接受。`DONE` 才表示动作结束。急停解除后不自动续跑被打断的动作。

错误码：`BAD_FORMAT`、`BAD_VERSION`、`BAD_DURATION`、`ESTOP`、`BUSY`、`WATCHDOG`、`INTERNAL`。

```text
PC  → MCU: MCV1|PING
MCU → PC : MCV1|PONG

PC  → MCU: MCV1|PUMP|A001|300
MCU → PC : MCV1|ACK|A001
MCU → PC : MCV1|DONE|A001
```

探测不打开串口时：

```text
.\.venv\Scripts\python.exe scripts\probe_stm32_link.py
```

实机要显式给出端口，并且不要和步进武装写在同一次运行里。
