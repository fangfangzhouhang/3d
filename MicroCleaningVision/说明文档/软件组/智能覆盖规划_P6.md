## 3. 数据流与输入输出

```text
审核 pre.frame.image + 首次目标完整 Mask / 人工矩形
复洗 pre.mask & measurement_domain（取最大残片之前）
复检 post.mask & measurement_domain（独立recheck目录）
    → freeze_source / WorkbenchCoverageSource
    → 当前目标与帧绑定的 CoverageDataset
    → 显式 FootprintProfile → P1 kernel → P2 planner/metrics
    → P3 visualization → P4固定输入Toplevel → 工作台只读预览
    → 用户点击保存 → 独立归档 + binding.json → 可选质量报告内容
```

`freeze_source`：输入task_id、folder、target_id、stage、cycle/recheck、frame_id、BGR原图、全尺寸二值Mask、mask_kind、原metadata和输入校验状态；输出WorkbenchCoverageSource。图像转RGB且与Mask均为bytes支持的不可变数组；binding以规范JSON字符串冻结，公开读取返回新dict。原文件SHA与RGB像素SHA分别保存，不能混用。源入口：[适配器](../../demo/workbench_coverage.py:35)、[首次冻结](../../demo/workbench_runtime.py:363)、[全残留观察器](../../microcleaning/control_system/orchestration/cleaning_loop.py:549)。

`WorkbenchCoverageSource`：dataset、folder、binding_json；identity为绑定内容摘要。绑定包含coordinate_frame=image_px、shape_hw、target_id、mask_kind/area_kind、source_ref、frame_id、image_ref/image_sha256、segmentation_sha256、mask_sha256、task_id、stage、cycle、recheck、observation_id、captured_at、roi_segmentation_sha256、input_valid/input_reasons。

`WorkbenchCoverageHub`：Tk主线程持有，每目标只缓存initial和latest两张，不随无限复洗保留所有历史图。窗口换目标/帧会销毁旧弹窗回调并失效预览；同轮重复或更旧源不能顶替最新源。整个工作台只用一个LatestCoverageWorker：一条正在计算、一条可替换待计算、一条最新响应；跨弹窗generation单调递增，旧回调还检查panel身份和source.identity。关闭弹窗保留有效参数，包括160ms防抖期间尚未提交的修改；无效参数回退最后有效Profile。整工作台关闭才关闭共享worker。弹窗不启用grab_set或第二个mainloop，停止/取消仍能从主工作台操作。

`StandaloneCoveragePanel`：默认仍为独立面板。可选input_locked、on_view/on_invalidate/on_close、exporter_factory/on_exported、initial_generation/owns_worker、layout_scale/source_description由集成人传入；不导入workbench/硬件。`parameter_snapshot()`仅解析参数，不提交任务。目标/直径/策略改变需要重新规划；图层/逐点播放/窗口缩放只重绘；执行链完全不消费这些参数。

`export_bound_preview`：输入点击时冻结的RGB、CoveragePlan、原约束、渲染选项/步数、运行目录、binding及accepted_generation；输出新的目录路径。先核对本任务源元数据/原图与Plan input，再保存并完整重算重绘P3归档，最后发布binding.json。每次独立UUID目录，不覆盖旧归档：

```text
station_*/coverage_previews/<uuid>/
├── binding.json                  # 最后原子发布
└── archive/                      # P3固定四文件保持不变
    ├── coverage_preview.json
    ├── coverage_overlay.png
    ├── source_image.png
    └── coverage_masks.npz
```

binding另含schema=workbench-coverage-v1、generation、plan_id、source_pixels_sha256、manifest_sha256、validation=deterministic_replay_at_export、simulation=true、comparison_status=hypothetical_plan_was_not_executed及三个false标志。三个标志为executable、feeds_action_request、send_to_controller，任何true都拒绝。缺binding或manifest的中断保存只列为不完整，不能算成功；保留原始文件，供检查恢复。

`read_coverage_evidence`：输入run root、task_id和目标名单；输出(previews, issues)。检查task/target、源帧/文件SHA、合法固定stage路径、cycle/独立recheck来源、Mask语义、Plan ID、manifest/产物SHA及路径逃逸/重定向。读档只做有限资源哈希检查，不解压NPZ/重做规划；JSON上限1/8MiB、单产物64MiB、一次最多256目录是可选证据资源限制，与人工复洗次数无关。SHA是损坏检测，不是签名，不能保证有人同步改写所有摘要后的来源真实性。

`read_run`：旧schema新增coverage_previews和coverage_preview_issues，目标行新增对应预览列表。旧档案缺预览返回空列表。预览问题不加入原evidence_issues，不改变quality_status/report_ready；保存后在任务空闲时后台刷新当前结果且不强制跳页。HTML增加独立模拟区域；CSV只有存在完整预览时才增加coverage_previews.csv，旧task/targets/attempts内容保留。整份Plan指标与当前播放前缀指标分列，实际清除预测准确率为null。

## 4. 完整 Mask 和旧行为的保护

复洗输入是冻结measurement_domain内的全部残留，完整指该现有测量域内，不保证域外未知污染。测试中两个残片共83px均进入覆盖规划，旧执行仍选48px最大残片，邻居S0002不进入本Mask。空/边界/位移/可比性无效状态保存并显示；高覆盖数字不能覆盖输入无效提示或放行复喷。

首次pre_mask.png会在执行时被ROI分割写回，预览在审核时已冻结原数据；后续不以这个可变路径冒充首次Mask。重拍后图使用cycle_NNN/recheck_MMM/post.json/png，不能读最新镜像post.png错绑旧复检。

原CleaningPlan、CENTER_POINT、EXECUTION_STRATEGY_UNSUPPORTED_V1、动作确认、STOP/取消、回程、位置账本和四种复检选择均保留。CleaningLoop的on_coverage_input默认None；Workbench明确启用观察器。回调复制图/Mask/metadata，抛异常不改变核心数据或决策；没有CoveragePlan→ActionRequest转换。未启用多驻点执行或边走边喷。
