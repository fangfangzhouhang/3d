## 2. 当前真实存在的主线代码

```text
microcleaning/
├── contracts.py
├── ports.py
├── data_learning/       A：质量、回放图片、数据集清单
├── vision/              B：HSV污染分割、状态、面积复检
└── control_system/      C：分段路径、固定申请、安全下限、FakeSerial、回放
```

当前新增的是可运行的软件算法和集成证据；硬件证据仍然没有增加。

## 3. 当前通过测试能证明什么

- 接口对象、模拟失败路由和Episode存储可回归；
- 回放相机能真正解码本地图片文件；
- 文件缺失或伪图片会被拒绝；
- 没有标定时状态估计不会产生毫米目标；
- 未准备好、越界、篡改或过期的模拟动作会被拒绝；
- FakeSerial能模拟成功和超时回执。

不能证明：

- USB显微镜采集稳定；
- 质量阈值适合真实显微图；
- HSV能识别PLA模拟污染；
- 前后图片可以真实配准；
- 目标点可转换成工作台坐标；
- STM32、泵、电机或喷头执行；
- 真实清洗有效或无损伤。

## 4. 当前最大瓶颈

没有团队采集的真实USB显微镜图片、采集清单和人工标注。因此B不能完成真实算法评价，C也没有真实mask可以集成。

最短下一步不是新增模型，而是：

```text
A采集并标注小样本
→ B完成HSV最小基线
→ C完成mask到目标点的像素级仿真
→ 三者第一次集成
```

## 5. 旧仓库事实

`legacy/`保存早期相机、检测、规划、通信、模型和3D代码。历史审计发现大量核心函数为桩或未验证，并存在直接规划到控制器、接口类型不匹配、缺数据/标定/固件等问题。当前主线不导入它们。

旧详细文档位于 `docs/archive/legacy_docs/`。它们值得借鉴阶段感、任务表和新人步骤，但其中固定YOLO→双目→3D路线、旧路径和依赖声明不再适用。
