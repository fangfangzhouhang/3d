# 团队任务看板：先把一条小闭环做实

## 先学会使用任务卡

不要把任务卡当“待办清单”。每张卡都在回答六件事：**为什么现在做、谁负责、做出什么证据、依赖谁、失败时怎么办、何时可以停。**

今天不知道从哪开始时：A 先拿 A-P1-01，C 先拿 C-P1-01，B 先读取 C 的物理边界并准备 B-P1-01 的伪串口测试。三人一周至少用 15 分钟把各自证据放进同一条闭环里看一次，不能等到“各自都做完”。

所有工单使用 Git 仓库根目录 `D:\大创\3d`；不要在 `MicroCleaningVision` 内部放置第二个 Git 仓库。仅在团队确认基线为最新后，才创建分支。估算时间不包含等待硬件或人工关卡的时间。

| 字段 | 详情 |
|---|---|
| 所有者 / 分支 | A / `feat/perception-observation-v0` |

| 输出 / 验收 | 十个未被覆盖的原始文件 + 哈希清单 + 设置表；模式测试通过；另一位成员能复现其中一次拍摄。 |

## PR 模板

```markdown
## 这次解决的具体问题 / 失败是什么？
## 新增了什么能力？证据等级从哪里到哪里？
## 接口或版本有没有变化？
## 用什么测试、日志、图像或实验记录证明？
## 它怎样帮助或阻碍最小闭环？
## 新风险是什么？如何回滚？
```
