# 团队入门指南：先学会读懂一条软件回放

## 一句话认识项目

我们正在做一套显微视觉软件：它先判断图像是否可信，再测量污染、提出受限动作、模拟控制器回执，最后用后图复检并保存完整记录。

当前三人都属于视觉软件团队。机械和 STM32 固件不在本阶段职责中；软件通过端口（`Port`，软硬件之间约定的方法）为它们预留位置。

## 用“实验室助手”理解数据流

```text
Observation       眼睛这次拍到了什么，图像是否合格
StateEstimate     根据图像，系统相信污染在哪里、有多不确定
ActionRequest     一份动作建议，不是硬件命令
SafetyDecision    是否允许这个建议进入控制端
ExecutionReceipt FakeSerial 返回的模拟回执
Verification      后图是否可比、污染是否减少
Episode           整次软件实验的档案
```

四个关键区别：图像不等于状态；动作申请不等于命令；ACK 不等于清洗成功；面积减少也只有在前后图可比时才有意义。

## 第一天怎么开始

1. 读 `AGENTS.md` 和 `project_state.yaml`。
2. 运行 `python -m unittest discover -s test\visual_loop -v`。
3. 打开 `docs/team/三人分工与文件所有权.md`，找到自己的文件。
4. 读自己的任务手册，复述上游输入、自己的输出和下游消费者。
5. 用一个测试做最小修改练习，不修改共享契约。

## 当前该学和不该学的深度

| 概念 | 当前深度 | 最小动手任务 |
|---|---|---|
| OpenCV | A/B 会用读图、HSV、形态学和轮廓；C 理解输入输出 | 对一张标记物图输出 mask 和面积 |
| 图像质量 | A 实现；B/C 能解释为何阻断下游 | 让失焦图产生 `FOCUS_LOW` |
| 图像配准 | B 实现；A 理解采集影响；C 理解失败路由 | 对齐一组轻微平移的前后图 |
| dataclass/JSON | C 实现；A/B 会读写自己的接口对象 | 保存并检查一条 Episode |
| 串口协议 | C 只学上位机接口、ACK、超时、错误码 | FakeSerial 超时产生失败回执 |
| CNN/YOLO | 当前只理解何时需要 | 不作为本阶段交付 |
| Transformer/3D/World Model | 只理解长期位置 | 不建目录、不写实现 |
| Agent/Skill | 会用 AI 做有限任务和独立审查 | 使用项目 Skill 完成一张任务卡 |

## 共同验收

每个人都应能解释：自己的输出如何被下一人消费；质量不足怎样停止；当前测试证明了什么；为什么不能宣称真实硬件或清洗已完成。
