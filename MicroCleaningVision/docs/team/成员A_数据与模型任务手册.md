# 成员 A 长期任务手册：数据与模型负责人

## 1. 你的角色到底有什么用

你不是“负责拍照的人”。你负责把真实世界变成算法可以学习、团队可以复查的证据。

```text
真实样本
→ 可重复拍摄
→ 有编号的原始图片
→ 人工标注和数据划分

→ 必要时训练并保存模型
```

如果A的数据不可靠，B只能在错误图片上调参，C得到的目标坐标也没有意义。

## 4. 当前核心任务：USB显微镜数据 v0

完整任务卡见 [团队任务看板](团队任务看板.md#3-a数据与模型任务包)。这里解释为什么和怎样做。

### 4.1 先准备实验对象

1. 选择尽量平坦、表面颜色稳定的PLA试片。
2. 给每块试片永久编号，例如 `pla_001`、`pla_002`。
3. 如果暂时没有正式水溶性标记物，可以先拍干净表面和临时彩色目标，但必须在清单注明用途。
4. 不要把不同材料、不同颜色、不同倍率的数据混成一个“训练集”。

### 4.2 固定成像条件

需要记录：

| 项目 | 大白话解释 |
|---|---|
| 设备 | 哪一台手机或USB显微镜 |
| 分辨率 | 图片宽高像素数 |
| 倍率档位 | 当前镜头或软件放大设置 |
| 工作距离 | 镜头到样本大约多远 |
| 光源 | 内置环形灯或外部灯，档位多少 |
| 曝光 | 相机让画面变亮/变暗的设置 |
| 样本方向 | 哪一边朝上，防止前后图旋转 |

最好拍一张装置整体照片，让另外两个人知道图片是怎么来的。

### 4.3 分批拍摄

连续拍100帧不等于100个独立样本。第一版至少分两个采集批次：重新打开软件或重新放置样本后再拍。

第一批至少包含：

- 干净表面；
- 明显彩色区域；
- 较小彩色区域；
- 失焦失败；
- 反光失败；
- 过亮或过暗失败。

失败图片不能删除。它们会告诉团队算法和设备最容易在哪里出问题。

### 4.4 检查真实像素

```powershell
.\.venv\Scripts\python.exe -m microcleaning.data_learning.inspect_images `
  data\raw\usb_microscope\<日期>_A `
  --output output\quality\usb_A_v0.json
```

你必须能解释：

- 拉普拉斯方差只能在近似相同设备、倍率和纹理下比较；
- SHA-256能发现文件是否被替换，不能判断图片好坏；
- 暂定质量阈值只用于链路冒烟测试，不是显微成像标准。

### 4.5 建立数据清单

每张图片至少记录：

```text
image_id
sample_id
capture_session
relative_path
source_device
resolution
magnification_setting
lighting_condition
surface_condition
phase
label_status
notes
```

`phase` 表示动作前、动作后或普通样本。当前人工擦除得到的后图必须标为 `manual_change`，不能写成机器清洗。

### 4.6 完成人工标注

第一版只设两个标签：

```text
contamination   明确认为是模拟污染的区域
ignore          反光、边缘或无法判断的区域
```

沿边缘画多边形；不要只画矩形框，因为B需要比较面积。完成后随机复查至少20%的标注。

## 5. 你的学习路线

### L0：当前必须掌握

| 知识 | 学到什么程度 | 最小练习 |
|---|---|---|
| Python路径与CSV/JSON | 能读写相对路径和清单 | 检查缺失图片和重复ID |
| OpenCV读图 | 知道BGR、灰度、尺寸和通道 | 解码一张USB图片并打印尺寸 |
| 图像质量 | 能解释失焦、过曝、反光 | 对三张失败图写人工说明 |
| 标注工具 | 会画polygon并保存 | 标注5张图片 |
| Git基础 | 会建分支、提交、推送和PR | 提交数据清单程序，不提交原始大图 |

### L1：P1/P2学习

- 数据版本：知道某次实验到底用了哪一版图片和标注；
- 数据划分：按样本/批次隔离，避免相邻帧泄漏；
- 图像配准对采集的要求；
- 模型评价中训练集、验证集、测试集的区别。

### L2：满足训练关卡后学习

- PyTorch数据集和批次；
- 损失函数：训练时衡量预测和标注差距的数值；
- 过拟合：训练图表现很好，换新图明显变差；
- 学习率、随机种子、早停；
- AutoDL环境、数据上传、预算和模型下载；
- 模型卡：说明模型训练数据、用途、限制和版本。

不需要先学Transformer、强化学习或世界模型。

## 6. 什么时候才允许使用AutoDL训练

你有GPU经验，但这项经验应放在证据最有价值的时候。启动前检查：

- HSV存在稳定失败；
- 人工mask足够并完成复查；
- 独立测试集没有参与调参；
- 团队写明模型要解决的失败；
- 本地CPU管线跑通；
- 固定Git提交、依赖、随机种子、数据版本和预算。

第一次GPU实验只做小规模管线验证。先确认训练能复现、输出能被B读取，再扩大数据和轮次。

## 8. AI和人的边界

AI适合：写清单检查器、标注转换、数据划分测试、训练脚本、日志解析和失败假设。

你必须亲自：操作设备、确认样本状态、复查标注、判断数据是否可比较、决定实验是否可信、控制GPU预算。

AI输出代码后，你至少要能回答：输入是什么、输出是什么、失败时会怎样、测试证明了什么。

## 9. 常见失败与处理

| 失败 | 不应该做 | 正确处理 |
|---|---|---|
| 图片模糊 | 偷调低阈值让它通过 | 记录失败并重拍/改固定方式 |
| 反光像污渍 | 删除失败图 | 标记ignore并反馈A/B |
| 数据量太少 | 直接租GPU | 先完成HSV和人工标注 |
| 相邻帧泄漏 | 随机打散所有图片 | 按样本/批次划分 |
| 模型指标很好 | 直接宣布有效 | 在独立测试和端到端回放比较 |
