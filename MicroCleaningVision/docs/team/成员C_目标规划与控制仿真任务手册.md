# 成员 C 长期任务手册：目标规划与控制仿真负责人

## 1. 你的角色到底有什么用

你不是“帮A/B整理结果的人”，也不是“只写CSV和报告的人”。你负责把B测出的污渍位置变成明确的处理目标、移动顺序和可以被控制器理解的结构化动作。

```text
污渍mask/中心
→ 选择目标点
→ 规划访问顺序
→ 坐标转换
→ 动作申请
→ FakeSTM32/未来真实STM32
→ 执行回执
```

A和B让系统“看见”，C让系统知道“下一步准备怎样动”，但真实硬件是否允许执行仍受最低边界和人工关卡限制。

## 2. 你当前拥有的目录

```text
microcleaning/control_system/
├── fixed_rule.py          # 当前固定动作申请
├── governor.py            # 最低动作边界
├── fake_serial.py         # 模拟控制器回执
├── replay_mcl.py          # 软件回放编排
├── episode_store.py       # 回合持久化
└── mock_mcl.py            # 合成回归基线

test/control_system/
├── test_control_system.py
└── test_mock_mcl.py
```

你接下来的核心新增文件不是报告工具，而是经任务批准后的目标点、路线、坐标变换和FakeSTM32程序。

## 3. 你的输入和输出

### 从B得到

- mask或目标区域；
- 污渍面积和中心；
- 坐标单位；
- 置信度与不确定度；
- 是否有目标；
- 无法测量的原因。

### 输出

- 目标点列表和编号；
- 目标点访问顺序；
- 路线可视化；
- 坐标变换结果和误差；
- `ActionRequest`；
- FakeSTM32/真实控制器的 `ExecutionReceipt`；
- 一次软件回放的Episode。

C不能修改B的mask来“让路线好看”，也不能编造A/B没有提供的毫米坐标。

## 4. 当前核心任务：目标点与路线 v0

### 4.1 用合成mask独立开始

不用等待B。测试代码先生成：

- 一个圆形污染区；
- 一个矩形污染区；
- 两个分开的区域；
- 靠近图片边界的区域；
- 完全空白mask。

这些样例只用于控制算法逻辑测试。

### 4.2 第一版目标点策略

不要一开始做复杂覆盖规划。最小规则：

1. 找到每个独立污染区域；
2. 每个区域先选一个中心点；
3. 目标点必须位于图片内部；
4. 无区域则返回空计划；
5. 每个点保存来源区域和坐标单位。

如果一个大污渍只喷中心明显不够，这会成为后续“增加网格点”的真实失败证据，而不是现在预先堆复杂算法。

### 4.3 第一版路线策略

可以从两种简单规则中选择一种并写清：

- 从左到右：最容易解释；
- 最近邻：每次走向离当前位置最近的点。

路线结果必须画在图上：点的编号、连线和起点。路线长度减少只是局部指标，不能自动证明清洗更好。

### 4.4 像素坐标不等于毫米坐标

图片中的 `(300, 200)` 表示第300列、第200行；机械平台的 `(30 mm, 20 mm)` 是物理位置。两者之间需要真实标定。

当前阶段：

- 可以在像素坐标上画目标和路线；
- 可以用人为设定的已知点对测试坐标算法；
- 不可以使用固定比例把模拟结果送进真实硬件；
- 标定版本失效时动作必须停止。

像素计划先作为C内部的预览结果，不能直接塞进只接受 `work_mm` 的 `ActionRequest`。只有真实标定把像素点转换为工作坐标后，才讨论生成动作申请；多点动作需要单独接口提案。

### 4.5 接入现有软件回放

你需要读懂：

```text
fixed_rule.py       产生动作申请
governor.py         检查最低边界
fake_serial.py      模拟ACK/超时
replay_mcl.py       把各步骤串起来
episode_store.py    保存完整回合
```

当前重点不是继续增加安全规则，而是先把目标点和路线做成可测试的像素级预览。标定有效以后，再把工作坐标通过结构化接口接入回放，同时不绕过现有最低边界。

## 5. FakeSTM32和未来串口

### FakeSTM32阶段

你可以定义明确标记为 `SIM_ONLY` 的测试帧，模拟：

- 正常ACK；
- 超时；
- 错误码；
- 重复命令；
- 动作ID不匹配；
- 控制器断开。

ACK只说明控制端回应，不说明表面处理成功。

### 真实串口入口条件

必须拿到：

- STM32固件命令格式；
- 字段单位和字节顺序；
- ACK、错误码和状态含义；
- 超时和安全停止命令；
- 限位、急停和联锁事实；
- 人工批准的第一次硬件操作规程。

没有这些信息时，不打开COM口发送未知字节。

## 6. 你的学习路线

### L0：当前必须掌握

| 知识 | 学到什么程度 | 最小练习 |
|---|---|---|
| 图像坐标 | 会判断x/y方向和边界 | 在图片上画5个编号点 |
| 连通区域 | 知道mask中有几个独立目标 | 为每个区域选中心 |
| 简单排序 | 会从左到右或最近邻 | 画出访问路线 |
| dataclass/结构化对象 | 能读懂ActionRequest | 打印并解释一次申请 |
| 单元测试 | 会构造空目标、越界和多目标 | 证明无目标时不动作 |

### L1：P2/P3学习

- 仿射变换/单应性：用对应点把像素映射到工作平面；
- 标定误差和独立验证点；
- 路径长度、覆盖率和目标遗漏；
- 状态机：系统在等待、执行、失败、停止等状态间怎样切换；
- 串口帧、校验和、ACK、超时和幂等性。

幂等性指重复收到同一动作时，不应该无意执行两次。

### L2：真实硬件阶段学习

- PySerial和端口配置；
- 固件协议合同测试；
- 控制器状态与实际值回执；
- 运动限位、急停、联锁和安全停止；
- 时序和重试预算。

### L3：研究升级

- 多目标路径规划；
- 不同区域大小对应的处理点覆盖策略；
- 根据Episode分析动作与结果；
- 简单结果预测与参数选择。

不需要当前学习强化学习、复杂机器人规划框架或多Agent控制。

## 8. AI和人的边界

AI适合：生成简单路径算法、坐标变换代码、测试mask、FakeSTM32、协议解析和异常测试。

你必须亲自：确认坐标系/单位、理解每个动作字段、检查路线是否合理、核对真实固件协议、参与第一次真实硬件人工关卡。

AI不能猜STM32协议，也不能根据自然语言直接控制硬件。

## 9. 常见失败与处理

| 失败 | 错误做法 | 正确做法 |
|---|---|---|
| B没有mask | 停工等待 | 用合成mask完成目标和路线测试 |
| 大区域只选一个点 | 直接上复杂优化 | 记录覆盖失败，再增加最小网格策略 |
| 像素被当毫米 | 使用固定比例 | 等待标定并记录版本/误差 |
| ACK成功 | 写“清洗成功” | 只写控制器回应，等待后图复检 |
| 未知STM32协议 | 猜命令试发 | 使用FakeSTM32，等待固件合同 |
| C集成失败 | 修改A/B代码 | 将问题退回文件所有者 |
