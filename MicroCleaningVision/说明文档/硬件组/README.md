## 2. 整条链里，我们负责哪一段

~~~text
A 可追溯图片 → B 污染位置/Mask → C 路径与受限动作
                                 ↓ 经明确批准的电脑入口
                        common/main.c
                     ├─ safety / serial：计时、急停、喷水回执
                     ├─ pump：PB0 电平 → 泵控制模块       H1
                     └─ motion：X/Y 脉冲 → 样本托盘     H2
                                 ↓
                       命令回复 / 脉冲计数 / 忙闲
~~~

硬件组不重做识别，不用脉冲计数宣布定位成功，不用 PUMP_ON 或 DONE 宣布洗干净。清洗效果需要 A/B 的真实后图。

## 3. 文件归谁，不按工程名分人

| 所有者 | 主要目录 | 输入 → 输出 |
|---|---|---|
| H1 喷洗 | firmware/pump/，含自己的 tests/ | 经公共状态机决定的开/关 → PB0 输出；人测管路、覆盖与出水量 |
| H2 托盘运动 | firmware/motion/，含自己的 tests/ | 步数/方向/名义偏移 → X/Y 脉冲、计数、忙闲；人测位移和重复性 |
| 公共集成 | firmware/common/ | 串口 + 时间 + 按钮 → 审核、分发、起停、回复及单一 Keil 构建 |

common 包含 main.c、board、safety、serial、keil、tests/scripts 和 compat 旧工程。它不是没人负责的杂物箱：默认 H1 负责本轮公共集成，H2 复核运动/编译影响；实际按工作量调整，一次只一位主改。协议改动还要 C 一起核对。

Keil 是工程/构建入口，不是一项独立业务。旧 STM32F103 Stage 1 保留在 common/compat/stage1/；已写好的安全状态机和 MCV1 协议抽到 common/safety/、common/serial/ 复用，未删除旧工程。

## 4. 本次接通了什么

1. 当前主循环实际读取 PB2/PB3，并调用旧安全状态机；定时输出结果真正驱动 pump_on/off。
2. PUMP ON 保持原回复，但现在固定 300 ms 后关闭，重复 ON 不延期。MCV1 限时喷水、STATUS、PING、STOP 接入同一主入口。
3. STOP、MCV1 STOP、急停和 FAULT 都会停止两轴并关泵。急停解除不自动继续。
4. TO_NEEDLE / TO_SCOPE 通过 sm_start_scope_offset 调用普通 XY 驱动，名义 Y 偏移 7680 步；没有另写一套运动程序。
5. Keil 两份工程的所有源文件和路径已更新；旧工程继续可编译。

合法旧运动句子、115200、STEP_OK v0.3、引脚、频率和计数方式保留；有意拒绝非法数字、忙时覆盖、过长行尾部注入，并处理停止后的挂起中断。不能把修复非法输入称作“所有行为完全不变”。

## 5. 首次烧录前必须知道的变化

PB2 由浮空改为上拉，假设常闭急停触点连接 PB2–GND：正常低，断开高并锁存停止。**不接按钮会阻止动作**。实际接线尚未核对，不要把本页当现有实物完全匹配的保证。PB3 已释放 JTAG 引脚用途，保留 SWD；默认配置并不强制按 ARM。

喷水仍没有流量反馈，位置仍只有脉冲计数，轮询急停仍不等于硬件断电。针头偏移 24 mm / 7680 步尚未标定；移动的是托盘，真实正负方向必须现场测。

## 7. 下一步的并行实干任务

- H1：追踪已有 300 ms / MCV1 定时链，核对 PB0 控制模块和 PB2 急停接线；现场批准后测固定时长出水/覆盖。不要重复造一个泵计时状态机。
- H2：核对两轴方向、步距、实际行程、显微镜到针头的有符号偏移；做小范围正反位移和返回测量。先测量，不直接运行 7680 步。
- 公共：确认编译/烧录版本，先按接线完成停止和输出验收，保留原始回复；H1 主改、H2 复核。
- C 后续：统一电脑端各入口的授权和失败停止，再接入“对中 → 偏移 → 短喷 → 返回 → 后图”。正式 Stage2SerialLink 仍不发 PUMP/TO 命令，不能把固件具备能力写成上位机已自动联动。
