# 软件回放闭环四周路线图

## 最终演示

给定一对显微前后图，系统能判断图像质量、测量污染、提出受限动作、经过安全审批、获得假串口回执、比较后图并保存完整 Episode。

这证明软件链和未来硬件接口准备就绪，不证明真实设备或清洗效果。

## 第 1 周：统一输入和接口

- A 建立图像清单与质量评分框架。
- B 确认污染测量和状态字段。
- C 确认回放、安全、假串口、Episode 主线。
- 全体运行当前测试基线（视觉框架 + Mock 回归）；以命令实际输出为准，不在计划中锁死数量。

出口：每个人能画出完整数据流，并独立运行自己的测试。

## 第 2 周：接入真实图片，不接硬件

- A 收集 30～50 张链路验证图，包含正常、失焦、过曝、阴影和反光。
- B 用 HSV（色相、饱和度、明度颜色空间）完成彩色标记物基线分割。
- C 读取图像清单并生成回放 Episode。

出口：真实图片能走到 State；坏图被拒绝。

## 第 3 周：完成前后复检

- B 实现配准（把前后图对齐到同一位置）和面积变化。
- A 复查图像质量是否足够支持配准。
- C 测试 ACK 超时、断连、审批篡改和缺后图。

出口：至少 5 组前后图完成回放；失败组也留下记录。

## 第 4 周：失败复盘与接口冻结

- 统计主要失败：成像、分割、配准、状态、审批、回放数据。
- 冻结 `mcl-v0` 接口；明确未来真实相机和 STM32 应实现的方法。
- 录制软件演示并更新 README、状态文件和 Skill。

出口：新成员可按文档复现软件演示；团队不夸大成硬件闭环。

## 高级技术门槛

若 HSV 在固定光照下仍因材料颜色、反光或污染形态稳定失败，再设计 CNN/YOLO A/B。若单视角定位误差成为主要失败，再研究第二视角或 3D。任何升级只解决一个已经记录的失败。
