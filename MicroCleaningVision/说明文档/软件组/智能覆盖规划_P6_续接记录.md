## 5. 已形成的实施设计（待编码验证）

数据链：

```text
审核首次输入 / 最大残片筛选前的全部残留 / 同域复检残留
→ 不可变 CoverageDataset + task_id/target_id/frame/轮次/来源绑定
→ 显式 Profile（未知直径为 None）+ Kernel + 原 CoveragePlanner
→ 独立 LatestCoverageWorker（运行1份、可替换待处理1份）
→ 仅 Tk 主线程更新叠加/指标/图层/播放
→ 用户点击保存时冻结同一快照
→ P3 完整归档 + 归档外工作台绑定 → 可选报告
```

- Profile 不提供真实喷头的隐式尺寸。改直径只重建核/驻点/指标/渲染，不重新分割、抓帧或发送指令。修改 measured 直径沿用现有规则变为 assumed 子情景。
- 实时相机帧不能自动换成预览源。拟保留“首次审核 / 本轮前图 / 本次复检后图”等显式来源选择，记录来源阶段；旧请求晚到不得显示在新目标/新帧上。缓存数量须有界，不能随无限人工复洗无限积累图像。
- Tk、相机、设备与 coverage worker 仍各由自己的线程拥有。设备回调仅做有限复制/传递，不在动作线程规划或编码 PNG；后台不操作 Tk。
- 原 P3 归档保持四件：`coverage_overlay.png`、`source_image.png`、`coverage_masks.npz`、`coverage_preview.json`。不要直接往归档根目录塞工作台第五件。
- 拟保存结构为任务目录内 `coverage_previews/<新唯一ID>/archive/<P3四件>`，外层另放 `binding.json`，绑定文件最后发布。只保存到新目录，失败可见；不覆盖旧档案、不递归删除用户目录。
- 绑定草案包含 task/target、stage、cycle/recheck、generation、frame/observation、源图文件/像素哈希、完整目标 Mask 哈希、分割/冻结 ROI 哈希、Profile/Plan ID、完整计划与当前播放前缀、时间/模拟来源及三项 false 标志。字段草案尚未成为实现合同。
- 所有 `CoveragePlan`、预览和归档继续 `executable=false`、`feeds_action_request=false`、`send_to_controller=false`。不修改 task 的旧锁定执行 Plan，也不转换 ActionRequest。
- 报告中的多驻点 coverage 是假设方案；实际仍单点执行，所以不能拿后来残留计算该假设方案的预测准确率。保留预测与实际两个独立字段；历史无预览的档案仍可正常读。
- 校验完整归档的重规划较重，不在 Tk 或活动动作线程进行。报告快速引用校验与完整重放的分工仍需实现时明确，不能用只检哈希冒充已完成确定性重算；哈希不是来源认证。
