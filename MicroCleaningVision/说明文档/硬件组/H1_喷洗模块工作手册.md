## 1. 你的模块有什么用

一句话：**把公共状态机决定的开/关变成泵控制电平，并用实际测量回答“喷多久、喷了多少”。**

你不负责识别污染，不判断清洗成功，不计算托盘路径。你的结果会影响 C 能不能合理安排“先移到哪里、再喷多久”，也影响 A/B 怎么解释清洗前后照片。

| 输入 | 你做的事 | 当前输出 | 谁使用 |
|---|---|---|---|
| 公共入口调用 `pump_init()` | 设置 PB0 并保持关闭 | 控制输出为高电平 | 全系统启动 |
| 公共入口收到 `PUMP ON` | 共享状态机申请 300 ms，按输出调用 `pump_on()` | PB0 低，到时自动关；公共入口回复 `PUMP_ON` | 电脑端动作流程 |
| `PUMP OFF` 或公共 `STOP` | 调用 `pump_off()` | PB0 高；公共入口回复对应结果 | 电脑端关闭/中止流程 |
| 后续实测喷射数据 | 测量固定条件下的覆盖和出水量 | 条件、测量值、误差与失败记录 | C 选参数，A/B 分析前后图 |

**“输出已打开”不等于“水已到达目标”。** 当前没有流量传感器；代码也不提供真实出水量。

## 2. 你负责哪些文件

所有路径从项目根目录 `MicroCleaningVision` 开始。

| 文件 | 作用 | 所有权 |
|---|---|---|
| `firmware/pump/pump.c` | 泵初始化、打开、关闭的实际实现 | H1 主责 |
| `firmware/pump/pump.h` | 告诉其他代码“可以调用哪些函数” | H1 主责；改签名前与调用者确认 |
| `firmware/pump/tests/test_pump.c` | 在电脑上验证泵代码，不实际喷水 | H1 主责 |
| 本手册 | 解释你的当前代码和后续任务 | H1 主责 |
| `firmware/common/main.c`、`firmware/common/keil/`、`firmware/common/tests/test_command_flow.c` | 两模块共同入口、构建和一起工作的测试 | 共享；一次一位主改 |

公共代码路径相对于 `firmware/common/`；Keil 工程在 `firmware/common/keil/`。H1 默认主改公共集成，H2 复核；不是各自新增入口。不修改 H2 的 `stepmotor.c/h`，也不自己新增第二个 `main.c`。

## 3. 现在代码实际能做什么

```c
void pump_init(void);
void pump_on(void);
void pump_off(void);
```

- `init` 是初始化：先把输出寄存器设为高，再配置输出模式，避免初始化过程短暂输出低电平。本轮测试检查了这个顺序；实际上电过程仍需实测。
- `on/off` 是开/关。在当前接法中 PB0 低电平有效，意思是“低电平触发控制模块”。换模块后不能默认极性不变。
- 泵低层模块不占 TIM2/TIM3，不与电机抢定时器。限时逻辑在 `common/safety/control_core.c`，公共主循环使用毫秒时钟轮询，不在 `pump.c` 重复造一套计时器。
- 泵函数不回复串口，回复由公共 `main.c` 发送。这样不会出现两个模块同时抢串口、拼乱消息。

## 4. 今天可以独立完成什么

### H1-01：跑懂真实泵代码，而不是只看测试数量

输入：当前 `pump.c/h`、公共入口、泵测试。无需摄像头、无需插开发板。

在 PowerShell 中进入项目：

```powershell
cd "D:\大创\3d\MicroCleaningVision"
```

本机已有测试用编译器时运行：

```powershell
& .\firmware\common\scripts\run-host-tests.ps1 `
  -ZigPath "D:\大创\tmp\hw-split-zig-0.16.0\zig-x86_64-windows-0.16.0\zig.exe"
```

这条命令先跑当前固件 5 个 C 程序，再跑旧兼容 7 个程序，覆盖泵、运动、实际主入口、异常和按钮。换电脑后把 `-ZigPath` 改为实际 `zig.exe` 路径；不必激活 Python 虚拟环境。编译器缺失时会明确报错，不自动安装、不打开串口。

输出：终端应出现当前 5 组 `PASS`、旧 7 组结果，并显示生成目录；可执行文件放在 Git 忽略的 `.tools` 下。具体编译方法见 [固件说明](../../firmware/common/README.md)。

验收：能亲自解释“为什么初始化先设高”“为什么重复关泵仍然是关闭”“为什么泵测试通过不等于实际出了水”。试着给 `test_pump.c` 添加一个确实缺少的边界断言，而不是凑测试数量；没有缺项就不必加。

### H1-02：整理泵控制与管路的实物条件

输入：手头实际泵、控制模块、喷头、管路和供电的照片/铭牌；没有的字段写“待确认”。

具体动作：

1. 写清控制模块型号和有效电平，泵额定参数从铭牌或真实资料抄，不靠图片猜。
2. 核对当前 PB0 接的是控制输入，不是直接为泵供电。
3. 与 H2 确认喷头固定位置、托盘移动范围、管路是否会被移动部件拉扯。
4. 准备固定喷头高度和固定喷水区域的测试装配，记录如何重复装回同一位置。
5. 真正通电/喷水需成员现场确认后进行；本轮命令只用于电脑测试。

输出：可以复现的接法和装配条件，以及明确的未确认项。C 需要它来理解“这个动作是否可执行”，A/B 需要固定喷射位置来比较图片。拍清接线、装配和现象比写十页泛泛检查更有用。

## 5. 后续分阶段任务

下面分别标清已有代码验收与后续实验；代码具备不等于现场验证。新的代码修改仍先提文件级方案再执行。

### H1-03：验收已经接通的限时喷洗

2026-10-05 代码已接入，不再把“实现计时器”分配成待办。当前目标是理解、复核和现场验收这条真实代码通路。

输入：pump.c/h、common/main.c、common/safety/control_core.c、common/serial/mcv1_protocol.c，以及 test_interlocks.c。

具体动作：

1. 沿 PUMP ON → fw_core_command → service_safety → apply_safe_outputs → pump_on/off 追踪固定 300 ms 的开始与结束。
2. 沿 MCV1 PUMP 追踪动作编号、ACK/DONE、拒绝和 STOP 中止。主机仍只准 100–500 ms；MCU 继承 100–2000 ms，不主动调高上限。
3. 看测试里的到时关闭、重复 ON 不延期、中途停止、急停锁存、异常状态；旧核心回归还覆盖计数回绕。不要只看 PASS。
4. 实物未接电前，核对 PB0 模块极性、PB12 常闭触点、PB3 输入及默认 ARM 配置。没有接 PB12 时会阻止动作；不要绕过。
5. 成员现场批准后，先形成可复查的输出起止/停止证据，再测试固定喷头短喷；记录请求时间与测量方法。没有量具就不写假毫升数。

输出：接线确认、构建/烧录版本、收发原文、真实时长/停止测量（若完成）、未通过的条件。编码器 ACK/DONE 不是流量反馈。

验收：能解释为何软件限时不等于硬件断电急停；能在相同条件下重复输出停止。主机 center_object.py 已增加明确维护模式/禁喷水/短距授权/位置作废，真实联锁效果仍待同次验收，固件定时不能掩盖它。

### H1-04：测出一个可用的固定喷洗参数

前提：H1-03 的实物验收通过，允许现场测试，且样本/介质和电气装配已确认。

任务：固定泵、喷头、高度和供电，选一个受限时长做重复测试；每次记录时长、覆盖范围、可测的出水量、漏水/不出水等异常。没有合适量具时先记录可测现象，不制造体积数字。

输出交给 C：在这些条件下，一个固定时长通常能覆盖多大区域，重复性怎样；交给 A/B：喷洗前后照片对应哪个条件。先找一个可重复参数，再谈自适应喷洗。

当前继电器式开/关不等于可调泵速。喷水速度可调还需要确认控制模块、泵特性和反馈手段，不能只在 Python 里加一个 `speed` 字段就宣称实现。

## 6. 要学到什么程度、怎样用 AI

| 知识 | 大白话解释 | 当前学到的深度 |
|---|---|---|
| C 函数与头文件 | `.h` 写“你能叫我做什么”，`.c` 写“我怎样做” | 能增加、调用、测试一个函数 |
| GPIO / 有效电平 | 芯片引脚输出高或低，控制模块据此开关 | 知道电平不是泵的供电电压；能核对初始化 |
| 非阻塞计时 | 记下时间并反复检查，不让整个程序等在那里 | 能解释为什么等待时仍能响应停止 |
| 毫秒、流量与体积 | 时间是申请值，出水量需要测量 | 不把 300 ms 直接写成某个毫升数 |
| Git 分支与小提交 | 自己开发，经过检查再合到共同版本 | 会看差异，避免误改 H2/C 文件 |

可以给 AI 这样的任务：

> 先读硬件组入口、泵手册和串口约定，再读 pump.c/h、test_pump.c 和 main.c 的泵分支。只解释输入输出，指出遗漏的测试；先给文件级方案，不修改运动代码、不打开 COM、不烧录。未测的硬件参数不得猜测。

AI 可以帮写代码和断言；控制模块极性、管路效果和真实出水量必须由人核实。当前不需要先学深度学习、复杂控制理论或另建一套框架。

## 7. 怎样与 H2 和 C 交接

- 给 H2：我会用哪些引脚和计时资源；哪些时候泵可能仍开着；请共同检查停止通路和管路干涉。
- 给 C：唯一串口约定中的命令与回复，说明已经有固件自动定时、没有体积反馈；正式运动会话还不混入喷水，后续改主机流程提前协商。
- 给 A/B：真实喷洗条件和对应前后图，不自己给出“污染已去除”的结论。
- 可以不等别人就做：读代码、跑电脑测试、整理实物信息、复核已有定时与停止通路、装配与测量准备。

工作量按真实投入检查：记录编码、装配、反复测量和排错的时间，不按文件数量或“拍几张照片”估算。H2 调两轴较重时，H1 可承接双方约定的公共入口集成，仍保持一次一位主改。

每次有效推进留下一个可复用成果：一个能复现的命令测试、一张带条件的接线照片、一次真实测量，或修好的一个明确故障。单纯把说明改漂亮不算喷洗能力提升。
