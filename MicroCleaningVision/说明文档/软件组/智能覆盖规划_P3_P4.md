## 3. 数据流与重算边界

```text
原图 RGB + 完整二值 Mask / provenance
  → CoverageDataset / CoverageInput（只读快照）
显式 FootprintProfile + 可选 PixelScale + Policy / Constraints
  → CoverageRequest（generation）
  → LatestCoverageWorker（一个运行、一个可替换待处理槽）
  → 原 P1/P2 Kernel / Planner / Metrics
  → CoveragePlan（executable=false）
  → CoverageVisualization（指定图层、驻点前缀）
  → StandaloneCoveragePanel / 四件归档
```

| 操作 | 重新计算 | 保留 |
|---|---|---|
| 改直径 | 新 assumed 情景、核、候选、计划、指标、画面 | 原图、完整 Mask、父 Profile 与来源 |
| 改目标比例/驻点上限/候选间隔 | 候选/计划/指标/画面；未改直径时保留原 Profile/已载入核 | 原图、Mask、尺寸证据 |
| 切图层/调整窗口 | 只渲染已有计划 | 核、驻点和完整计划 ID；不提交规划请求 |
| 播放/选前缀 | 用原核重算该前缀的几何并集，再渲染 | 完整计划与访问顺序 |
| 导出 | 冻结点击时快照，后台编码并写入新目录 | 调参可继续；导出完成不会覆盖新计划 |

每次参数编辑**立即**增加 generation、清空旧计划/指标、禁用旧结果的导出与播放；160ms 防抖后才提交。工作线程不调用 Tk，运行中的贪心计算完成后丢弃过期结果，只运行最新待处理请求。主线程再检查 generation，防止编辑到提交之间的旧结果回流。这里实现的是过期结果丢弃，不是强行中断 P2 算法，也不承诺任意大图实时完成。

## 4. 输入来源和 Mask 语义

- 独立演示可用 `circle/strip/concave/split/border` 五种固定合成形状；来源明确标为 `synthetic-fixture-v1`，不称为实拍。
- 文件入口需要原图、完整二值 Mask 与明确 `mask_kind`。原图解码为 RGB，Mask 必须为同尺寸二维 bool/灰度 0、1、255；没有自动阈值、缩放、ROI 平移或最大连通块筛选。
- 文件原始字节 SHA256 与归档 RGB 像素 SHA256 分开保存。原图文件转为归档 PNG 后不冒充原编码字节相同。
- `manual_region` 表示人工指定区域，界面显示“人工区域面积”，不能称为真实污渍面积；`manual_roi_segmented` 才表示人工 ROI 内已分割结果。面板不重新做 B 的分割。
- 带尺度/区域约束的输入绑定当前帧，面板禁止把它们静默套用到另一张图。另开启动参数加载新输入；没有根据窗口大小猜毫米尺度。
- P6 将来必须在旧“最大残片”选择之前冻结全目标 Mask。本轮没有更改旧执行对最大残片的选择。

## 5. 公共函数的输入输出

### P3 渲染

`render_coverage(image_rgb, plan, options=RenderOptions(), step_count=None) -> CoverageVisualization`

- 输入：原尺寸 `(h,w,3)` uint8 RGB，原 P2 CoveragePlan，bool 图层开关和 0–1 alpha；`step_count` 为 0 到驻点总数的整数，默认完整计划。
- 输出：不可变 RGB 像素、当前前缀 `CoverageMetrics|None`、step_count、`to_dict()` 元数据。包含 plan_id、图层、图例颜色、前缀/总步数、当前画面指标、像素哈希、原图坐标和禁止硬件标志。
- 绿色覆盖、红色遗漏、可选紫色重叠、蓝色**实际栅格核边界**；支持非圆/非对称显式核，圆形不是渲染端重新猜出的形状。编号使用访问顺序，黄色虚线含起始点至首驻点的几何连线。
- 无可用模型时不涂“预计覆盖/遗漏”，只保留原图/目标层与原因；空目标比例为 None。
- 部分播放的保守覆盖为未知，完整播放复用 P2 计算的保守 Mask。没有复制 P2 私有误差核算法来冒充逐点保守结果。

`render_report(plan, view) -> PIL.Image.Image`

- 输出带模拟/尺寸来源/几何指标/图例/不可执行提示的 RGB 报告图，渲染时验证 plan_id 一致。
- 报告图的图像区域按比例放大显示；算法坐标和 Mask 从不跟着报告尺寸变化。
- 系统有微软雅黑时使用中文，其他系统使用英文说明与可用字体。图层透明混色只影响展示，不影响面积。

### P3 归档

`export_coverage_preview(image_rgb, plan, destination, constraints=None, options=..., step_count=None) -> Path`

目标必须为**不存在的新目录**，不会覆盖已有归档。对有约束的计划必须传入原始 CoverageConstraints；仅有计划中的 Mask 哈希不足以完整重放。

| 文件 | 内容 |
|---|---|
| `coverage_overlay.png` | 当前前缀报告图；PNG 内含 plan_id 和不可执行声明 |
| `source_image.png` | 同一快照的原尺寸解码 RGB |
| `coverage_masks.npz` | 完整目标、精确核、完整计划覆盖/遗漏/重叠/次数/可选保守 Mask，以及原中心/喷湿/禁喷约束 Mask；不使用 pickle |
| `coverage_preview.json` | 完整 P2 Plan、Profile/尺度/约束/访问序列/算法标识、当前视图与前缀指标、文件字节/数组哈希、所有禁止硬件标志 |

JSON 先完整写入同目录临时文件，再以改名发布为归档完成标记。写入失败时错误可见，留下没有完成标记的目录（可能含临时清单）；不会为了清理而递归删除用户目录。完整 Plan 与前缀画面分别记录，不能把播放到第 1 点的图冒充完整计划效果。导出线程尚未完成时直接退出整个进程，也可能留下未完成目录；应另建归档，不覆盖或假装完成。

`load_coverage_preview(directory) -> CoverageArchive`

- 固定文件集合、schema、硬件 false 标志检查；单文件 64MiB、清单 8MiB、NPZ 解压总量/声明 shape/dtype 等软件资源限制。
- 校验字节、原图像素和数组哈希；`allow_pickle=False`；先检查 NPY 声明尺寸再申请数组。
- 恢复完整输入、Profile、精确核/锚点、尺度、所有约束与 Policy，**重新运行原规划算法**，比对完整 Plan 和所有 Mask；再重画指定视图验证像素哈希/元数据。
- 输出只读 RGB、Plan、Constraints、RenderOptions、step_count。哈希用于损坏检测，不是数字签名，也不能把 assumed 变成实测。
- 算法/依赖版本变化可能使重放校验拒绝；这比默默接受旧指标更可追溯。保留原归档并按原运行环境复查，不触发执行。

### P4 会话与面板

- `CoverageDataset(image_rgb, input)`：冻结同尺寸原图和完整 CoverageInput。
- `load_image_mask(image_path, mask_path, mask_kind=...)` / `synthetic_dataset(shape)`：输入适配，不操作相机。
- `CoverageRequest(generation, dataset, profile, scale, policy, constraints, model=None)`：model 只用于重放已保存的精确核，Profile 必须匹配；用户改直径后生成新虚拟圆核，不篡改原测量。
- `LatestCoverageWorker.submit/poll/close`：递增请求，最多一个待处理请求和一个最新响应；异常变为带 generation 的 error，不污染下一次请求。关闭不等待长计算，不向已销毁 Tk 发布内容。
- `StandaloneCoveragePanel(...)`：Tk 主线程拥有控件、PhotoImage 和 after 生命周期；后台仅规划/编码文件。独立页具备直径滑条/输入、目标/预算/间隔、输入来源、图层、逐点播放、几何指标和显式导出。
- 空直径 Profile 可展示“无法预测”，滑条在显式输入有效尺寸前停用；没有启动默认真实尺寸。修改 measured 直径产生 assumed 且保留父哈希；单改规划目标不会降级未编辑的测量来源。
