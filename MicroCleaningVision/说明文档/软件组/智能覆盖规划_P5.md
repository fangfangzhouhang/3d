## 3. 对比定义：先把比较对象说清楚

每个情景与预算内，三个方法共用同一完整 Mask、精确核/尺度、约束与误差包络、候选网格、起点、覆盖目标及驻点预算上限。达到目标可以提前停止，故比较的是**相同预算上限**，不是强行让每个方法使用相同点数。

| 方法 ID | 本轮几何基线定义 | 与旧代码的关系 |
|---|---|---|
| `CENTER_POINT_COMPONENTS` | 每个 8 连通块一个质心，按原最近邻组件顺序，以 Python ties-to-even 取整 | 强制中心基线；不是全目标一个总质心，不改变旧自动策略切换 |
| `RASTER_SCAN_DWELL` | 强制旧 raster 分支，复用原逐行前景索引取样、尾点、蛇形及组件顺序，把每一点视为一次驻点 | 是离线离散驻点模拟；不是旧固件连续扫描，也不启用沿路喷水 |
| `COVERAGE_AWARE` | 调用原 P2 最大增益、距离/y/x 确定性解并列的贪心规划 | 原返回 CoveragePlan 的 Plan ID 另存；未创造虚假旧 Plan ID |

基线原始提案点逐个审计。非法点保留在 `proposed_points_px/rejected_proposals`，合规对比按原顺序过滤，不偷偷挪到更好的位置。`raw_prefix_metrics` 另评价原始提案的预算前缀，用于显示过滤造成的差异，明确不参与排名。Raster 超过 4096 个提案点时先计数拒绝，再决定是否调用旧完整路线生成器。

默认 `candidate_stride_px=1`，避免稀疏网格人为排除取整质心。使用更粗网格时，`CANDIDATE_GRID_MISMATCH` 与足迹/中心域违规分别记录；这时曲线还反映采样网格影响。`raster_step_px=16` 是原软件点间隔，单独记录，不是暗含的喷头尺寸。

完整足迹（含误差外扩）必须处于喷湿域并避开禁喷区；未知域只默认图像范围并保留 assumed 提示。访问距离包含起点至首点以及各点的直线连线，没有计算往返观察位、泵时长、实际 XY 插补轨迹或清洗耗时。

## 4. 公共接口与数据结构

### 共享可行域

`prepare_coverage_domain(input, model, policy=..., constraints=...) -> CoverageDomain`

- 输入沿用 P1/P2 的完整 `CoverageInput`、`KernelResult|FootprintKernel`、Policy 与原始约束 Mask，不新增共享协议。
- 输出 `status/reason_codes`、只读 `feasible_centers_mask`（完整几何约束）、`candidate_centers_mask`（再与候选网格求交）、`conservative_kernel_mask|None`、`candidate_count`。
- 无模型、缺误差/尺度或资源超限时无可行域 Mask，不能冒充安全区域。原 P2 复用同一入口；空目标的旧 None 比率语义保持。

### 分析输入

`analyze_coverage(input, model, spec=AnalysisSpec(), constraints=None) -> CoverageAnalysis`

`AnalysisSpec` 字段：`station_budgets`（升序唯一正整数，默认 1/4/8/16/32/64）、`target_coverage`、`candidate_stride_px`、`start_px`、`coverage_basis=nominal|conservative`、`raster_step_px`、`diameters`（显式情景，沿 Profile 的 px/mm 单位，默认空）、`position_errors`（显式非负情景，默认空）、`position_error_unit=px|mm`。

直径没有软件猜测值。毫米 Profile 无尺度时保持不可用；毫米定位误差不能偷偷当像素误差。非圆或显式核不能被直径扫描静默换成圆，返回 `DIAMETER_SWEEP_REQUIRES_CIRCLE_FACTORY_KERNEL`；它仍支持误差情景。圆直径变化调用原 `with_diameter/build_kernel`，产生 assumed 子 Profile、保留父哈希和尺度，未修改原 measured 证据。

### 每个分析结果

`AnalysisRun` 保存以下分组；`to_dict()` 可序列化，JSON 不允许 NaN：

- 身份：稳定 `run_id`、method、phase、参数名/数值/单位、固定方案 `source_run_id`、原 legacy 自动分支、基线/取整语义。
- 条件：完整 Profile/精确核元数据与 SHA、Policy、约束/来源/包络/Mask SHA、candidate_count。
- 驻点与审计：实际 `points_px`、原 `proposed_points_px`、带 1 起始提案索引与原因的 `rejected_proposals`、固定方案 `constraint_violations`、raw_prefix_count/metrics/reasons。
- 结果：沿用 P2 CoverageMetrics，含目标/覆盖/遗漏/重叠/溢出/毫米面积与可选条件下保守覆盖；保留六类评估数组的哈希和实际不可变数组；status/reason_codes/warnings、qualifies_for_comparison、route_length_px、greedy_plan_id。
- 测量：`planning_evaluation_seconds`、`audit_seconds`；前者包括可行域/基线或贪心/指标，贪心还包括 Plan ID 编码；后者是基线原始前缀的额外审计。均为一次本地调用，不是重复试验的性能统计，核构建/文件编码/分析结果编码不计入前者。
- 隔离：`executable=false`、`feeds_action_request=false`、`send_to_controller=false`，不可在构造时改成 True。

`CoverageAnalysis` 冻结完整输入、基础模型/约束、Spec、全部 Runs 和总 elapsed；`analysis_id` 与 run_id 排除耗时，避免同一几何结果因本次速度不同而换身份。原 Plan ID 字段不变。软件上限：最多 256 个 run，评估 Mask 估算/导出 192MiB，单输入 100 万像素，沿用 P2 候选/驻点/核/画布上限。

### 固定方案与重规划

- `diameter_fixed` / `position_error_fixed`：严格保留基础情景选中的原驻点。新模型或约束不可用时坐标仍在、指标为 None；发现违规时保留几何指标并标为 `CONSTRAINT_VIOLATION`、不参与合规排名，不过滤原点来伪造安全固定方案。
- `diameter_replan` / `position_error_replan`：在新核/约束下重新调用同一方法。参考情景不可用时 fixed 为 `REFERENCE_UNAVAILABLE`；有效的新虚拟直径仍可以重新规划。
- Nominal 目标优化名义并集；conservative 目标优化误差盒下收缩核的覆盖。后者是条件模型的保守面积，既不是成功概率，也不是已实测鲁棒性；未知误差时保持 None，不画 0% 来冒充已知失败率。

### 报告接口

`export_analysis_report(CoverageArchive, CoverageAnalysis, new_directory, include_figures=True) -> Path`

只接与分析的完整输入/模型/约束一致、已经校验的 P3 归档，写入**不存在的新目录**。包含：

| 文件 | 内容 |
|---|---|
| `input/` | 原 P3 四件完整输入归档，含原图、完整目标/核/全部约束、原 Plan 与视图；源归档不改 |
| `analysis.csv` | UTF-8 BOM，每 run 一行，单位/来源/预算/状态/实际点数/拒绝与违规/所有指标/几何距离/耗时 |
| `analysis_masks.npz` | 每 run 的原尺寸 footprint/covered/uncovered/overlap/counts/可选 conservative 数组，名称如 `r000_covered_mask`，无 pickle |
| `comparison.png` | 同情景三个方法的覆盖图，预算—覆盖/距离/一次计算耗时曲线 |
| `sensitivity.png` | 直径/误差，固定/重规划，名义/条件下保守覆盖四图；违规红叉、未知留空 |
| `analysis.json` | 完整分析、文件/数组 SHA、原输入清单 SHA、依赖版本、false 标志；最后用临时文件改名发布，作为完成标记 |

Matplotlib 使用 FigureCanvasAgg，不导入 pyplot/Tk/硬件。图像只是显示，面积仍从原尺寸 Mask 计算。`--no-figures` 不要求 Matplotlib。中途写失败保留未完成目录且没有最终清单，不递归删除用户目录，也不覆盖旧归档。

`load_analysis_report(directory) -> AnalysisReport`：检查 schema/固定文件集合/false 标志/资源上限和哈希；先检查 NPZ 内 NPY 声明再分配数组；完整 P3 输入重放；再运行所有 P5 方法与情景，逐字段比对稳定结果和实际 Mask；单独验证并恢复记录耗时，使 CSV 精确一致。PNG 校验字节哈希/分析身份/格式，不把它当清洗证据。SHA 用于损坏检测，不是数字签名，也不验证实测来源真实性。


CLI 默认继承原归档起点、覆盖目标和 basis，分析默认 dense stride=1；显式直径单位继承 Profile，误差另指定 `--position-error-unit px|mm`。不传情景列表即不生成相应扫描。`--verify` 不允许混入新参数/导出选项；重新计算的数据不是覆盖旧清单。

若要以 conservative 目标分析，原参考归档须有显式定位误差（例如人为假定 0px）；缺误差不是 0px。把 `--coverage-basis conservative` 用在无误差参考上会得到明确不可用参考，而不是有效固定方案。

| 场景 | 中心基线：点数 / 预计比例 | 扫描驻点：点数 / 预计比例 | 贪心：点数 / 预计比例 | 贪心 / 扫描访问连线 px |

| 圆形 | 1 / 7.60% | 55 / 95.52% | 19 / 95.75% | 971.72 / 1053.37 |
| 长条 | 1 / 11.00% | 36 / 97.40% | 13 / 96.25% | 571.72 / 652.72 |

分裂目标本次一次计算调用：中心 0.00917s、扫描 0.02116s、贪心 0.12512s（额外 raw 审计另列）。不能把一次耗时当统计结论，也不能据此预测真实设备清洗用时。

直径固定/重规划：分裂原 17 点从 36px 改为 24px，固定比例 58.93%；重新规划 34 点达 95.11%。改为 48px，原 17 点几何 100%，重新规划 11 点达 95.33%。图像边界原 11 点改为 48px，几何 99.90% 但 **5 点违反足迹边界、不参与合规排名**；重新规划 8 个合规点达 96.07%。这说明更大直径不自动让固定方案合格。
