# 软硬件联调操作手册：先通信，再接负载

## 1. 这份手册的目标

它用于完成第一次 NUCLEO 与电脑通信验证。当前电脑脚本只发送 `PING` 和 `STATUS`，不会启动水泵。

## 2. 开始前确认

```text
[ ] 使用 NUCLEO-F401RE
[ ] 固件使用 USART2 / PA2 / PA3
[ ] 固件参数为 115200、8N1
[ ] 固件实现 MCV1|PING 和 MCV1|STATUS
[ ] PB5 上电默认关闭
[ ] 真实泵尚未接入，或 12V 电源保持断开
```

## 3. 第一步：电脑端只预览协议

从项目根目录运行：

```powershell
cd "D:\大创\3d\MicroCleaningVision"
.\.venv\Scripts\python.exe scripts\probe_stm32_link.py
.\.venv\Scripts\python.exe scripts\probe_stm32_link.py --command status
```

输入：无真实串口。

输出：程序打印将要发送的文本，并明确说明没有打开 COM。

## 4. 第二步：硬件组编译和烧录

硬件组在自己的 STM32CubeIDE 工程中：

1. 配置 USART2；
2. 实现按换行接收一整条消息；
3. 实现 `PING → PONG`；
4. 实现 `STATUS → ESTOP/PUMP`；
5. 本地编译无错误；
6. 烧录 NUCLEO；
7. 把源码和 `.ioc` 上传到功能分支。

此时仍不要求实现水泵命令。

## 5. 第三步：找到明确的 COM 口

在 Windows 设备管理器中查看“端口（COM 和 LPT）”，记录类似：

```text
STMicroelectronics STLink Virtual COM Port (COM5)
```

不要在脚本中自动尝试 COM1～COM20。由人确认实际端口，再把它传给程序。

需要真实串口时安装独立依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements\control-serial.txt
```

虚拟环境不需要因为安装 pyserial 而提交到 Git。

## 6. 第四步：实机 PING

把示例中的 COM5 替换成设备管理器显示的端口：

```powershell
.\.venv\Scripts\python.exe scripts\probe_stm32_link.py `
  --port COM5 `
  --command ping
```

成功输出应包含：

```json
{
  "kind": "PONG"
}
```

如果超时，按顺序检查：

1. 固件是否已经重新烧录；
2. 波特率是否都是 115200；
3. 固件是否在收到 `\n` 后才处理；
4. 是否使用 USART2；
5. 是否选错 COM；
6. 串口是否被 CubeIDE 终端或其他软件占用。

## 7. 第五步：实机 STATUS

```powershell
.\.venv\Scripts\python.exe scripts\probe_stm32_link.py `
  --port COM5 `
  --command status
```

至少记录两组：

```text
急停正常：MCV1|STATUS|ESTOP=0|PUMP=0
急停按下：MCV1|STATUS|ESTOP=1|PUMP=0
```

如果硬件使用相反电平，固件内部负责转换；上位机协议仍保持 `ESTOP=1` 表示急停有效。

## 8. 第六步：PB5 和 MOSFET

在加入电脑端真实 PUMP 控制前，由硬件组独立完成：

1. 上电、复位和固件异常时 PB5 默认关闭；
2. 用 LED、万用表或示波器验证 PB5 开关；
3. 不接水泵时验证 MOSFET 输出；
4. 确认模块高/低电平逻辑；
5. 确认续流二极管方向；
6. 确认急停能切断 12V。

做到这里后，把结果和器件事实提交到 PR。软件组再实现经过 `ControllerPort` 的真实 PUMP 发送，不通过探测脚本绕过主流程。

## 9. 联调证据怎样保存

一次合格联调至少留下：

- 固件提交号；
- NUCLEO 型号和接线图版本；
- COM 口名称；
- `PING/PONG` 终端输出；
- 急停正常和按下的 STATUS 输出；
- 测试日期和执行人；
- 当前没有验证的功能。

这些可以直接写进硬件组 PR，不需要再创建形式化报告。
