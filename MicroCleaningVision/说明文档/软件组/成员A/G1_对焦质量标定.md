## 1. 为什么需要这条入口

本次真实失焦图拉普拉斯方差约252.864，正常批次最低约947.370，恢复图约1664.782；默认focus_reference=100时，三类图的focus均饱和为1，失焦图没有FOCUS_LOW。

新模块复用现有ImageQualityPolicy和inspect_image_file，不改变默认100、不删除0–1归一化、不训练模型、不访问相机/串口。实际动作许可仍由原有控制链负责。

源码：[focus_calibration.py](../../../microcleaning/data_learning/focus_calibration.py)。
回归：[test_focus_calibration.py](../../../test/data_learning/test_focus_calibration.py)。
样例：[manifest.json](../../../test/data_learning/fixtures/gate1_focus/manifest.json)。

## 2. 输入与已知局限

输入清单schema为focus-manifest-v1，purpose固定为development_regression。context包含设备记录、分辨率、setup_id、材料/倍率/灯光；images逐项记录相对路径、SHA256、操作者标签、session_id、batch_id及condition。

标签允许clear、defocused、uncertain，必须声明operator_confirmed，并至少有clear和defocused。uncertain不被算成已正确分类，也不参加清晰/失焦区间端点计算。工具不猜标签或设备条件。

本仓库的3张回归图为本次原始PNG字节副本：正常、失焦、恢复；它们来自同一次操作者会话，只有一张明显失焦图。完整22图开发包与原Gate1证据另存本机，不等于团队已共享或有独立测试集。材料、倍率、灯光档位保持unknown。

清单中的会话/批次是操作者记录；程序不能认证其真实性。不同批次编号不自动构成独立验证；相同文件哈希的重复项单独列出，路径重复及同文件字节的清晰/失焦标签冲突拒绝。

## 3. 默认回放命令

在项目根目录运行，输出目录必须是新的：

~~~powershell
cd C:/Users/lin43/Desktop/32/3d/MicroCleaningVision
$focusRun = Get-Date -Format 'yyyyMMdd_HHmmss'
./.venv/Scripts/python.exe -B -m microcleaning.data_learning.focus_calibration test/data_learning/fixtures/gate1_focus/manifest.json --output-dir "output/focus_calibration/$focusRun"
~~~

本命令只读本地图片，输出report.md和report.json，不打开相机或串口，也不生成候选配置。

报告包含逐图原始指标、默认分数/flags、操作者标签是否对应、漏报和误报、声明会话/批次数、重复文件哈希、开发图可行区间及未独立验证状态。

## 4. 候选比较与导出

只有显式提供--candidate-reference数值时才比较该候选；再加--export-profile才写candidate_profile.json。不提供数值不会自动挑一个参考值。

参数形式：

~~~text
python -B -m microcleaning.data_learning.focus_calibration MANIFEST
  --output-dir NEW_DIRECTORY
  --candidate-reference EXPLICIT_NUMBER
  --export-profile
~~~

上面是参数说明，EXPLICIT_NUMBER不是可直接运行的数值。本轮没有为设备选择生产参考值或导出实际设备配置。单元测试显式使用1200，只是固定的回归输入，不是推荐参数。

同一评分公式下，本批开发图在minimum_quality=0.7时的算术可行范围为：

~~~text
361.234667 < focus_reference <= 1353.385506
~~~

该范围不是标定标准。许多数值都能分开已看过的图片，不代表其中任一值能区分临界失焦、新样本或新成像条件。分布重叠时报告不可分离，不硬选阈值。

已有候选可用--profile PATH重放，使用前核对清单context一致性。它和主入口已有的分割--policy不同，也不会让工作台自动读取此文件。

## 5. A → 后续消费者的局部API

| API | 用途 |
|---|---|
| load_focus_manifest(path) | 校验清单、操作者标签、相对路径、类别及原文件哈希 |
| evaluate_focus_manifest(manifest_or_path, candidate_policy=None) | 复用现有质量算法，生成开发回放结果；不选生产参考值 |
| write_candidate_profile(report, path) | 仅导出报告中已显式比较的候选，不覆盖旧文件 |
| load_focus_profile(path, expected_context=None) | 校验schema、状态、完整policy、有限值、内容哈希和可选context；返回冻结的ImageQualityPolicy |
| render_focus_report(report) | 把逐图结果和边界写为Markdown |
| main(argv=None) | 无设备访问的模块CLI |

profile状态只支持candidate，独立验证固定not_performed。修改文件为validated会被拒绝；当前工具没有自动升级为正式标定的接口。加载失败明确报错，不回退到默认100。

load_focus_profile返回对象的quality_policy可用于现有ReplayCamera的quality_policy参数。USBCamera原本也有这个参数，但本任务没有打开它或修改其CLI消费者。C/B接入主线和正式验证状态需后续方案。

profile内content_sha256检验规范化内容，返回对象sha256记录原配置文件字节。两者均不是数字签名，不证明操作者标签或实物设置真实；expected_context只比较记录，不能检测旋钮、倍率或光照的物理改变。

## 6. 失败与输出行为

缺文件、文件字节变化、错误分辨率、空/缺类别清单、缺操作者标签、重复ID/路径、越出清单根目录的路径、无效/非有限参数、配置损坏和context不匹配都会明确失败。

CLI成功退出0只表示离线计算完成，默认策略仍可能漏报；判断看report中的missed_defocused、flagged_clear和independent_validation_status。错误退出2，已有输出目录不覆盖。图像和原清单不被修改。

输入校验或回放失败不创建成功报告。写入阶段中断可能留下不完整新目录，report.json是最后发布的报告文件；此类目录需人工复核，不当作完整证据。
