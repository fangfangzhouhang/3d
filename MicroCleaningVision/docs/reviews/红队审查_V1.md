# 对抗性评审 v1 — 2026-08-12

**评审者角色：**独立红队。**范围：**基线仓库和 MCL 升级。**结论：**模拟契约能力是有用的，但当前物理平台仍处于 E0。不允许做出硬件 MCL 声明。

| 批评 | 严重度 | 回应 / 修复 | 证据 / 残留风险 |
|---|---:|---|---|
| 旧版路径在没有治理的情况下直接提出移动/喷涂 | 严重 | `main.py.start()` 现在在模块初始化前返回；测试调用入口守卫而不构造硬件依赖 | 守卫测试通过。旧版代码仍被隔离，并非物理安全控制器。 |
| 候选提议可能膨胀自身的限制 | 高 | 引入不可变的 `MockSafetyPolicy`，由治理器拥有 | 伪造的 9000 ms 候选被拒绝。真实策略值仍是未知的人工关卡事实。 |
| 硬安全故障可能变成 HUMAN | 高 | 硬拒绝现在优先；人工路径仅用于安全但不足的条件 | E-stop + 低置信度组合测试产生拒绝。真实 E-stop 仍未验证。 |
| 批准令牌未绑定或非一次性 | 高 | Decision 现在绑定 action/state/request 的 SHA-256/policy/expiry；控制器拒绝不匹配、篡改、过期和重放 | 已测试四种拒绝场景。这只是模拟令牌语义。 |
| 模拟验证可能被呈现为清洁效能 | 高 | 文档明确命名了合成区域和 `mock://` 来源；状态仍为 E0 | 真实的预/后图像质量/配准和物理残留指标缺失。 |
| 旧版套件不可复现 | 高 | 保留无依赖的 MCL 套件作为默认的狭窄证据；记录了旧版测试失败 | 16 个 MCL 测试通过；旧版仍有 9 个导入错误；可复现环境仍需单独批准的依赖工作流。 |
| Episode 存储可能覆盖或丢失完整性 | 中 | 添加了原子 JSON 写入和 SHA-256 附属文件；写入拒绝已存在的 JSON 或摘要 | 写入器测试通过。真实制品哈希/清单和保留存储仍是后续工作。 |
| 标定是占位符/默认比例 | 高 | 没有适配器向 MCL 暴露旧版默认比例；物理标定是阻塞项 | 需要真实目标、误差、过期和夹具证据。 |
| 高级模块抢跑基线 | 中 | MCL 计划将 YOLO/双视图/Z/3D 转为门控假设 | 还没有失败数据集来选择 P2 假设。 |

## 故意未在代码中“修复”的问题

- 我们**没有**实现 STM32、相机、泵、XYZ、YOLO、3D 或真实控制器适配器。在没有协议、标定和安全事实的情况下这样做是不负责任的，并且会拖延正确的 P1 证据路径。
- 我们**没有**安装缺失的旧版依赖。那会改变环境，且仍然无法证明物理功能；依赖规范化成为一项单独的、可评审的任务。

## 合并关卡

MCL 脚手架只能作为 **E1 模拟软件契约行为**被接受。在真实证据满足 `docs/03_最小闭环路线图.md` 和 `docs/06_真实实验操作规程.md` 中的关卡之前，不能作为 E2/E3/E4 被接受。
