# DECISIONS｜为什么这样设计

核对日期：2026-10-05；历史条目保留原依据，新决定注明替代范围。这里记录能影响下一次选择的理由，不记录每个提交细节。原始历史见[提交与拉取日志](../进度记录/提交与拉取日志.md)。

## 1. 状态与记录方法

- **现行**：当前代码或已确认团队规则采用；不等于实验已证明它最好。
- **历史 / 已替代**：以前采用，保留原因和失效范围。
- **提议**：本轮提出，尚未批准实施或做过实验。

每条新增决策写：问题 → 选择 → 依据 → 没选什么/代价 → 复议条件 → 影响接口。历史依据缺失时明确写“当前实现观察”，不虚构团队会议、投票或人的动机。

## D-001｜先完整小系统，再升级算法（现行，用户长期原则）

优先级是阻塞真实闭环的问题、安全/接口/坐标/复检/追溯，再是主要失败率和研究证据质量。简单 Baseline（可复现的基础方案）先行；复杂度必须有稳定失败和最小对照支持。

代价是早期效果和界面可能很朴素。收益是每一次增加能力都能用端到端输入/输出检查。若简单视觉在冻结数据上持续失效，而数据和基线已可信，才进入模型升级；不能因“AI 看起来高级”提前启动。

## D-002｜A/B/C 按顶层模块负责（现行，用户确认）

A 管 data_learning，B 管 vision，C 管 control_system；硬件组管 firmware。一个模块的负责人负责完整输入—程序—输出，减少跨目录抢同一文件。模块上游未就绪时用契约样例独立开发，真实集成仍要尽早做。

代价是集成入口和共享合同要协调，不能靠目录所有权免除沟通。工时不固定平均：拍摄、人工标注、现场排故也是工作。两轮实际投入记录后再调任务。用户作为 A 持有相机、有 GPU 使用经验；这不意味着所有现场任务或未来训练都必须由 A 单独承担。

## D-003｜U500 先按普通 USB 视频设备接入（现行）

通过 CameraPort 和 OpenCV VideoCapture 接入，B/C 读 Observation 和像素，不绑定相机型号。依据是团队当前只有 U500 USB 数码显微镜，没有已确认厂商 SDK 或工业相机。

不预建多个设备抽象或采购工业相机。若 U500 存在稳定复现的失焦、曝光、延迟或接口问题，并能量化对任务的影响，才评估驱动调整或替换。抓帧和动作授权独立。

## D-004｜local 替代 HSV 作默认（现行；效果待验收）

当前实现观察：Demo/run_baseline 默认 local，通过 Lab 颜色空间的局部背景差异与连通域筛选识别，不固定目标颜色；HSV、Otsu、ExG/ExR 继续作对照。历史提交和进度记录在 2026-09 已反映这一变化。

历史报告中 local 比 HSV 的平均 IoU 高，但在 4 张留出旧图上仅约 0.2094。选择它作为当前入口不等于它能泛化到 U500/PLA；过滤细长块也可能删掉真实细长污染。复议条件是同条件采集、冻结评价和错误类型支持另一个方案。

## D-005｜当前 train_entry 是调参，不是模型训练（现行）

源码后端只开放 OpenCV 调参；网络训练、GPU/AutoDL 路线尚未实现。自动搜参数和人工看叠加图有当前收益，无需先配置训练服务器。

未来若换神经网络，需新的数据划分、训练/测试、依赖、模型输出适配和 A/B；现有脚本不是一个“改 backend 就能训练”的承诺。

## D-006｜保留像素与假设毫米的区别（现行）

B 输出像素；有效 work_mm 与假设 assumed_work_mm 分开。Stage 2 目前使用电机位移反推尺度，毫米仍依赖 5 mm/圈/320 步/mm 假定。Preview 的 `feeds_action_request=False` 防止假设坐标被写成已验收喷射定位。

代价是不能把漂亮路径图当对准证明。复议条件：独立刻度、轴方向、原点、喷头偏移与留出点误差都被验证；否则只做受限工程试验。

## D-007｜Stage 1 泵与 Stage 2 运动暂时分开（历史，固件侧已被 D-013 替代）

当前 F103 有两份固件/Keil 工程，协议分别为 MCV1 和 STEP v0.3。这是仓库实现事实，不是认定永久最优架构。2026-09-24 至 09-30 的运动提交逐步加入双轴和标定工具。

代价是同一芯片不能同时烧两份程序，移动喷水没有集成。下一次合并要解决 GPIO/定时器/状态机/协议/急停和回执，不靠把两份 main.c 粘在一起。统一固件或多控制器都只是候选，需硬件组确认。

## D-008｜分析与真实运动分开，异常先 STOP（现行，`91c3809` / `17bf617`）

analyze 只看路径；stage2-move 经过运动关卡、内容绑定的一次性审批、人确认和显式武装。串口失败留下部分发送记录并让位置未知，避免断连后继续相信旧坐标。

代价是多一个明确操作步骤。范围是 Demo/Stage2SerialLink；旧居中和标定脚本未统一进此关卡。不能写成“仓库所有运动都已有同样保护”。独立脚本整改是 GAP-CTRL-01。

## D-009｜结果必须来自真实后图（现行目标；真实验收缺失）

Controller 回 DONE 只能说明固件流程结束；Verification 才判断污渍是否减少。模拟改变 Mask、人工擦除或纯软件回放必须标明来源。

当前 verify_area_change 要调用者确认前后可比，默认 0.80 去除率只是回放阈值。真实阈值、配准误差、损伤判据尚未确定。不能用前后光照变化冒充清洗收益。

## D-010｜六份仓库记忆，避免每个 Agent 各有“项目真相”（本轮落实）

六份文件保存项目目标、机制、交接、理由、证据和下一步；AGENTS 要求开工完整阅读并检查 Git/原始材料。命令百科仍是教程，进度记录是事件日志，project_state 是机器可读快照。

采用短文档与证据索引，而不是现在建立 RAG、自动向量化、Agent 自动写回或新平台。依据是当前瓶颈为真实数据/闭环/标定，记忆应减少误判和重复解释。未来只有文档量或查找错误形成稳定瓶颈才考虑自动检索。

## D-011｜固定点闭环可先于移动喷洗（提议，未执行；固件现状见 D-013）

若团队能在稳定夹具中把目标置于固定喷头覆盖内，先用 Stage 1 做 `前图 → 定点短喷 → 后图 → 复检`，无需等待移动喷水固件。它可更短地逼近 E3，但不证明 XY 路径有效。

选择仍需团队确认喷头与相机布置、样本/介质和前后可比性。若无法固定条件或样本移动导致不可比，先补夹具和配准。移动控制已有成果保留为独立方向，并行做位移验收。

## D-012｜模型、双视角、3D 与结果预测都是有条件候选（提议路线）

模型应针对已分类的分割失败；双视角针对遮挡；3D 针对高度带来的定位误差；结果预测需要真实 State–Action–Outcome。每个方案先设主指标、简单对照、投入预算与删除条件。

目前没有数据支持同时启动这些方向，也没有已验证的跨行业迁移。下一轮若条件不足，回到数据与工艺，不建立空目录。

## D-013｜H1泵 / H2运动 / 共同入口，保留旧工程（现行，2026-10-05用户批准）

问题：按keil、stage2、stm32f103工程目录分人会割裂同一装置；旧安全核心存在但当前main没有调用。

选择：pump与motion为两人的独立顶层责任模块；main、board、safety、serial、keil放common，旧Stage1放compat作回归。已有安全核心和MCV1只有一份，当前联合入口实际复用。默认H1主改集成、H2复核，一次只一位主改；按实耗调整，不刻意禁止共同负责。

依据：迁移前65文件快照/哈希、原3项兼容测试、新5项和旧7项回归、两套Keil可编译。没有复制供应商库或重写状态机，没有改A/B/C业务与共享Python接口。

代价：路径变更需同步两个工程及说明；旧/新HAL同名，必须隔离include目录。复议条件：实际多人协作或现场故障显示目录/接口不合用，再做最小改动。旧历史目录只作兼容，不新增第三个岗位。

## D-015｜一条串口按顺序走两套协议，复检按单块而不是整图（现行软件，2026-10-05）

问题：联合固件已经能听步进句子和 `MCV1`，但电脑上是两个控制器，各开各的口；整图面积也不能说明刚洗的那一块有没有变小。

选择：不合并解析器。`F103Session` 独占一条已打开的连接，先 `MOVEXY`，成功且喷水仍获批准才发 `MCV1|PUMP`。视觉用连通域得到 `TargetInstance`，只用配上的那一块面积调用原来的 `verify_area_change`。排序用独立的 `SequenceTarget`，不让规划导入视觉类型。

依据：分支 `feat/closed-loop-cleaning-v1` 上的合成干跑。运动失败、未武装、错协议回复、T2/T3 面积变化、配不准和空 Mask 都有断言。

没选什么：不把 `PUMP` 写进 `stage2_protocol.py`；不把 `TO_NEEDLE` 或 7680 步当成正式行程；不放宽 1600 步；不改 `contracts.py`；不把这条链接进 Demo。

代价：现场命令仍是原来的 `stage2-move` 和 `arm-pump`。干跑通过不等于板上已经先动后喷。

复议：Demo 要自动走这条链，或要把两类对象放进共享合同时，另开集成变更。

## D-014｜兼容旧句子，但拒绝无限ON与未服务的按钮（现行软件；实机接线未批准验收）

选择：原始PUMP ON保持回复、限制一次300ms；MCV1计时走旧状态机。PB2常闭接地/上拉假设，断开高急停锁存；PB3读取并释放JTAG引脚（保留SWD）。STOP同时关闭两模块，CLEAR不续跑。

依据：真实main故障测试覆盖计时、重复ON、急停、停止、过长行尾部和挂起IRQ；旧核心已有回绕等边界测试。未把安全逻辑扩成新平台。

代价与边界：旧无限ON行为有意改变；PB2接线不符合时新固件会阻止动作，不能偷偷旁路。ARM按钮默认不强制，轮询并非独立断电。需要现场成员确认后才可烧录/运行；主机授权与失败判断仍未因固件计时而被修好。

针头偏移保留在同一XY驱动，名义值不当实测；PC只应采用一份有符号标定且施加一次，主机混合会话和返回后图另行实施。
