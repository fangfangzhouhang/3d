# MicroCleaningVision 项目作战总表

更新日期：2026-09-07。  
**本文件是六份并行审计收口后的仓库准则。** 以当前代码、磁盘数据和无硬件测试为准，不以过时 README / `project_state.yaml` 旧条目 / 交接审计原文为准。

Cursor 交互总表（组员默认看不到）：聊天旁 Canvas。组员执行入口是本文 + [团队任务看板](团队任务看板.md)。

硬原则：

- 代码写了 ≠ 功能完成；模拟 ≠ 真机；无标定禁止 pixel→mm。
- 视觉与 LLM 不得直接控硬件；泵必须经过 Safety Governor → Human Gate（`--confirm-pump`）→ `--arm-pump`。
- `analyze` / `--live` 默认不发泵是正确设计，不要改成看见污渍就喷。
- 先验证再优化；先最小闭环再复杂化。

## 3. 本周最重要任务 Top 10

顺序不可颠倒：先通信，再 GPIO，最后 12V。禁止扫 COM1–COM20，禁止 live 看见污渍就喷。执行卡见看板。

1. CubeMX 打开本仓 `firmware/nucleo_f401re/f401re-stage1/f401re-stage1.ioc`（Keep User Code）→ CubeIDE 出 elf → 确认 F401RE 后烧录。不提交二进制。
2. 设备管理器人认 STLink Virtual COM Port；安装 `requirements/control-serial.txt`。不要猜 COM5。
3. 12V/泵物理断开。`scripts/probe_stm32_link.py --port COMx --command ping` 然后 `status`。期望 `kind=PONG`。
4. Demo `--generate-sample --mode ping-only --serial-port COMx`。保存原文、COM 名、固件 commit、`12V disconnected`。
5. 若 STATUS 一直 `ESTOP=1`：处理 PB12 浮空（正常=LOW）。不要加大脉冲硬喷。
6. 不接 12V：万用表/LED 看 PB5 空闲为低；`arm-pump` + `--confirm-pump` + `--arm-pump` 发 100 ms，对照 ACK+DONE 与脚脉冲。
7. 对照：去掉 `--confirm-pump` 或 `--arm-pump`，串口不得出现 `MCV1|PUMP`。
8. 填泵电流、MOSFET/继电器极性、保险、续流管；通电检查表 + 第二人签字。未签字禁止接 12V。
9. 签字后同一软件路径 100–200 ms 实喷。证据=可见喷水 + DONE + 人在场。禁止写清洗有效。
10. 并行不阻塞泵：U500 `probe_usb_camera.py --capture-test` 留 PNG/SHA。13 张已 labeled；不要为刷分改留出标注。

## 8. OpenCV → 模型训练决策标准

**现在不准开训练。** 不允许只靠肉眼宣布算法准确。

磁盘实数（2026-09-07）：13 JPG + 13 Labelme + 13 张 `{0,255}` Mask，一一成对。`metadata` `labeled=13`。来源全部 `unknown`。`public_*` 不是 U500。U500 实拍 0。冻结留出：`public_002`、`public_011`、`M9`、`M12`。

`public_001` HSV 锁：IoU=0.0739，Precision≈0.083，中心误差 86.87 px。评价已含 IoU / P / R / FP / FN，以及 develop / holdout 分表。邻域差异 `local` 已作为 B 默认对照，**不是**过关。

**允许不下模型：** U500 labeled 留出集（n≥10，跨 2 批次）上 OpenCV 连续 2 个版本达到 mean IoU≥0.50、灾难率≤10%、P/R≥0.50、整图涂白 0 张。Otsu 在部分未验收图上 IoU 高于 0.6 **不得**当过关。

**进入训练必须全部勾上：** 成像条件固定；≥2 批次；≥50 张原图；≥30 张 labeled；按批次切分；OpenCV 留出集有稳定失败类型；调参后仍达不到阶段 B；负样本≥10%。未满足任一条 → 继续 OpenCV + 补数据。

若必须 DL：语义分割首选；检测仅辅助；分类不够。禁止 AGPL YOLO、禁止 `legacy` YOLO 当入口。

## 9. 串口通信最终架构

```text
Application → ActionRequest → Safety Governor → Human Gate
  → ControllerPort.execute() → MCV1 → Serial/USB → STM32
  → ACK/DONE/ERR → ExecutionReceipt
```

| 层 | 允许 | 禁止 |
|---|---|---|
| Vision / live / analyze | Observation、像素目标、`path_px` 预览 | `serial.write`、发 PUMP、看见就喷 |
| 规划 | `PUMP_IN_PLACE` / 未来 `SPRAY_AT_POINT` | 把 `path_px` 直接当电机指令 |
| Governor | 泵第一次 HUMAN；工作区/急停/时长 DENY | 被业务改写成永久 ALLOW |
| Human Gate | `--confirm-pump` 一次性令牌 | 未确认发泵；LLM 点批准当协议 |
| Controller | FakeSerial 或 `STM32SerialController`；默认 `arm_pump=false` | 上层直接打开 COM 发 PUMP |
| MCV1 | PING / STATUS / STOP / PUMP | MOVE/XY（MCV2）；旧文本 `PING`/`ARM` |
| 真机 | 不接 12V 的 PONG；签字后短喷 | FakeSerial 或 host C 测试写成联调完成 |

`STM32SerialController` 已实现 `ControllerPort`。固件 `main.c` 走 MCV1。缺的是可烧录二进制和 USB 回执。`probe_stm32_link.py` 只读写探测，不能发泵。时长三套上限未对齐：编码默认 500 ms / 定点泵软件 300 ms / 固件 2000 ms（下次再批，本轮只记录）。

## 10. 坐标转换路线

当前**不具备** pixel→mm。`simulate` 的 `simulation-normalized-v0` 是虚拟 100×100 mm，只给 FakeSerial。

字段：`image_px`（有测量）；`work_mm`（无真实变换）；`nozzle_fixed` + `(0,0)` = 喷头原地脉冲，**不是**伪造工作台点。相机系 / 平台系 / 电机步：**不存在**。

| 步 | 输入 | 输出 | 验收 |
|---|---|---|---|
| B0 现状 | 现有字段 | 只用上述三套语义 | 真实图无 `target_centroid_mm` |
| A0 离线尺度 | 固定 U500 + 测微尺 | mm/px JSON，不进契约 | 留出点 ≤ max(5%, 0.05 mm)；不生成 ActionRequest |
| B1 只读 mm 报告 | `centroid_px` + 尺度 | 日志里的 mm² | 仍禁止 `propose_action` |
| A1 可过期标定 | 条件哈希 | `calibration_valid` | 条件变则 invalid |
| B2 单点 `work_mm` | 有效标定 | 一个 `SPRAY_AT_POINT` | 仅 FakeSerial 直到 MOVE 存在 |
| A3 喷头配准 | 喷斑像素 + 平面变换 | 相机–喷嘴偏移 | 无偏移禁 MOVE |
| B3 电机步 | `work_mm` + 脉冲当量 + HOME | `motor_steps` | 未 HOME 禁止 MOVE |

## 12. GitHub 调研结果（建议复用 / 禁止引入）

**不要为用框架而引入框架。** 真正落地：已在用的 OpenCV + pyserial。

| 项 | 性质 | 说明 |
|---|---|---|
| OpenCV | 建议采用 | Apache-2.0；采集、HSV、平面标定、单应性 |
| pyserial | 建议采用 | BSD-3；已在 `requirements/control-serial.txt`；打开 COM ≠ 允许泵 |
| OpenCV 平面标定 SOP | 建议采用的方法 | 显微用测微尺；不要 Kalibr |
| OpenWeedLocator | 可借鉴概念 | MIT；HSV→12V 阀。**不要学视觉直连 GPIO** |
| OpenPnP 标定 + Klipper 职责分离 | 可借鉴概念 | units-per-pixel；PC 规划 MCU 只执行。整栈 GPL，不引入 |

**明确不要引入：** ROS 2 / tf2 / Kalibr；OpenPnP / Klipper / Marlin / LinuxCNC 整栈（GPL + G-code）；Ultralytics YOLO（AGPL）；ViSP / OpenFlexure（GPL）；视觉直连泵；LLM Agent 规划硬件。
