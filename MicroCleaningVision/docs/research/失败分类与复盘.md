# 失败分类与复盘 v0：失败不是一句“没洗干净”

每个失败码保留英文，是为了让代码、日志和测试能稳定匹配；团队讨论时请先说中文现象，再附上对应失败码。例如：“图像反光严重，属于 `PERCEPTION_*`，所以本回合不允许动作。”

| 失败码族 | 首个可观测症状 | 遏制/默认路径 | 负责人 |
|---|---|---|---|
| `IMAGING_*` | 模糊、眩光、文件缺失、曝光异常 | 无动作；重新采集或换图 | A |
| `PERCEPTION_*` | 目标缺失、背景误判、面积/质心不稳定 | HUMAN；保存 mask 和失败图 | B |
| `REGISTRATION_*` | 前后图错位或不可比较 | HUMAN；不计算去除率 | B |
| `DECISION_*` | 无有效目标、不支持的原语、规则越界 | STOP/HUMAN；离线修订 | C |
| `SAFETY_*` | 标定无效、工作空间/参数违规 | DENY；不进入 FakeSerial | C |
| `EXECUTION_*` | FakeSerial 超时、缺 ACK、申请与回执不匹配 | HUMAN；无盲重试 | C |
| `DATA_*` | 缺 ID、版本、哈希或覆盖尝试 | 隔离并修复元数据 | C |
| `INTEGRATION_*` | 契约、版本或 frame 不匹配 | 拒绝集成；三人评审接口 | C 维护，全员评审 |

## 一条合格的失败记录必须写清

```text
task/version -> first symptom -> upstream condition -> propagation chain
-> containment actually taken -> recovery -> smallest discriminating experiment
```

示例：`CALIBRATION_EXPIRED → 没有可信的 work_mm 目标 → Safety DENY → 不产生执行回执 → 人工重新标定`。不要将它压缩成“喷射失败”。

## 严重度

- **Critical：** 未指令/未知的物理动作、E-stop/联锁违规、疑似伤害/损伤。保留证据并停止。
- **High：** 命令/实际不匹配、标定失败、控制器超时、不安全请求被迟滞拦截。复用前需人工审查。
- **Medium：** 质量低、残留不确定、协议/数据不匹配。无自主重试。
- **Low：** 非安全性文档或可视化问题。在下一次证据审查前修复。
