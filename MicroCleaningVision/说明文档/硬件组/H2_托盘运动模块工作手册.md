## 1. 你的模块有什么用

一句话：**把电脑给出的步数和方向，变成 X/Y 驱动器的脉冲，让样本托盘移动；以后再负责托盘旋转。**

当前实际移动的是样本托盘，不是显微镜或喷头。这个事实会影响画面坐标、运动方向和未来旋转中心，不能在文档里混写。

| 输入 | 你做的事 | 当前输出 | 谁使用 |
|---|---|---|---|
| X/Y 步数和方向 | 启动各轴的脉冲计数 | 驱动引脚波形，目标脉冲完成后停止 | 托盘驱动器 |
| 频率设定 | 调整两轴发脉冲的速度 | 当前脉冲频率 | 电脑等待时间与运动实验 |
| 状态查询 | 读出已发脉冲和忙闲 | `READXY` 对应的数据 | C 判断能否发送下一段 |
| 后续位移测量 | 核对方向、步距与重复性 | 实测步/mm、误差和装配条件 | C 换算路径，A/B 配准与标定 |

**“发了 320 个脉冲”不等于“实际走准了 1 mm”。** 当前没有编码器确认位置；电机可能丢步、机械可能有间隙。名义步距与实测步距必须分开。

## 2. 你负责哪些文件

所有路径从项目根目录 `MicroCleaningVision` 开始。

| 文件 | 作用 | 所有权 |
|---|---|---|
| `firmware/motion/stepmotor.c` | 双轴初始化、频率、起停、脉冲计数 | H2 主责 |
| `firmware/motion/stepmotor.h` | 给公共入口提供运动函数 | H2 主责；签名变更需沟通 |
| `firmware/motion/tests/test_stepmotor.c` | 在电脑上模拟定时器，验证实际运动源码 | H2 主责 |
| 本手册 | 解释当前运动代码和后续任务 | H2 主责 |
| `firmware/common/board/`、`firmware/common/main.c`、`firmware/common/keil/` | 真正的中断入口、HAL基础服务、两模块集成 | 共享；一次一位主改 |

不把泵控制再塞回 `sm_init()`，不在 `stepmotor.c` 内接收串口，也不把 H1 的 `pump.c/h` 复制到运动目录。

## 3. 现在代码实际能做什么

- `sm_init()`：只初始化运动 GPIO、TIM2/TIM3 和中断，不再初始化泵/蜂鸣器/按钮。
- `sm_start_xy(nx, dx, ny, dy)`：两轴同时开始，各走自己的步数。某一轴为 0 就不启动那一轴。
- `sm_start(steps, dir)`：旧的 X 单轴入口，保留兼容；不要因此把 Y 误认成 X。
- `sm_set_freq(freq)`：两轴设置同一频率。TIM3 驱动 X，TIM2 驱动 Y。
- `sm_stop()`：只停两轴；串口 `STOP` 在公共入口的 `stop_all()` 经过共享状态机关闭泵，所以停止整个系统不能只调用运动函数。
- `sm_start_scope_offset(returning_to_scope)`：TO_NEEDLE/TO_SCOPE 使用同一个 `sm_start_xy`，名义 Y=7680 步，分别 FWD/REV。不是绝对位置、自动回零或已校准偏移。
- `sm_step_count()` / `sm_y_step_count()` 与两个 busy 函数：已发脉冲和忙闲，不是绝对托盘坐标。

偏移代码已经接入固件主入口和普通运动驱动，但电脑正式 Stage2SerialLink 没有自动发送它。主机按单条 MOVEXY 限制每轴 10000 步，去程和回程不相加。软限位是人工零点 ±10000 步。单段超过 10000 步不能拆段绕过。实际移动的是托盘，不能凭“针头在相机某侧”直接判断托盘应往哪侧走。

一个完整脉冲经过低、高两个半周期，因此 500 脉冲/秒对应 1000 次更新中断/秒。当前两轴同频，短轴先结束；**不是按比例同时到达终点的直线插补**。直线插补是“配好两个轴的速度，让它们沿一条直线同时走完”，当前没有这项能力。

## 4. 今天可以独立完成什么

### H2-01：跑懂双轴通路

输入：`stepmotor.c/h`、`stm32f10x_it.c`、公共入口和运动测试。无需图片、无需插板。

```powershell
cd "D:\大创\3d\MicroCleaningVision"
& .\firmware\common\scripts\run-host-tests.ps1 `
  -ZigPath "D:\大创\tmp\hw-split-zig-0.16.0\zig-x86_64-windows-0.16.0\zig.exe"
```

换电脑时把编译器路径换成本机实际路径；无需 Python 虚拟环境。输出是当前固件 5 组测试 `PASS` 加旧兼容 7 组结果 和 `.tools` 生成路径，不产生真实移动。

具体动作：沿着 `MOVEXY` → `sm_start_xy()` → 各轴计数 → TIM2/TIM3 中断 → 停止，逐段读代码；在测试中找出“Y 先走完而 X 仍忙”“发一半周期不能多算一个完整脉冲”“0 步轴不启动”的断言。

验收：能够解释 X/Y 分别是哪两个引脚和定时器、什么算一步、为什么 `STEP2_START` 不等于已经到位；不额外写第二套运动测试主程序来替代真实源码。

### H2-02：弄清“步数到底对应多少实际位移”

输入：实际托盘、两轴电机/驱动器、丝杆或传动结构、测量工具。可以先整理，不必等 B 检测算法完成。

具体动作：

1. 拍下实际驱动器拨码和铭牌，核对 X/Y 分别接到哪组脉冲与方向脚。
2. 记录实际导程与细分设置。当前约定的 `1600 步/圈 ÷ 5 mm/圈 = 320 步/mm` 是名义计算，未经过本轮实测。
3. 与 C 明确：画面左/右、上/下分别对应哪条轴与哪个方向；不要凭“正转”推断画面方向。
4. 在批准的受控实机实验中，选不超出实际行程的小位移，记录申请步数与独立量具测出的位移；做正反方向与返回测试。具体步数先按真实装配确认，不在这里写死一条自动运行命令。
5. 记录偏差、抖动、丢步、返回不到同一位置等失败，不只留成功视频。

输出交给 C：真实方向映射、已测步距与适用条件、可信行程、显微镜到针头的有符号偏移和返回误差、哪些值仍待确认。交给 A/B：样本怎么移动，重复返回同一位置的误差是多少。

注意：电脑侧当前 `microstep` 约定为 1，实际细分已经计入 320 步/mm；不要再乘 16。当前 `0.01 mm/像素` 只是未标定占位，不能当成实际显微倍率标定结果。

## 5. 后续分阶段任务

以下是计划，不是本轮已实现的能力。先有明确失败，再提小改动，文件级方案确认后实施。

### H2-03：把一个主要运动失败修成可重复结果

可选失败：方向映射错误、返回偏差过大、目标脉冲完成但托盘明显没走足。先选一个最稳定可复现的问题，不同时引入复杂加减速和轨迹库。

步骤：记录同一装配与参数下的问题 → 定位是接线、参数、传动、名义偏移方向还是代码 → 提出一个最小修改 → 补一个针对性电脑测试（若适用） → 在同条件下重复测量修改前后。

输出：一个明确修复与前后证据。软件修改主要在 `stepmotor.c/h` 和自己的测试；中断或公共入口确需修改时，与 H1 确定单一主改人。建议后续分支 `feat/hw-tray-motion`，本轮未创建它。

验收：C 能根据交付的方向、步距、行程和误差，合理生成下一段动作；不能只交付“程序编译成功”。如果最小实验说明新复杂算法没有帮助，就不引入它。

### H2-04：准备托盘旋转，而不是现在开一个空目录

已经确认的方向：把样本托盘改装成旋转底盘，不是转显微镜。

先做实物与接口准备：

1. 明确托盘旋转中心、可旋转角度、可重复定位方式、样本固定，以及与管路/喷头的干涉。
2. 与 H1 一起检查管路是否绕缠或遮挡；与 A/B 明确旋转前后图片怎样找到同一块表面。
3. 检查新电机需要哪些引脚和计时资源；TIM2/TIM3 已用于 X/Y，不能直接重复占用。
4. 与 C 约定角度单位、零点和返回方式，再决定是否增加运动 API 与串口命令；共享协议不能各自定义。
5. 先做单角度重复返回实验，再决定是否值得增加 45° 视角或双目三维。

输出：一份有实物约束的旋转最小实验方案，之后才是代码。不在本轮制造未实现的旋转接口，不声称有三维成像能力。

## 6. 要学到什么程度、怎样用 AI

| 知识 | 大白话解释 | 当前学到的深度 |
|---|---|---|
| C 结构体与 `volatile` | 把一轴的数据放在一起；提醒编译器变量可能被中断改变 | 能追踪 busy、已发/目标步数，不凭空修改计数 |
| GPIO 与驱动器 | 芯片提供控制信号，驱动器用外部电源驱动电机 | 不把脉冲脚当电机供电脚 |
| 定时器与中断 | 芯片按节拍触发小段代码，生成脉冲 | 能解释半周期、完整脉冲、停止条件 |
| 步、毫米、像素、角度 | 不同空间里的量，不能直接相加或互换 | 能核对换算依据与是否标定 |
| 机械误差与丢步 | 代码发出的信号不保证机构全部执行 | 用测量区分软件计数与真实位移 |
| Git 与公共文件协作 | 独立改运动模块，共享入口协商后改 | 会核对 diff，不覆盖 H1 的工作 |

可以给 AI 这样的任务：

> 先读硬件组入口、运动手册和串口约定，再沿 MOVEXY、sm_start_xy、TIM2/TIM3 中断追踪 X=3、Y=1 的全过程。说明每个半周期的计数与 busy 状态。只给修改方案，不改泵、不打开 COM、不烧录；名义步距不能写成实测事实。

AI 能辅助追踪状态、写断言；实际方向、结构干涉、步距和丢步必须由人测量。现在不需要先学强化学习、三维重建或复杂运动规划库。

## 7. 怎样与 H1 和 C 交接

- 给 H1：托盘运动区域和时间，停止行为，占用的引脚/定时器，管路和喷头的干涉限制。
- 给 C：方向映射、步距、行程、完成查询方式和误差；当前没有比例直线插补，也没有实测位置回执。
- 给 A/B：同一表面如何返回显微视野，位置重复性的真实测量；未标定前只声明像素/名义步数结果。
- 可以不等别人就做：真实源码追踪、电脑测试、结构/参数整理、测量装配准备和旋转干涉设计。

H2 的工作包含双轴接线、参数和重复性测量，不能只按代码行数判断轻重。与 H1 每次用实际耗时调整共享集成的主改人：两模块仍分别拥有自己的代码，不通过轮流修改对方文件来“平均分工”。

每日可持续成果应能复用：一个被定位的运动故障、一组带条件的位移数据、一个能反复装回的夹具改进，或一个真实缺口的回归断言。CSV 和报告只是这些成果的载体，不是任务本身。
